<risks>
- **DEFAULT_ALLOWLIST creep:** the existing allowlist in browser-diagnostics.ts lines 125-132 silently covers `_rsc=… ERR_ABORTED` AND `POST /api/locale ERR_ABORTED`. The spec inherits both automatically. DO NOT add new entries unless a real failing run proves the noise is framework-level. PRD §Verification calls for the spec to FAIL on first console.error — adding allowlist entries to silence real bugs is exactly the anti-pattern.
- **Empty-state user vs seeded user:** 99-cross-screen-smoke.spec.ts seeds 1 row per list (lines 54-56). The 100-acceptance spec deliberately does NOT seed — it tests the brand-new-user OOB path. If a list screen crashes on empty state (e.g., the previous `Smoke transcription` assertion at line 67 would never match), that's a real bug per PRD §"Bugs to surface" — file BUG-54-*, do NOT seed your way out.
- **Locale toggle leaves the page in Russian:** if step 7 (theme) runs while the locale is still Russian from step 6, the theme-toggle button selector may need to match `/тема|theme/i`. Mitigation: explicitly toggle back to English at the END of step 6 so steps 7-8 run against deterministic English copy.
- **Sign-out button selector is project-dependent:** grep apps/web/src/components/ + apps/web/tests/e2e/ for the existing testid BEFORE writing the selector. If u8/u9/u10 already exercise sign-out via a stable testid, reuse it verbatim.
- **Better Auth rate-limit on sign-up via UI:** the spec generates a unique email per run (flow54+${Date.now()}@local.test), so per-email throttling does not bite. Per-IP throttling COULD bite if this spec runs back-to-back with the existing 100-fullflow spec — the slim project has workers=1 (per playwright.config.ts line 72) so the two specs serialise; the ~60s window between sign-ups is usually enough. If the spec flakes on 429, that's a Phase 54+ rate-limit-window-tightening conversation, NOT a spec fix.
- **Verification email from `from=docker.internal`:** if a Phase 53 deferred-item changed the AUTH_URL or mailer from-address such that the regex in support/mailpit.ts no longer matches, this spec fails on step 2. Mitigation: keep the regex byte-identical to the one already proven in 100-fullflow.spec.ts line 56-58.
