## Locked Decisions

### D-01 — Provision OIDC env in contract-test compose context

Two options for where to set the env:
- **(a)** Add to `docker-compose.yml` api service `environment:` unconditionally with sensible defaults pointing at fixture-idp (only resolvable inside the network when fixture-idp is up via `--profile contract-test`)
- **(b) RECOMMENDED** Use a compose override file `compose/contract-test.override.yml` activated via `-f` flag in the Makefile contract-test target

Picking **(a)** for simplicity — environment variable references that resolve to fixture-idp DNS name are harmless when fixture-idp isn't running (api just gets DNS resolution errors at runtime IF those vars are read; per auth.ts the vars are read once at startup. Need to verify api startup doesn't crash if OIDC_ISSUER_URL set but fixture-idp unreachable.)

Actually, safer: condition on profile presence via separate override OR just always-set with fixture-idp DNS — Better Auth genericOAuth uses lazy discovery (only fetches discovery doc when an OAuth flow is attempted), so default-profile boot is unaffected.

**Going with (a):** add to `docker-compose.yml` api service environment:
```yaml
OIDC_ISSUER_URL: ${OIDC_ISSUER_URL:-http://fixture-idp:9000}
OIDC_CLIENT_ID: ${OIDC_CLIENT_ID:-conformance-test-client}
OIDC_CLIENT_SECRET: ${OIDC_CLIENT_SECRET:-conformance-test-secret-do-not-use-in-prod}
```

The defaults point at fixture-idp; operators override via `.env` for production OIDC. When default profile runs (no fixture-idp), the discovery doc fetch won't happen until someone actually attempts an OAuth flow — at which point a 503 is correct because no OIDC is configured.

Actually wait — better to LOOK at what fixture-idp expects. Need to read `tests/fixtures/idp/server.mjs` to see if there's a hardcoded client_id/secret it accepts.
