# Plan 02.3-01 — SUMMARY

## Outcome

Phase 02.3 succeeded at its scope: `make contract-test`'s seed step now runs as an in-network compose service, Better Auth's universal `/api/auth/*` handler is mounted, and CSRF is configured for in-cluster traffic. Seed reaches better-auth's drizzle adapter — the next failure (`The model "user" was not found in the schema object`) is a separate Phase 02 Plan 03 schema defect, surfaced for Phase 02.4.

## What was built

### Fix 1 — Second tsup entry `seed-conformance.cjs`

`packages/data/tsup.config.ts` adds `"seed-conformance": "src/seed/conformance.ts"`. Same CJS bundling rules as migrate (`external: ["pg-native"]`).

### Fix 2 — Dual ESM/CJS CLI detect

`packages/data/src/seed/conformance.ts` — entry-point detect now handles both module systems. Wraps `import.meta` access in a `typeof` guard so the CJS bundle doesn't ReferenceError; falls back to `require.main === module`.

### Fix 3 — Explicit `Origin` header in signup fetch

`packages/data/src/seed/conformance.ts` — `signUp` POST now forwards `origin: AUTH_URL` so it satisfies better-auth's `trustedOrigins` CSRF gate.

### Fix 4 — Better Auth `/api/auth/*` route plugin

`apps/api/src/routes/better-auth-handler.ts` (new) + `apps/api/src/routes/index.ts` (register first). Bridges Fastify req → Web Request → `auth.handler(req)` → Web Response → Fastify reply. `config: { auth: false }` opts the namespace out of `dualAuthHook` so better-auth manages its own session lifecycle.

### Fix 5 — `fastifyHeadersToWebHeaders` exported

`apps/api/src/middleware/dual-auth.ts` — function previously module-private, now exported for use by the new better-auth handler plugin.

### Fix 6 — `AuthLike.handler` optional

`apps/api/src/middleware/dual-auth.ts` — `AuthLike` extended with `handler?: (req: Request) => Promise<Response>`. Optional so existing test fakes that only stub `api.getSession` keep compiling.

### Fix 7 — `AUTH_TRUSTED_ORIGINS_EXTRA`

`apps/api/src/auth.ts` reads a comma-separated list and appends to `trustedOrigins`. `docker-compose.yml` api service sets `AUTH_TRUSTED_ORIGINS_EXTRA=http://api:3000` so the in-cluster seed container's Origin is admitted.

### Fix 8 — `seed` compose service

`docker-compose.yml` adds a one-shot `seed` service in `contract-test` profile. Uses `openwhispr-api` image, depends on api healthy, env_file .env, AUTH_URL=http://api:3000, SMTP_HOST="" (no-op email), entrypoint `node /app/packages/data/dist/seed-conformance.cjs`.

### Fix 9 — Makefile contract-test routing

`Makefile` — `contract-test` target now invokes `docker compose --profile contract-test run --rm seed` instead of `pnpm -F @openwhispr/data run seed:conformance`. Bails out before the test phase if seed exits non-zero.

## Surfaced for next attempt — Phase 02.4

Better Auth drizzle adapter aborts with:
```
[# Drizzle Adapter]: The model "user" was not found in the schema object.
Please pass the schema directly to the adapter options.
```

Phase 02 Plan 03 instantiated `drizzleAdapter(db, { provider: "pg" })` without the `schema` option, AND `@openwhispr/data` does not declare the `user` / `session` / `account` / `verification` tables better-auth requires. Both must be fixed before `make contract-test` completes.

Phase 02.4 plan:
1. Run `npx @better-auth/cli generate` against the running api to produce the canonical schema
2. Hand-merge the generated tables into `packages/data/src/schema/`
3. Re-run drizzle migration (the schema diff goes through the existing migrate path)
4. Pass the merged schema to `drizzleAdapter(db, { provider: "pg", schema })`
5. Re-run `make contract-test` end-to-end → 02-HUMAN-UAT.md Item 1 finally flippable
