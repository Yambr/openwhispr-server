# Phase 02.3 — CONTEXT

## Goal

Make `make contract-test` invoke the conformance seed step inside the openwhispr_internal docker network so DATABASE_URL_OWNER and AUTH_URL (both internal hostnames) actually resolve. Wire up the Better Auth `/api/auth/*` route handler that Phase 02 Plan 04 left unmounted.

## Locked Decisions

### D-01 — Seed-as-compose-service (NOT host shell)

Move the seed step from `pnpm -F @openwhispr/data run seed:conformance` (host shell) into a one-shot `seed` compose service. Justification:
- DATABASE_URL_OWNER points at `postgres://...@postgres:5432/...` — the `postgres` hostname only resolves inside the openwhispr_internal network
- AUTH_URL points at the api container, also internal-only
- Avoids requiring publishing a postgres port (which would weaken the D-05 "only Traefik publishes ports" rule from Phase 1)
- Reuses the api image (Phase 02.1 Dockerfile already ships data/dist/seed-conformance.cjs)

Implementation: tsup adds a second entry `seed-conformance.cjs`; CLI detect made dual ESM/CJS-friendly; compose `seed` service in profile `contract-test`; Makefile uses `docker compose run --rm seed`.

### D-02 — Mount Better Auth handler at /api/auth/*

Phase 02 Plan 04 left this wiring undone (buildApp comments promised `app.all('/api/auth/*', ...)` but no plugin actually mounted it). Without it, sign-up / sign-in / verify-email / sign-out / etc. are all caught by `dualAuthHook` (no session) and 401'd before Better Auth ever sees the request.

New `apps/api/src/routes/better-auth-handler.ts` plugin:
- `app.all("/api/auth/*", { config: { auth: false } }, handler)` — opts the namespace out of dualAuthHook
- Bridges Fastify `req` → Web `Request` → `auth.handler(req)` → Web `Response` → Fastify `reply`
- Registered first in the `buildAllRoutes` list so it's wired before everything else

`AuthLike` interface extended with optional `handler?: (req: Request) => Promise<Response>` so existing test fakes that only stub `api.getSession` keep compiling.

### D-03 — `AUTH_TRUSTED_ORIGINS_EXTRA` for in-cluster traffic

Better Auth's CSRF gate compares `Origin` header against `trustedOrigins`. Production trustedOrigins = [OPENWHISPR_API_URL, AUTH_URL] = [`https://api.localhost`, `https://api.localhost`]. The seed container POSTs to `http://api:3000` (in-cluster, no traefik), so its Origin doesn't match. Adding `AUTH_TRUSTED_ORIGINS_EXTRA=http://api:3000` admits the in-cluster origin without weakening the public-traffic gate.

Read in `apps/api/src/auth.ts` as a comma-separated list, appended to the existing trustedOrigins array.

### D-04 — Out of scope (DEFERRED)

After all 02.3 fixes, seed reaches better-auth's drizzle adapter and fails with:

> `[# Drizzle Adapter]: The model "user" was not found in the schema object. Please pass the schema directly to the adapter options.`

Phase 02 Plan 03 instantiated the drizzle adapter without passing a `schema` option, AND `@openwhispr/data` does not declare the `user` / `session` / `account` / `verification` tables better-auth requires. Both gaps need fixing before `make contract-test` can complete end-to-end. New phase needed (Phase 02.4 — better-auth drizzle schema).

## Surfaced for next attempt — Phase 02.4

1. The `schema` option passed to `drizzleAdapter(...)`
2. The actual `user` / `session` / `account` / `verification` tables in `@openwhispr/data` schema

Without these, the entire auth flow fails at first DB hit. Phase 02.4 will:
- Generate the better-auth schema via `npx @better-auth/cli generate`
- Add the resulting tables to `packages/data/src/schema/`
- Pass `schema` option in `apps/api/src/auth.ts` drizzleAdapter call
- Re-run `make contract-test` end-to-end
