# Phase 02.11 — CONTEXT

## Goal

Close cascade tail #11: Better Auth's drizzle adapter throws `BetterAuthError: The field "token" does not exist in the schema for the model "session"` because Phase 02 Plan 01 designed `sessions.tokenHash bytea` (AUTH-04 hash-only storage) but BA v1.6.9 expects plain `session.token` text. Adopt BA-native plain-token model; preserve AUTH-04 5-minute overlap contract via plain-text `previous_token` column; defer at-rest hardening to v2 (ADR-tracked).

## Locked Decisions (Recommended Option C from advisor research)

### D-01 — Drop tokenHash, replace with plain `token` text

**Migration `0005_session_token_plain.sql`** (forward + reversible):
- `ALTER TABLE sessions DROP COLUMN token_hash` (and `previous_token_hash`)
- `ALTER TABLE sessions ADD COLUMN token text NOT NULL` (UNIQUE — index)
- `ALTER TABLE sessions ADD COLUMN previous_token text` (nullable)
- Drop the SECURITY DEFINER function `session_lookup_by_token(bytea)` and recreate with `text` parameter
- Replace `token_hash` btree index with `(token)` UNIQUE index
- Existing rows: TRUNCATE sessions (Phase 02 dev — no production data; documented in migration head comment)

**Drizzle schema** (`packages/data/src/schema/sessions.ts`):
- Remove `tokenHash`, `previousTokenHash` columns + bytea customType
- Add `token: text("token").notNull().unique()` and `previousToken: text("previous_token")`
- Replace `tokenHashIdx` with `tokenIdx`

## Why this phase exists

Phase 02 Plan 01 + AUTH-04 spec mandated hash-only token storage as defense-in-depth. Better Auth v1.6.9 has no native hashed-token support and entire OSS auth ecosystem (NextAuth, Auth.js, Lucia, BA itself) stores plain session bearers. The hash design fights the auth library and is over-engineered for v1 self-host (DB-side defense should be Postgres TDE / disk encryption, not application-layer hashing). Aligning with BA upstream is the boring enterprise answer; AUTH-04 overlap CONTRACT (not storage shape) survives.
