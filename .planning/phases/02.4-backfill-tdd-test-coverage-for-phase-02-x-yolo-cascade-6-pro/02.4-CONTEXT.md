### D-02 — TDD discipline (red→green retro)

This is retroactive coverage: the production code already exists, so tests will start green. The discipline is enforced differently:

1. Each test must be written so that **deleting/reverting the corresponding production fix makes it RED** (verifiable by `git stash apply` of an inverse patch — documented in each test's `Reverts:` block in the docstring).
2. `pnpm vitest run --coverage <file>` for each new test file must show the targeted production file at ≥90% lines/branches in v8 report.
3. Any test that's green even when the production fix is reverted = **broken test**, must be fixed before commit.

### D-03 — Vitest config — narrow coverage scope per test file

The constitutional 85/80/80/85 floor (`vitest.config.ts`) applies to the whole monorepo. For per-phase ≥90% verification, we use `pnpm vitest run --coverage --coverage.include=<targeted-files>` invocations in each plan's verification block — NOT a global config change. Global config stays at 85/80.

### D-04 — Real services via testcontainers (no mocks)

Per `feedback_local_docker_tests.md`: G2 (Postgres roles) and G4 (observability) MUST use real services. G2 uses `@testcontainers/postgresql` (already a project dep — verify or add). G4 uses `docker compose --profile obs-only` directly (already exists in compose) and asserts `docker compose ps --format json` returns the expected status set.

### D-05 — Bootstrap shell tests via shellspec or bats? — DECIDED: vitest+execa

`tools/bootstrap.sh` is shell. We do NOT add a new test runner just for this. Use vitest's existing infra with `execa` to invoke `tools/bootstrap.sh` as a subprocess against a temp `.env` fixture, then assert resulting file content. Keeps one test runner across the repo. (Already used for other shell tests like `tests/self-tests/verify-images.test.ts`.)

### D-06 — Out of scope (DEFERRED)

- E2E test of `make contract-test` running clean — that's Phase 02.5's responsibility (better-auth schema fix lands first, then the full pipeline becomes assertable).
- Mutation testing (Stryker) on these new tests — the constitutional `TEST-MUTATION-01` only mandates Stryker on auth/multi-tenancy/virtual-key minting modules. Out of scope here.
- New CI matrix jobs — existing `ci.yml` already runs `pnpm test --coverage`, which picks up all new `*.test.ts` files automatically.
