## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] Scoped `up -d --wait` to the 4 services under test instead of the whole profile**

- **Found during:** Task 1 verification (first `pnpm vitest run`)
- **Issue:** Plan-as-written invoked `docker compose --profile obs-only up -d --wait` against the entire `obs-only` profile. `obs-only` includes 5 services per `docker-compose.yml` (tempo, mimir, loki, otel-collector, **grafana**), but the plan's `<behavior>` block and `SERVICES` array only assert on 4 (no grafana). Grafana's healthcheck has a 90s `start_period` because first-boot installs the `grafana-pyroscope-app` plugin over the network; under CI/test conditions this routinely flaps "unhealthy" past `--wait`'s window even when the four services under test are all `Healthy`. Initial run failed assertion #1 with `container openwhispr-grafana-1 is unhealthy` despite tempo/mimir/loki/otel-collector all reaching `Healthy`.
- **Fix:** Pass `...SERVICES` as the explicit service list to `docker compose ... up -d --wait`. `--wait` then only blocks on the four services the plan claims to verify; grafana still starts (it's pulled in transitively via `depends_on`) but is not in the wait set. Inline comment in the test explains the rationale.
- **Files modified:** `tests/integration/observability-stack-up.test.ts` (one `it(...)` body)
- **Commit:** `3af355d`

This is a test-only adjustment (Phase 02.4 D-06 honored — zero production changes).
