# Phase 02.14 — CONTEXT

## Goal

Move the contract-test runner inside the openwhispr_internal docker network, mirroring the Phase 02.3 seed-as-compose-service pattern. Eliminates host→docker DNS leak class (Group E surfaced by Phase 02.13), one URL one issuer, zero /etc/hosts mutation.

## Locked Decisions (Recommended Option C from advisor research)

### D-01 — New `contract-test-runner` compose service in contract-test profile

`docker-compose.yml` add service mirroring `seed` block (lines 370-404). Reuses `openwhispr-api` image (which already ships node_modules + workspace structure). Bind-mount `packages/contract-tests` source so vitest sees the test files; OR bake into image via separate Dockerfile-thin layer.

**Going with bind-mount** for v1 (fastest iteration; tests change frequently). Future: bake into image if CI needs portable artifact.

```yaml
contract-test-runner:
  image: openwhispr-api
  profiles: [contract-test]
  networks: [openwhispr_internal]
  restart: "no"
  depends_on:
    api:
      condition: service_healthy
    fixture-idp:
      condition: service_healthy
  env_file: .env
  environment:
    BACKEND_URL: http://api:3000
    AUTH_URL: http://api:3000
    NODE_TLS_REJECT_UNAUTHORIZED: "0"  # internal-only http; no TLS to validate
  volumes:
    - ./packages/contract-tests:/app/packages/contract-tests:ro
    - ./packages/auth:/app/packages/auth:ro
    - ./node_modules:/app/node_modules:ro
  working_dir: /app
  entrypoint: ["pnpm", "-F", "@openwhispr/contract-tests", "run", "test", "--run"]
```

Note: NODE_TLS_REJECT_UNAUTHORIZED=0 here is acceptable because BACKEND_URL/AUTH_URL are http:// internal-only — no TLS to validate. The host-side `contract-test-deployed` target (already guards against this env per Phase 02.7-01) is unchanged.

Actually, wait — that's a workaround per CLAUDE.md. Better: don't set the var; just use http:// URLs internally; no TLS validation triggered when scheme is http. Verify and remove if not needed.

### D-02 — Update Makefile

`Makefile` `contract-test` target replaces the host-side pnpm invocation:

```make
contract-test: build
	docker compose --profile contract-test run --rm seed
	docker compose --profile contract-test run --rm contract-test-runner
```

The two `run --rm` calls happen sequentially — seed first (must succeed), then test runner. `contract-test-deployed` target unchanged (host-side runner against external BACKEND_URL).
