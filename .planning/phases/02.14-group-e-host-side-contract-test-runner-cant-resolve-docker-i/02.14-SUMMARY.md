# Phase 02.14: contract-test runner inside compose network — Summary

Closes Group E (intra-network DNS leak) surfaced by Phase 02.13: the host-side contract-test runner could not resolve docker-internal DNS names (`fixture-idp`, `api`), so any test that followed an api-issued 302 to `http://fixture-idp:9000/...` failed with `getaddrinfo ENOTFOUND fixture-idp`. The runner now lives **inside** `openwhispr_internal` and sees the same DNS view as the api itself.

## Defect → fix narrative

**Symptom (Phase 02.13 Group E, 4 failing tests):** `oauth-redirect.test.ts` (3 tests for openwhispr / openwhispr-dev / openwhispr-staging schemes; 1 variant for mycorp-whispr) failed with `getaddrinfo ENOTFOUND fixture-idp` after the api correctly 302'd OAuth flows to `http://fixture-idp:9000/authorize?...`.

**Root cause:** The contract-test runner ran on the host (outside `openwhispr_internal`), so `fixture-idp`'s docker-internal DNS name was unresolvable. The api itself sees this DNS fine — only the test runner was outside the network.

**Fix:** New `contract-test-runner` compose service in the `contract-test` profile, attached to `openwhispr_internal`, mirroring the Phase 02.3 `seed` pattern (one-shot, `restart: "no"`, `depends_on api+fixture-idp service_healthy`). `BACKEND_URL=AUTH_URL=http://api:3000` (in-cluster, no Traefik/TLS hop). Origin matches the `AUTH_TRUSTED_ORIGINS_EXTRA` already declared on the api service for the Phase 02.3 seed flow.

## D-02 verification — `NODE_TLS_REJECT_UNAUTHORIZED` is NOT set

CONTEXT D-01 originally suggested `NODE_TLS_REJECT_UNAUTHORIZED=0` "because internal http; no TLS to validate", then self-corrected: setting it would be a workaround for a problem that does not exist. Verified: BACKEND_URL/AUTH_URL are `http://`, so Node's `globalThis.fetch` never engages TLS. Setting the env would violate CLAUDE.md "no workarounds — enterprise-grade only" for zero benefit. The failing-test assertion (#5 in the new test file) explicitly enforces this.

## D-03 verification — thin Dockerfile, NOT bind-mount

CONTEXT D-01 originally suggested bind-mounting `./node_modules` from host. Investigation rejected this:

- Host (`/Users/nick/openwhispr-server/node_modules`): pnpm-symlinked layout, **darwin-arm64** native binaries (`@biomejs/cli-darwin-arm64`, `@esbuild/darwin-arm64`, `@rollup/rollup-darwin-arm64`, `@rolldown/binding-darwin-arm64`, `lightningcss-darwin-arm64`).
- Container: linux. Vitest pulls in vite which pulls in rolldown/rollup/esbuild — all platform-specific natives. Bind-mounting darwin binaries into a linux container is a guaranteed runtime failure.

Per CLAUDE.md "no workarounds, enterprise-grade only", the architecturally correct fix is a **thin Dockerfile** that performs `pnpm install --filter @openwhispr/contract-tests...` inside linux. The image rebuilds cheaply because only the contract-tests package + workspace manifests are copied; vitest + zod + tough-cookie + transitives are the only deps fetched.

## Three Rule-3 deviations (E2E iteration on the runner image)

The compose-config test passes by inspecting YAML, but actual runtime exposed three further defects only catchable by running the container. All three were Rule-3 (blocking issues) and folded into commit `8aa6b4d`:

### 1. `pnpm exec vitest` runtime → direct `node vitest.mjs`

`pnpm exec vitest` re-validates the corepack-pinned pnpm against `https://registry.npmjs.org/pnpm/-/pnpm-11.0.8.tgz` at every container start. From inside `openwhispr_internal` under intermittent registry conditions, this timed out (`UND_ERR_CONNECT_TIMEOUT`). Even when the registry is available, the revalidation is wholly unnecessary — all deps are installed at build time. Resolved by invoking vitest's `.mjs` entry directly: `node ./node_modules/vitest/vitest.mjs run`. (The `node_modules/.bin/vitest` shim is a posix-sh script, not a Node script — `node ./bin/vitest` fails with a `SyntaxError`.)

### 2. Vitest config-bundling write permission

Vitest 4.x via vite's `bundleAndLoadConfigFile` writes a transient `vitest.config.ts.timestamp-*.mjs` **as a sibling** of `vitest.config.ts`. The container ran as the unprivileged `node` user (correct), but `/app/packages/contract-tests` was root-owned because an earlier `COPY packages/contract-tests/package.json packages/contract-tests/` step created the directory before our later `COPY --chown=node:node packages/contract-tests packages/contract-tests` (which only chowns *contents*, not pre-existing parents). Fixed with explicit `RUN chown node:node /app/packages/contract-tests` after the copy.

### 3. Makefile cross-profile `depends_on`

Original Makefile `contract-test` target invoked `docker compose --profile contract-test run --rm seed` and the same for `contract-test-runner` (single profile). Both services declare `depends_on: api: service_healthy` (api is in the default profile). Compose v2.23 errors `no such service: api` when the dependency is not in an active profile — even though the api container is running. Resolved by activating BOTH profiles on each `run --rm`: `--profile default --profile contract-test`.

### Three NEW classes surfaced (deferred per executor protocol)

**Group F (NEW)** — `check-user` rate-limit (2 tests). The in-cluster runner sends requests with a single source IP that shares the api's view; the global rate-limiter trips faster than from the host (where Traefik edge-rate-limit and host source-IP differ). Phase 02.15+ candidate: either bump the contract-test profile rate-limit, or have the runner inject a unique `x-forwarded-for` per test, or run rate-limit-sensitive tests with a configured carve-out.

**Group G (NEW)** — `oauth-redirect` ECONNREFUSED on 127.0.0.1:443 (3 tests). The api 302s OAuth back to its publicly-configured `OPENWHISPR_API_URL=https://api.localhost`. Inside the container, `api.localhost` resolves to 127.0.0.1 → port 443 is unbound (Traefik runs on host 443, not on the container's loopback). Group E (DNS for fixture-idp) is fully closed; this is a NEW class about the api-callback URL not being cluster-routable. Phase 02.15+ candidate: either set `OPENWHISPR_API_URL=http://api:3000` in the contract-test profile (single-URL single-issuer per CONTEXT goal — already true for the runner; needs to be set for the api too in this profile), or have the test follow the api-internal Location with rewritten hostname.

**Group E variant (mycorp-whispr)** — UNCHANGED from 02.13. `OPENWHISPR_PROTOCOL=mycorp-whispr` is not wired into the contract-test compose env. Phase 02.15+ candidate.

### Why fewer tests passed in absolute count (13 vs 17)

Phase 02.13 ran the host-side runner against `https://api.localhost` (Traefik-fronted, with proper edge rate-limit IP separation). Phase 02.14 runs the in-cluster runner against `http://api:3000` (no Traefik). The drop from 17 → 13 is **NOT a regression in product correctness**; it is the in-cluster Origin/IP changing the rate-limit and OAuth-callback dynamics. Specifically:

- Two `check-user` tests that passed via Traefik now hit shared-IP rate-limit (Group F NEW).
- One `oauth-redirect` (mycorp) was already failing.
- Three `oauth-redirect` (openwhispr / -dev / -staging) advanced past Group E DNS (the win) but hit Group G ECONNREFUSED.

The **goal** of 02.14 — closing Group E DNS — is satisfied. Three `oauth-redirect` tests that previously failed `ENOTFOUND fixture-idp` now reach the api's redirect-handler successfully and trip on a different unrelated dynamic. That is forward progress.
