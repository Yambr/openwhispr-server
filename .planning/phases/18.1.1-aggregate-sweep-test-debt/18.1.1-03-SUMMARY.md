## D-12 helper shape

Helper at `packages/data/tests/unit/__helpers__/bootstrap-roles.ts` performs
six SQL operations against a superuser-connected `Pool`:

1. `CREATE ROLE openwhispr_owner WITH LOGIN BYPASSRLS CREATEROLE PASSWORD ...`
2. `CREATE ROLE openwhispr_app   WITH LOGIN          PASSWORD ...`
3. `GRANT openwhispr_app TO openwhispr_owner WITH ADMIN OPTION`
4. `GRANT SET, ALTER SYSTEM ON PARAMETER "app.tenant_id" TO openwhispr_owner`
5. `ALTER DATABASE <opts.dbName> OWNER TO openwhispr_owner`
6. `ALTER SCHEMA public OWNER TO openwhispr_owner`

`pg_partman` provisioning is intentionally NOT part of the helper —
callers that need it call `provisionPgPartman(superPool)` separately.
This keeps the helper usable from `tools/lint-rls.test.ts` and other
non-partman call sites.

## D-11 transitive resolution detail

`tools/lint-rls.test.ts` previously bootstrapped `openwhispr_owner`
without the `CREATEROLE` attribute and without the
`GRANT openwhispr_app TO openwhispr_owner WITH ADMIN OPTION` grant.
Migration `0003` (`ALTER ROLE openwhispr_app SET app.tenant_id …`) then
failed with **PG 42501 "permission denied to alter role openwhispr_app"**.
The helper grants both. Additionally, the postgres image had to switch
from `postgres:17-alpine` to `openwhispr/postgres:17.5-pgpartman` because
migration `0014` needs `pg_partman`; `provisionPgPartman` is now invoked
right after `bootstrapRoles`.

Post-fix, all 4 base D-11 tests pass:
- `exits 0 against a clean migrated schema`
- `flags a table with tenant_id column but RLS disabled`
- `flags a table with ENABLE RLS but no policy attached`
- `flags a policy that does not reference app.tenant_id`

(5 unrelated `PHASE_6_NOT_YET` stubs remain — they are explicit
`throw new Error("not yet implemented")` placeholders for Phase 6 / Plan
06-02 pg_partman child-table handling; not in scope for D-11.)

## Prod-parity caveat (planner risk #2)

The helper grants `CREATEROLE` only to `openwhispr_owner`, which matches
production. If a future Phase 19.x prod-parity test ever demands the
strict `owner-without-CREATEROLE` bootstrap shape, split the helper into
`bootstrapMinimalRoles` (no CREATEROLE) plus `grantCreateRoleForTesting`
so the elevation becomes opt-in. Documented in the helper file header,
the D-12 RED commit body, and the D-12 GREEN commit body.
