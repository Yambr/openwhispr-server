# Phase 02.12: Better Auth session.token field — Summary

Adopted Better Auth v1.6.9's canonical plain-text `session.token` model. Closes Phase 02.5-04 cascade tail #11 (`BetterAuthError: The field "token" does not exist in the schema for the model "session"`) by replacing Phase 02 Plan 01's bytea hash-only storage (AUTH-04 v1) with plain text on `sessions.token` / `sessions.previous_token`. AUTH-04 5-minute overlap CONTRACT preserved unchanged at the API layer; storage representation flipped from bytea(SHA-256) to text. At-rest hardening deferred to v2 (column-level pgcrypto / Postgres TDE) — ADR-tracked.

## Defect → fix narrative

**Symptom (Phase 02.5-04 cascade tail #11):** Better Auth's drizzle adapter throws `BetterAuthError: The field "token" does not exist in the schema for the model "session". Please update your schema.` Sign-in (`POST /api/auth/sign-in/email`) returns HTTP 500 → entire conformance suite blocked at signin gate.

**Root cause:** Phase 02 Plan 01 designed `sessions.tokenHash bytea` (AUTH-04 v1 hash-only storage as defense-in-depth). Better Auth v1.6.9 has no native hashed-token support; its drizzle adapter expects the canonical `session.token` text column. Every mainstream OSS auth library (NextAuth, Auth.js, Lucia, BA itself) stores plain session bearers — the hash design fights the auth library and is over-engineered for v1 self-host (DB-side defense should be Postgres TDE / disk encryption, not application-layer hashing).

**Fix (Option C from advisor research):**

1. **New migration `0005_session_token_plain.sql`:**
   - `DROP INDEX sessions_previous_token_hash_idx` (drop dependents first).
   - `DROP FUNCTION lookup_session_by_previous_token(bytea)` (drop dependents first).
   - `TRUNCATE TABLE sessions` (Phase 02 dev — no prod data; FK chains do not cascade outwards).
   - `DROP COLUMN token_hash`, `DROP COLUMN previous_token_hash`.
   - `ADD COLUMN token text NOT NULL`, `ADD COLUMN previous_token text`.
   - `CREATE UNIQUE INDEX sessions_token_unique ON sessions(token)`.
   - `CREATE INDEX sessions_previous_token_idx ON sessions(previous_token) WHERE previous_token IS NOT NULL`.
   - Recreated `lookup_session_by_previous_token(text)` + new `session_lookup_by_token(text)` with `SECURITY DEFINER STABLE SET search_path = public, pg_temp`. REVOKE FROM PUBLIC + GRANT EXECUTE TO openwhispr_app.

2. **Drizzle schema** (`packages/data/src/schema/sessions.ts`): replaced bytea customType + tokenHash columns with `text("token").notNull()` + `text("previous_token")`; explicit `uniqueIndex("sessions_token_unique").on(t.token)`.

3. **token-rotation.ts:** deleted `hashToken()` helper (~40 LOC SHA-256 machinery); rewrote `recordPreviousToken` to write plain text into `sessions.previous_token`; rewrote `tryPreviousToken` to query plain text (no hash binding).

4. **index.ts + test-only.ts:** dropped `hashToken` import + usage; pass plain bearer to `recordPreviousToken`; rotation route updates `token` / `previous_token` directly.

5. **auth.ts:** doc comment update only — no `session.fields.token` override needed (BA's default field name now matches our column name).

6. **Test refactors (Rule 1 deviation):** existing tests in `0001_better_auth.test.ts`, `0003_better_auth_tenant_defaults.test.ts`, `rls-property.test.ts`, `token-rotation-overlap.test.ts`, `token-rotation.test.ts`, `test-only.test.ts`, `entrypoint-db-shape.test.ts` pinned the bytea storage shape; flipped to plain-text shape inline since they pin the schema being changed.

## ADR placeholder note (D-05)

**AUTH-04 v2 hardening (deferred to v2):** Phase 02.12 trades application-layer hash-only token storage for BA-native plain-text + UNIQUE index on `sessions.token`. Defense-in-depth at rest is now the responsibility of either:

- **Column-level pgcrypto** — `pgp_sym_encrypt(token, get_dek())` on INSERT, `pgp_sym_decrypt` on SELECT, with the DEK rotated via Vault/KMS. Drizzle adapter would need a custom column type (Phase v2.1 candidate).
- **Postgres TDE / disk-level encryption** — operator concern (LUKS, AWS EBS encryption, etc.). Documented in self-host operator runbook (Phase v2.0).

Logged to `STATE.md` Roadmap Evolution section. Phase 02 single-tenant dev posture is acceptable until v2 multi-tenant hardening sweep.
