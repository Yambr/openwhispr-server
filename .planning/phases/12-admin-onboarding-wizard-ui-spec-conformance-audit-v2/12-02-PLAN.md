<objective>
Ship three capability-discovery endpoints that the wizard, the auth screens, and (later) Phase 14 BYOK pages all consume:
1. Public `GET /api/auth/providers` — zero-drift OIDC provider list (D-08).
2. Authed `GET /api/capabilities` — tenant-scoped feature payload (Phase 14 grows it).
3. Public `GET /api/setup-state` — minimal boolean-shaped `{status}` endpoint consumed by the unauth `/setup` RSC fetch. Required because `/api/capabilities` is session-required and the wizard runs BEFORE any admin user exists (RESEARCH §15(a) — "fetch /api/capabilities OR a public /api/setup-state mini-endpoint"; we choose the latter so `/api/capabilities` stays session-only per D-07).

Purpose: UICONF-01 + ADMIN-02 need a runtime source of truth for "which providers are configured" so the UI stops baking it at build time (closes TD-12.c). Plan 12-03's `/setup` page needs an unauth status read. Phase 14 will grow `/api/capabilities` additively.

Output: One shared utility (`lib/oidc-providers.ts`), three new route plugins, four new test files, one routes-registration edit, and a one-line auth.ts extraction — single atomic commit. Sequenced after Plan 12-01 (depends_on) because both edit `apps/api/src/auth.ts`.
</objective>
