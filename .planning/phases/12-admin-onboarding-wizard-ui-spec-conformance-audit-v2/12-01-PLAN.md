<objective>
Ship the foundation that unlocks every other Phase 12 plan: a singleton `setup_state` table (operator-global, no RLS), a nullable `users.role` column, and Better Auth's `additionalFields.role` extension with `input: false` to prevent role escalation through public sign-up.

Purpose: ADMIN-01 needs a state-machine gate (NOT a `users-count` check) so v1-upgrade installs do not double-create admin. ADMIN-03 needs a role column to mark the wizard-created user as admin. The same migration ships both atomically because squawk linting wants one cohesive additive migration, not two.

Output: One new schema file, one new migration, one Better Auth extension hunk in `auth.ts`, three test files (one schema, one migration, one auth role-escalation), all in a single atomic commit.
</objective>
