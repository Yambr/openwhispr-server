## STRUCT-03 Helm in Monorepo vs Separate Repo

| Option | Pros | Cons | Complexity | Recommendation |
|--------|------|------|------------|----------------|
| **1. Keep Helm in monorepo (status quo)** | Single PR for cross-cutting compose+Helm+code changes; Compose-Chart parity gate (`tools/lint-compose-chart-parity.ts`) keeps working with zero ceremony; Phase 14's 5 `*.enabled` toggles + Phase 17 cert-manager sub-chart land atomically; matches user-global "НЕ СОЗДАВАТЬ ОТДЕЛЬНЫЕ ПРОЕКТЫ"; single CI surface, contributors onboard once; industry precedent for single-product charts (cert-manager, Traefik, CloudNativePG all ship chart in main repo) | No discoverability on ArtifactHub until distribution wired; bare `charts/openwhispr/` directory has no published index.yaml; `helm install openwhispr/openwhispr` doesn't resolve | Surface: 0 new files. Risk: distribution remains git-clone-only until v3 publication — blocks operator UX | Rec only if ArtifactHub publication is genuinely deferred to v3 and `git clone && helm install ./charts/openwhispr` is acceptable interim UX |
| **2. Extract to `openwhispr-charts` repo** | Mirrors Grafana/Prometheus-community pattern; chart-releaser-action works on conventional `/charts` layout; clean ArtifactHub registration; chart semver decouples from server semver | Breaks Compose-Chart parity gate — must either delete it (loses Phase 14 invariant) or build cross-repo sync bot (new infra, drift risk); every Phase 14/17-style change becomes 2 PRs across 2 repos; violates user-global rule "do not create separate projects"; Grafana/Prom precedent applies to **multi-chart orgs** (40+ charts), not single-product backends; doubles CI surface; contributors must clone 2 repos | Surface: new repo, mirror workflow, parity-gate rewrite or deletion. Risk: HIGH — parity drift between compose and Helm is exactly the bug class Phase 14 worked to eliminate | Not recommended — costs are structural, benefits are cosmetic |
| **3. Monorepo + `chart-releaser-action` workflow** | Keeps every monorepo advantage of Option 1 (atomic PRs, parity gate intact, single CI, user-global rule satisfied); `helm/chart-releaser-action` officially supports `charts_dir` parameter for subdirectory publishing; on tag push, publishes packaged chart + `index.yaml` to `gh-pages` branch; ArtifactHub registers the gh-pages URL exactly as it would a dedicated repo — operators get `helm repo add openwhispr https://openwhispr.github.io/openwhispr-server`; tag-scoped releases via `openwhispr-chart-vX.Y.Z` give chart its own semver lane without repo split; precedent: many CNCF projects (Linkerd, Argo CD sub-charts, OpenTelemetry-operator) publish from monorepo subdirs this way | Tag scheme needs convention (`chart-vX.Y.Z` separate from server `vX.Y.Z`) — one-time decision; gh-pages branch must be enabled; signing (provenance) is optional add-on | Surface: 1 new workflow file (`.github/workflows/chart-release.yml`), 1 docs section, gh-pages branch init. Risk: LOW — chart-releaser-action is the Helm-project-sanctioned tool, well-documented, widely used | **Strongly recommended** — captures all distribution benefits of Option 2 with none of the coordination tax |

**Rationale:** Option 3 is the decisive winner for this codebase. The Compose-Chart parity gate (`tools/lint-compose-chart-parity.ts`) is a load-bearing invariant established in Phase 14 — it guarantees that the 5 new `*.enabled` toggles and every future env-key change land in compose and Helm together; Option 2 either destroys that gate or replaces it with a fragile cross-repo bot, which directly contradicts the project's "enterprise-grade, no workarounds" stance and the user-global "НЕ СОЗДАВАТЬ ОТДЕЛЬНЫЕ ПРОЕКТЫ" rule. The Grafana/Prometheus precedent for separate `helm-charts` repos applies to organizations shipping dozens of independently-versioned charts (40+ in prometheus-community); OpenWhispr ships **one** chart (`charts/openwhispr/`) for **one** product, putting it firmly in the single-product cohort (cert-manager, Traefik, CloudNativePG, Linkerd) where the chart lives in the main repo. The only legitimate concern Option 2 addresses — ArtifactHub discoverability and `helm repo add` UX — is solved natively by `helm/chart-releaser-action` with its `charts_dir` parameter, which is the Helm project's own sanctioned tool for exactly this scenario. Phase 17's cert-manager sub-chart and any future toggle additions will continue landing as single atomic PRs with the parity gate green. Chart semver can be decoupled from server semver via a dedicated tag prefix (`chart-v1.2.3`), giving operators a clean upgrade lane without splitting the repo.
