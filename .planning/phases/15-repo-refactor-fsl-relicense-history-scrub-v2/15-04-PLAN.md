<deviation_handling>
- If `git filter-repo` is not installed on the operator's machine → halt; document install instructions in the runbook; do NOT fall back to `git filter-branch` (deprecated, slower, more failure modes).
- If `git push --force-with-lease` fails because `main` advanced mid-window → operator retries from step 3 (fresh clone) AFTER coordinating to freeze new commits; do NOT switch to `--force` (loses safety).
- If branch protection PUT fails because the repo uses GitHub rulesets instead of legacy branch protection → document the ruleset API (`gh api /repos/.../rulesets`) in the runbook and update the script accordingly; do NOT bypass protection.
- If a signed tag's signature cannot be verified post-rewrite → list it explicitly for manual re-sign per deferred-items #1; do NOT silently re-sign with a different key.
- If GHA cache flush enumeration fails because there are too many entries to paginate cleanly → fall back to bumping `CACHE_VERSION` ONLY (cache will age out naturally); document in runbook.
- If Phase 13 Gherkin suite fails post-scrub → halt; do NOT proceed with the ops commit until root cause identified (history rewrite SHOULD NOT affect tests against working-tree content, so a failure is a real signal).
- If the operator force-pushes WITHOUT running the dry-run first → log a post-incident note; the runbook prose makes dry-run a hard step.
</deviation_handling>
