## 9. TDD atomic commit pattern (D-25)

**Analog SHAs (Phase 17-fix):**
- RED: `be8ed57 test(17-fix): wr-05 red — issuer must use ingressClassName not deprecated class`
- GREEN: `4118d26 fix(17-fix): wr-05 green — switch issuer.yaml to ingressClassName + update values.yaml comment`

Also Phase 16-fix: `b42fa19 test(16-fix): red — close-out remove must precede keep-keyword check (wr-01)` → `17d95c2 fix(16-fix): green — reorder classifyLine to check close-out before keep keywords (wr-01)`.

**Convention:** **two-commit** pair (RED test, then GREEN fix) — NOT a single bundled commit. CLAUDE.md says "same atomic commit" but recent practice (17-fix, 16-fix) splits RED/GREEN as adjacent commits with shared ID suffix (`wr-05`, `cr-01`). RED commit proves the test fails on prior HEAD; GREEN commit lands the fix. Both must reference the same identifier `(<ID>)`.

**18.1 commit scope adoption:** `fix(18.1-<NN>): <subject> (<ID>)` and `test(18.1-<NN>): red — <subject> (<ID>)`. Match Phase 17/16-fix shape, not the older Phase 02.x style.

**Risk:** D-25 wording says "atomic commit (RED via failing CI, GREEN via fix in same commit)". Resolve in favour of the **recent precedent (two commits)** because CI proof of RED requires the RED commit to exist on its own. Planner should confirm during plan-check; if user pushes back, single-commit is also valid per strict-TDD interpretation.
