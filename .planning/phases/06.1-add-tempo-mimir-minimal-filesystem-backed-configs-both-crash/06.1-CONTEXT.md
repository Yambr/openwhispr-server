# Phase 06.1 — CONTEXT

## Goal

Make tempo + mimir + otel-collector start and run cleanly under `docker compose --profile default up`. Unblock further validation of Phase 01.1 Plan 05 (compose stack-up smoke).

## Locked Decisions

### D-01 — Filesystem-backed minimal configs (no external deps)
Both tempo and mimir need explicit config files; their default-empty backends abort with `unknown backend ""`. Use `local` (tempo) / `filesystem` (mimir) backend so the default-compose stack works with zero infrastructure prerequisites. K8s/HA deployments swap to S3/MinIO/GCS in Phase 9 Helm — only the `storage.*.backend` keys change.

### D-02 — Distroless images cannot expose docker HEALTHCHECK
mimir 2.x and otel-collector-contrib 0.151 are distroless (no shell, no wget, no curl — only the service binary). Docker `HEALTHCHECK` requires an in-image executable. Workaround: drop the `healthcheck:` block; switch dependents to `condition: service_started`. Orchestration-level liveness moves to Helm/K8s probes in Phase 9 (kubelet HTTP probe doesn't need an in-container shell).

tempo IS distroless too, but has busybox at `/busybox/wget` — use direct `CMD ["/busybox/wget", ...]` form (NOT CMD-SHELL).

### D-03 — Single-binary `target: all` for mimir
Multi-component mimir requires service discovery (DNS or consul) and a multi-replica ring. For default self-host single-VM, monolithic `target: all` with single-replica memberlist on `127.0.0.1` is the boring choice; matches CloudNativePG / single-binary loki defaults.

### D-04 — `loki` exporter renamed to `otlphttp/loki`
The dedicated `loki` exporter was removed from otelcol-contrib in v0.114; current best practice is `otlphttp` pointed at Loki's native OTLP endpoint at `http://loki:3100/otlp` (GA in Loki 3.x). 0.151.0 aborts with `unknown type loki` if the old exporter id is still referenced.

### D-05 — Out of scope (DEFERRED)
- grafana plugin install on first boot (`grafana-pyroscope-app`, `grafana-lokiexplore-app`) takes 2-3 minutes over network; bumped `start_period` to 90s but ultimately would benefit from baked-in image or `GF_INSTALL_PLUGINS=` set to empty. Phase 6 hardening.
- `make contract-test` invokes `pnpm seed:conformance` from the **host shell** with `DATABASE_URL_OWNER=postgres://...@postgres:5432/...` — that hostname only resolves inside the compose network. Will need either a published port on postgres OR running seed from a one-shot `seed` compose service like migrate. Phase 02 plan 02 hygiene.
