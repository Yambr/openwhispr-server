# Plan 06.1-01 — SUMMARY

## Outcome

Phase 06.1 succeeded. tempo + mimir + otel-collector now start cleanly under `docker compose --profile default up -d --wait`. **All API-critical services healthy** (postgres, pgbouncer, valkey, minio, loki, tempo, traefik, api). The cycle of cascading defects unmasked by Phase 01.1 + 02.1 + 02.2 + 01.2 is resolved at the observability layer.

## What was built

### Fix 1 — `compose/tempo/tempo.yaml` (new file)

Minimal filesystem-backend tempo config. Single-binary `target: all` (implicit by absence), local block storage at `/var/tempo/blocks`, WAL at `/var/tempo/wal`. OTLP receivers at gRPC 4317 + HTTP 4318. Compaction enabled with 24h block retention. Telemetry usage report disabled.

### Fix 2 — `compose/mimir/mimir.yaml` (new file)

Monolithic `target: all` mimir config. Filesystem common storage at `/data/mimir`. Single-replica memberlist ring bound to `127.0.0.1` to avoid DNS dependency. Multi-tenancy disabled. Generous ingestion limits (100k/s rate, 200k burst) suitable for single-host load.

### Fix 3 — `docker-compose.yml` tempo + mimir + otel-collector wiring

- tempo: `command: ["-config.file=/etc/tempo/tempo.yaml"]`, mount config, mount data volume at `/var/tempo`. Healthcheck via `["CMD", "/busybox/wget", "--spider", "-q", "http://127.0.0.1:3200/ready"]` — direct CMD form (distroless image has no `/bin/sh`). `start_period: 60s` budgets ingester ring-join.
- mimir: `command: ["-config.file=/etc/mimir/mimir.yaml"]`, mount config + data volume. **No HEALTHCHECK** (distroless, no busybox). Dependents updated to `condition: service_started`.
- otel-collector: HEALTHCHECK removed (distroless). No dependents required `service_healthy`, so no contract update needed.

### Fix 4 — `compose/otel-collector/config.yaml` exporter rename

Replaced the deprecated `loki` exporter with `otlphttp/loki` (endpoint `http://loki:3100/otlp`, TLS insecure). Updated the logs pipeline reference. The loki exporter was removed from otelcol-contrib v0.114; 0.151 aborts with `unknown type loki`.

### Fix 5 — `docker-compose.yml` grafana healthcheck `start_period: 90s`

First-boot installs `grafana-pyroscope-app` and `grafana-lokiexplore-app` plugins over network (~2-3 minutes). Old `start_period: 15s` was too short, causing perpetual unhealthy until plugins installed. Bumped to 90s. Still flaps occasionally on cold cache; see D-05 deferred.
