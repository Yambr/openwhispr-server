# Plan 02.1-01 — SUMMARY

## Outcome

**Phase 02.1 succeeded** without `--legacy`, without `force-legacy-deploy`, without any other workaround. Dockerfile pnpm v10 ERR_PNPM_DEPLOY_NONINJECTED_WORKSPACE blocker eliminated by replacing `pnpm deploy` with industry-standard multi-stage build pattern, made possible by inlining workspace deps into the api bundle.

## What was built

### Change 1 — `apps/api/tsup.config.ts`

Added `noExternal: [/^@openwhispr\//]` to the api entry-point config. Workspace packages (`@openwhispr/data`, `@openwhispr/contract-tests`) are now inlined into the api bundle instead of left as external imports. Bundle grew from 67KB to 505KB (acceptable for a server image; eliminates runtime dependency on workspace TypeScript source).

### Change 2 — `apps/api/Dockerfile`

Three-stage rewrite:
- **builder** — full workspace install, build api (with noExternal inlining workspaces) and data (CJS bundle for migrate service)
- **prod-deps** — `pnpm install --prod --node-linker=hoisted --filter @openwhispr/api...` produces a flat `node_modules` with NO pnpm symlinks, safe to COPY across stages. Replaces the broken `pnpm deploy` invocation.
- **runtime** — `node:24-alpine` minimal image; copies hoisted `node_modules` + api `dist/` + data's `dist/migrate.js` (the migrate compose service still invokes `node /app/packages/data/dist/migrate.js`). Preserves USER node, BusyBox healthcheck, defense-in-depth secrets check.

## Investigation history (kept for the next maintainer)

### Variant A (`inject-workspace-packages: true`) — REJECTED

Empirically not honored by pnpm 11.0.8:
- Adding to `pnpm-workspace.yaml` → `pnpm config get inject-workspace-packages` returns `undefined`
- Adding to root `.npmrc` → also `undefined`
- `pnpm install --force` AND `rm -rf node_modules && pnpm install` both produce symlinked workspace deps
- `pnpm --filter @openwhispr/api --prod deploy /out` continues to throw `ERR_PNPM_DEPLOY_NONINJECTED_WORKSPACE`

May indicate a pnpm 11.0.8 documentation gap, OR may require companion `dependenciesMeta.{name}.injected: true` annotations per consumer. Either way, NOT a one-line config fix.

### Variant B (multi-stage Dockerfile without `pnpm deploy`) — INITIALLY BLOCKED, then resolved

Variant B initially failed because `apps/api/dist/index.js` kept workspace imports external, but `@openwhispr/data` and `@openwhispr/contract-tests` had no usable build output (data only built migrate.js for a separate service; contract-tests build was `tsc --noEmit`). The previous `pnpm deploy`-based Dockerfile only "worked" because compose-up failed earlier on the MinIO pin and never actually proved the api could start.

**Resolution**: change tsup config so api's bundle inlines all `@openwhispr/*` workspace deps, making the runtime image's `node_modules` only need non-workspace deps. Then variant B becomes trivially correct.
