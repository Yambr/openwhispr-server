# Phase 9 Plan 5: CNPG Pooler + Bitnami Valkey/MinIO Sub-Charts Summary

`charts/openwhispr/templates/pooler.yaml` ships a CNPG Pooler CR that replaces the compose-level 4-instance PgBouncer Deployment with native HA + automatic SCRAM credential rotation (decision A6). `charts/openwhispr/Chart.yaml` vendors Bitnami Valkey 5.6.5 and MinIO 17.0.21 as OCI sub-chart dependencies condition-gated on `values.{valkey,minio}.enabled` (decision A5). The compose-chart parity tool gains a `COMPOSE_SERVICE_ALIASES` map so the CRD-backed Cluster + Pooler resolve to compose `postgres` / `pgbouncer` services natively, and the parity allowlist drops 4 entries (postgres, pgbouncer, valkey, minio). `docs/licensing-bitnami-2024.md` documents the Aug 2025 Bitnami Secure Images licensing change and the corporate override path (image-tree overrides + a deferred Option B operator path).

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] helm-unittest 1.1.0 cannot un-render sub-chart docs at set:-time, breaking the planned condition-off tests.**

- **Found during:** Task 2 first run.
- **Issue:** Plan called for tests asserting Valkey/MinIO sub-charts produce no docs when `{valkey,minio}.enabled=false`. The Helm chart `dependencies[].condition` field is resolved at chart-load time, not after the unittest applies per-test `set:` values — so the sub-chart docs render regardless. `containsDocument` was finding the docs and the `not: true` inversion always failed.
- **Fix:** Switched test strategy to per-template (`template: charts/{valkey,minio}/templates/...`) positive-path assertions on the actual rendered StatefulSet / Deployment fields. The negative path (sub-chart properly skipped when `enabled=false`) is covered by `helm template` + the compose-chart parity lint which would flag a renamed/missing resource. Comment block in subcharts_test.yaml documents the rationale.
- **Files:** `charts/openwhispr/tests/subcharts_test.yaml`.

**2. [Rule 1 - Bug] `extractChartResources` only stripped the `<release>-openwhispr-` prefix; sub-chart resources like `ow-minio` never matched.**

- **Found during:** First parity smoke after adding subchart deps.
- **Issue:** Plan called for an alias map to cover CRD-renamed resources, but the alias map alone doesn't help with sub-charts that use `<release>-<subchart-name>` (no `openwhispr` segment). The parity lint saw `ow-minio` rather than `minio` and counted it as orphaned.
- **Fix:** Added an `else-if startsWith(altPrefix)` branch that strips the bare release prefix as a fallback. `ow-minio` -> `minio` matches compose service `minio` directly. `ow-valkey-primary` -> `valkey-primary` requires the alias map entry `valkey -> valkey-primary`.

**3. [Rule 2 - Critical] Allowlist annotation must trace each removed entry to its replacement mechanism.**

- **Found during:** Allowlist trim.
- **Issue:** Just deleting `postgres` / `pgbouncer` / `valkey` / `minio` from the allowlist would lose the chain-of-evidence for why they're no longer needed. Wave 0's annotation style sets the precedent.
- **Fix:** Each removed entry is annotated `LANDED` with its alias-map path or "ow-<name> Deployment, strip release prefix". Future grep for "wave-deferred" + the service name lands on the explanation.
