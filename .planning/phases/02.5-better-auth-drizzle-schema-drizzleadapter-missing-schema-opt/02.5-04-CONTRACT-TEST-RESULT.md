### Root-cause of the seed 500 (NEW defect — Phase 02.6 candidate)

API logs show:

```
ERROR [Better Auth]: TypeError: db.select is not a function
    at Object.findOne (file:///app/node_modules/@better-auth/drizzle-adapter/dist/index.mjs:303:26)
    at Object.findUserByEmail (file:///app/node_modules/better-auth/dist/db/internal-adapter.mjs:445:60)
    at async file:///app/node_modules/better-auth/dist/api/routes/sign-up.mjs:164:18
```

This is **NOT** the schema-mapping error Plans 02+03 fixed (`The model "user" was not found in the schema object`). Better Auth resolved the model `user` → drizzle table `users` correctly via Plan 03's explicit map, then dispatched into the drizzle adapter's `findOne` — which is when the new error surfaced.

**Source of the bug:** `apps/api/src/index.ts:229-233` — production bootstrap:

```ts
const { makeAppDb } = await import("@openwhispr/data/client");
const { buildAuth } = await import("./auth.js");
const db = makeAppDb();                                          // returns { db, pool }
const auth = buildAuth({ db: db as never }) as unknown as AuthLike;
const app = await buildApp({ db: db as never, auth });
```

`makeAppDb()` returns the wrapper `{ db: NodePgDatabase, pool: Pool }` (per `packages/data/src/client.ts:33-41`). The bootstrap assigns the wrapper to `db` and passes it through, so `drizzleAdapter` receives the wrapper instead of the real Drizzle instance — hence `db.select is not a function`. The `as never` casts hid the type mismatch from the compiler.

The fix is one line: `const { db } = makeAppDb();` (destructure). But per the Plan 04 execution-context rule ("If contract-test reveals a NEW defect (not the schema/tenant issue we just fixed): STOP, surface as deviation — that's a Phase 02.6 candidate"), this is **not** auto-fixed by Plan 04. Phase 02.6 will own it.

Consider documenting a `make clean-stack` that does `docker compose --profile default --profile contract-test down -v` before re-running, or making bootstrap warn when an existing postgres volume's password is unknown.

## Phase 02.6 candidate (deferred fix)

**File:** `apps/api/src/index.ts:229-233`

**Fix (one-liner — TBD via Phase 02.6 plan):**

```diff
-  const db = makeAppDb();
-  const auth = buildAuth({ db: db as never }) as unknown as AuthLike;
-  const app = await buildApp({ db: db as never, auth });
+  const { db } = makeAppDb();
+  const auth = buildAuth({ db });
+  const app = await buildApp({ db, auth });
```

Plus removal of the `as never` casts that hid the wrapper-vs-instance type mismatch. Phase 02.6 should also add a unit test that asserts `buildAuth({ db })` receives an object with a callable `.select` method (or equivalent runtime contract test) so this class of wrapper-leak defect is caught before reaching the drizzle adapter at runtime.
