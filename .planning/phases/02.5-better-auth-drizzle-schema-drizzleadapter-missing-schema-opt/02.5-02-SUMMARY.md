## Decisions Made

- **Test harness permission grants instead of test-only superuser owner:** the alternative — promoting `openwhispr_owner` to `SUPERUSER` in the testcontainer — would diverge sharply from production where owner is BYPASSRLS but not superuser. The chosen approach (CREATEROLE + ADMIN OPTION on openwhispr_app + parameter-level GRANT on `app.tenant_id`) keeps the test owner's privilege envelope tight and explicit, and the comments explain the production-vs-test asymmetry. This matches the established pattern in PG 15+ where parameter-level GRANTs let non-superusers manage specific custom GUCs.
- **Removed `app.current_tenant` from migration comments** to fully satisfy plan acceptance criterion "No `app.current_tenant` string anywhere in the file." The rationale paragraph was rephrased to "alternate GUC name" while preserving the documentation-typo explanation.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 3 — Blocking] Test harness owner role lacked privileges to apply migration 0003's ALTER ROLE**

- **Found during:** Task 2 (first integration-test run after migration landed)
- **Issue:** The migration's `ALTER ROLE openwhispr_app SET app.tenant_id TO ...` failed with two cascading permission errors: first `permission denied to alter role` (owner lacked CREATEROLE + ADMIN OPTION on openwhispr_app), then `permission denied to set parameter "app.tenant_id"` (owner lacked SET privilege on the custom GUC at role scope — PG 15+ requires either superuser or explicit `GRANT SET ON PARAMETER`).
- **Fix:** Added three grants in three test-harness boot routines (`helpers.ts`, `rls-property.test.ts`, `pgbouncer-interleave.test.ts`):
  1. `CREATE ROLE openwhispr_owner` now includes `CREATEROLE`.
  2. `GRANT openwhispr_app TO openwhispr_owner WITH ADMIN OPTION` (so owner can ALTER openwhispr_app).
  3. `GRANT SET, ALTER SYSTEM ON PARAMETER "app.tenant_id" TO openwhispr_owner` (PG 15+ parameter-level grant).
- **Production impact:** None. In production, `openwhispr_owner` IS the bootstrap superuser (per `packages/data/migrations/init/00-roles.sql.tpl` — `POSTGRES_USER` is mapped to `openwhispr_owner` at container init), so all three privileges are implicit. The grants only land in test harnesses where owner is created by a separate superuser (`postgres_super`).
- **Files modified:** `packages/data/src/__tests__/helpers.ts`, `packages/data/src/__tests__/rls-property.test.ts`, `packages/data/src/__tests__/pgbouncer-interleave.test.ts`
- **Commit:** `91784ab` (same atomic commit as the migration)
