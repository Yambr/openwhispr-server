## Deviations from Plan

### Stop-on-new-defect (per Plan 04 execution-context rule, NOT an auto-fix)

**1. NEW DEFECT surfaced — wrapper-`db` passed to `drizzleAdapter` in production bootstrap**

- **Found during:** Task 1, second `make contract-test` invocation, seed step.
- **Issue:** `apps/api/src/index.ts:229-233` does `const db = makeAppDb()` then `buildAuth({ db: db as never })`. But `makeAppDb()` returns `{ db: NodePgDatabase, pool: Pool }` (per `packages/data/src/client.ts:33-41`). The wrapper object — not the Drizzle instance — is then passed to `drizzleAdapter`, so `drizzle-adapter/dist/index.mjs:303` calls `wrapper.select(...)` and throws `TypeError: db.select is not a function`. Better Auth returns 500 on signup; seed exits 1; conformance suite never runs.
- **Why NOT auto-fixed in Plan 04:** explicit rule in Plan 04's `<execution_context>` says STOP and surface for Phase 02.6.
- **Fix path (for Phase 02.6):** destructure — `const { db } = makeAppDb();` and remove the `as never` casts that hid the wrapper-vs-instance type mismatch from the compiler. Add a unit test that asserts `buildAuth({ db })` receives an object with a callable `.select` method.
- **Files affected:** `apps/api/src/index.ts:229-233`
- **Documented in:** `02.5-04-CONTRACT-TEST-RESULT.md` § "Phase 02.6 candidate (deferred fix)"

### Auto-handled retry (within scope — environment hygiene)

**2. [Rule 3 — Blocking] Stale postgres data volume from prior session caused first-attempt migrate failure**

- **Found during:** Task 1, first `make contract-test` invocation, migrate step.
- **Issue:** `bootstrap.sh` regenerated `.env` with new owner/app passwords, but `openwhispr_postgres_data` Docker volume retained from a previous session still had the OLD owner password baked into pg_authid. `migrate` container failed with `password authentication failed for user "openwhispr_owner"` and postgres logged `PostgreSQL Database directory appears to contain a database; Skipping initialization`.
- **Fix:** `docker compose --profile default --profile contract-test down -v` to wipe volumes, then re-ran `make contract-test` which got the clean init path.
- **Production impact:** None of this is a Plan 04 deliverable to fix — but documented in result file as a DEVEX/Phase 02.6 follow-up candidate (consider `make clean-stack` target, or `bootstrap.sh` detecting a previously-initialized postgres volume).
- **Files affected:** none (operational)
