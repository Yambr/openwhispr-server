## Witness 2 — Integration test RED (packages/data, testcontainer)

`pnpm -F @openwhispr/data test --run src/__tests__/0003_better_auth_tenant_defaults.test.ts`

```
 ❯ src/__tests__/0003_better_auth_tenant_defaults.test.ts (5 tests | 5 failed) 1619ms
     × ALTER ROLE openwhispr_app sets app.tenant_id=00000000-... default-tenant UUID
     × INSERT INTO users without tenant_id picks up default-tenant via column DEFAULT
     × INSERT INTO sessions without tenant_id picks up default-tenant
     × INSERT INTO account without tenant_id picks up default-tenant
     × INSERT INTO verification without tenant_id picks up default-tenant

(1) AssertionError: expected [] to deeply equal ArrayContaining{…}
- ArrayContaining [ "app.tenant_id=00000000-0000-0000-0000-000000000000" ]
+ []

(2..5) error: new row violates row-level security policy for table "users"
       error: new row violates row-level security policy for table "verification"
```

**Diagnosis:** No `ALTER ROLE openwhispr_app SET app.tenant_id = ...`
exists yet (rolconfig is empty), and `users/sessions/account/verification`
have no column DEFAULT bound to `current_setting('app.tenant_id')::uuid`.
Bare INSERTs without explicit `tenant_id` therefore fail the FORCE RLS
policy (USING / WITH CHECK clause requires `tenant_id =
current_setting('app.tenant_id', true)::uuid`). Plan 02's migration
0003 fixes by setting the role default + adding column DEFAULTs to all
four Better Auth tables.

Full log: `/tmp/02.5-01-task2-red.log`
