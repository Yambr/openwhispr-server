# Phase 02.5 — CONTEXT

## Goal

Make `make contract-test` complete end-to-end by closing the Better Auth ↔ Drizzle binding gap surfaced at the end of Phase 02.3. The seed step currently aborts with:

```
[# Drizzle Adapter]: The model "user" was not found in the schema object.
Please pass the schema directly to the adapter options.
```

After this phase: signup/signin/verify-email all work, conformance contract suite runs against a live api+postgres+seed stack, and `02-HUMAN-UAT.md` Item 1 becomes flippable.

## Discovery — what's actually wrong

The diagnosis "missing schema option AND missing tables" was half-right. Investigation:

1. **SQL physical table names are already singular and Better-Auth-correct:** `account` (accounts.ts:12), `verification` (verifications.ts:9). The pluralized cases (`users`, `sessions`) are also fine — Better Auth permits both via `usePlural` flag.
2. **Drizzle export names are pluralized:** `users`, `sessions`, `accounts`, `verifications`. Better Auth's adapter looks up models by the KEY names in the `schema` object you pass, mapped to Better Auth's canonical names: `user`, `session`, `account`, `verification`.
3. **`apps/api/src/auth.ts:139` already passes `schema`** — but `import * as schema` exports the pluralized names. Better Auth then can't find the model "user" because the schema object has `users`, not `user`.
4. **Tenant-scoping is the real complication:** every Better Auth table has a `tenant_id` NOT NULL FK to `tenants.id`. Better Auth has no concept of tenant_id; it issues plain INSERTs. RLS is FORCE-attached on these tables (per accounts.ts:4 comment). So even if the schema mapping is fixed, every Better Auth INSERT will fail RLS unless the session sets `app.current_tenant`.

## Locked Decisions

### D-01 — Use explicit schema-key mapping (NOT rename exports)

Renaming `users` → `user` in `packages/data/src/schema/users.ts` would ripple through every consumer (RLS lint, TENANT_SCOPED_TABLES literal, every `import { users } from "@openwhispr/data/schema"` site). Not worth the blast radius for a name-mapping problem.

Instead, in `apps/api/src/auth.ts`:

```ts
import { users, sessions, accounts, verifications } from "@openwhispr/data/schema";
// ...
database: drizzleAdapter(db, {
  provider: "pg",
  schema: {
    user: users,
    session: sessions,
    account: accounts,
    verification: verifications,
  },
}),
```

Drizzle export names stay pluralized; only the adapter sees Better Auth's canonical names.

### D-02 — Single-tenant v1: bind `app.current_tenant` per request via Postgres `SET LOCAL`

PROJECT.md decision: "Multi-tenancy retained, single 'default' tenant in v1." That means:
- Every request runs in the default tenant context (UUID seeded by Phase 02 conformance fixture, also created by the api's startup migration).
- The `appDb` Drizzle client (PgBouncer-fronted, `openwhispr_app` role, RLS-subject) needs `SET LOCAL app.current_tenant = '<default-tenant-uuid>'` before any Better Auth INSERT runs.

Two implementation options:
- **(a)** Wrap `appDb` queries in a withTenant() helper; not feasible because Better Auth issues raw queries we don't control.
- **(b) RECOMMENDED** — Add a Drizzle/pg pool `beforeQuery` hook (or, cleaner: a Postgres role default via `ALTER ROLE openwhispr_app SET app.current_tenant = '<default-tenant-uuid>'`) so EVERY connection from `openwhispr_app` lands with the default tenant pre-bound.

D-02 picks **(b)** for v1: role default. Migration adds `ALTER ROLE openwhispr_app SET app.current_tenant TO '<default-tenant-uuid-literal>'`. When v2 introduces real multi-tenancy, this default is removed and per-request `SET LOCAL` is added in a Fastify hook before route handlers.

The default-tenant UUID is deterministic, seeded in `packages/data/migrations/.../seed-default-tenant.sql` (or analogous). Verify it exists; if not, this phase adds it.

### D-03 — Auto-populate `tenant_id` on Better Auth INSERTs via column DEFAULT

Better Auth issues `INSERT INTO user (id, email, name, ...) VALUES (...)`. It does NOT supply `tenant_id`. Solution: Postgres column DEFAULT bound to the session GUC.

```sql
ALTER TABLE users ALTER COLUMN tenant_id SET DEFAULT current_setting('app.current_tenant')::uuid;
ALTER TABLE sessions ALTER COLUMN tenant_id SET DEFAULT current_setting('app.current_tenant')::uuid;
ALTER TABLE account ALTER COLUMN tenant_id SET DEFAULT current_setting('app.current_tenant')::uuid;
ALTER TABLE verification ALTER COLUMN tenant_id SET DEFAULT current_setting('app.current_tenant')::uuid;
```

With D-02's role default, every Better Auth INSERT will pick up the default-tenant UUID transparently. This is the pattern documented in Postgres RLS literature for adapters that don't know about tenancy.

### D-05 — Migration ordering and naming

New migration file: `packages/data/migrations/0002_better_auth_tenant_defaults.sql`

Contents:
1. Default-tenant seed (idempotent INSERT ... ON CONFLICT DO NOTHING)
2. `ALTER ROLE openwhispr_app SET app.current_tenant TO '<uuid>'`
3. `ALTER TABLE` × 4 with the column DEFAULT

Must be reversible (DOWN migration). Drizzle-kit doesn't generate ALTER ROLE — file is hand-written like `0001_better_auth.sql`.
