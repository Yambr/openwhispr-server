## Findings (4)

### F35 — Better Auth signup 403 (Origin / trustedOrigins)

**Symptom:** probe returned `step:signup-failed, signupStatus:403`.

**Root cause:** Better Auth's CSRF gate rejects POST requests whose Origin doesn't match `trustedOrigins`. `undici.fetch` sends no Origin by default; chart-rendered api had no in-cluster origin in `trustedOrigins`.

**Fix (3 files):**
- `tools/test-probe/src/probe.ts` — signup request now sets `origin: opts.target`.
- `charts/openwhispr/templates/api-deployment.yaml` — `AUTH_TRUSTED_ORIGINS_EXTRA` env built from `http://<fullname>-api:3000` + `https://<host.api>` (+ optional operator extension).
- `charts/openwhispr/templates/api-deployment.yaml` — `OPENWHISPR_DISABLE_EMAIL_VERIFICATION=1` env when `api.env.disableEmailVerification=true`. values-kind.yaml sets it; production overlays never do.
- `tools/test-probe/src/probe.test.ts` — RED→GREEN assertion on `observed.signupOrigin`.

### F36 — CNPG Pooler hostname wrong in helper

**Symptom:** probe `step:signup-failed, signupStatus:500`. api log: `getaddrinfo EAI_AGAIN openwhispr-pg-pooler-rw`.

**Root cause:** `openwhispr.poolerHost` helper printed `<fullname>-pg-pooler-rw` but CNPG Pooler CR creates a Service named `<fullname>-pg-pooler` (no `-rw` suffix; only Cluster CR creates `-rw/-r/-ro` variants).

**Fix:** `templates/_helpers.tpl` `openwhispr.poolerHost` → `<fullname>-pg-pooler`. Existing `api_test.yaml` + `worker_test.yaml` assertions updated.

### F37 — SSRF dispatcher host_not_allowed for in-cluster LiteLLM

**Symptom:** probe `transcribeStatus:502`. api log: `security.ssrf_blocked, target_url_host: openwhispr-litellm, rule: host_not_allowed`.

**Root cause:** Default-deny `OUTBOUND_ALLOWED_HOSTS` allow-list was empty in chart-rendered env. api → LiteLLM hop refused at allow-list gate.

**Fix:** `templates/api-deployment.yaml` sets `OUTBOUND_ALLOWED_HOSTS = <fullname>-litellm` (+ optional operator extension via `api.env.outboundAllowedHosts`).

### F38 — SSRF dispatcher rfc1918_10 block on resolved Service IP

**Symptom:** probe `transcribeStatus:502`. api log: `security.ssrf_blocked, target_url_host: openwhispr-litellm, ip: 10.96.85.42, rule: rfc1918_10`.

**Root cause:** k8s Service IPs are RFC1918 (10.0.0.0/8). The dispatcher's second-layer per-IP block-list (DNS-rebinding defense) rejected the litellm Service IP even though F37 admitted the hostname.

**Fix:** `templates/api-deployment.yaml` sets `OUTBOUND_PRIVATE_HOST_ALLOWLIST = <fullname>-litellm` (+ optional operator extension via `api.env.outboundPrivateHostAllowlist`).
