# Phase 09.1 — Real kind Apply

## Why this phase exists

Phase 09 closed with 106/106 helm-unittest GREEN and full CI workflows (helm-upgrade-matrix, helm-release), **but `helm install` against a real Kubernetes cluster on the maintainer's machine was never executed**. helm-unittest renders templates offline — it does not validate:

- CRD ordering (CNPG `Cluster` applied before operator CRD is `Established`)
- Bitnami sub-chart resolution (`helm dependency update` pulling valkey/minio OCI artifacts)
- HPA targeting against a real `metrics-server`
- IngressRoute admittance by a real Traefik 3 install
- `helm test` hook wall-time execution against running pods
- cert-manager `Certificate` issuance with a real ClusterIssuer
- Init-container ordering, image pull on multi-arch nodes, probe wiring under real kubelet timing

The closing summary explicitly flagged: *"first real `helm install` = first live trial."* This phase converts that trial into a verified GREEN deploy on a local kind cluster, captures every wiring bug surfaced, and lands inline TDD fixes (RED helm-unittest assertion → fix template → GREEN) for each.

## Goal

> An operator on a fresh kind v0.31 cluster runs `examples/kind-bootstrap.sh && helm dependency update && helm install openwhispr ./charts/openwhispr -f values-kind.yaml --wait` and lands on a fully GREEN deploy in <10 min, including `helm test` hook GREEN (DEPLOY-05 first-launch SLO probe <5 min wall-time).

## Decisions (locked)

- **Scope**: Full — entire 4-tier dependency chain (CNPG + cert-manager + Traefik + chart with valkey + minio + litellm mock + otel collector). Wave 0 mock-litellm image, no GPU (Speaches skipped — covered by Phase 08.5 baseline).
- **Bug handling**: Inline atomic TDD fixes. Each bug → RED helm-unittest assertion (or kind smoke check) → fix template → GREEN → commit.
- **Cluster**: kind 0.31 multi-node config (1 control + 2 worker) so HPA + PDB + anti-affinity meaningfully exercise.
- **values-kind.yaml**: minimal override committed under `charts/openwhispr/examples/values-kind.yaml` for reproducibility.
- **ESO posture**: `secrets.mode: helm-values` (skip ESO branch — covered by helm-unittest only).
- **CNPG image**: pin to the `openwhispr/cnpg-postgres-17-pgpartman` image built in Plan 09-04; if not yet pushed to GHCR, build locally via `docker buildx` and `kind load docker-image`.

## Success criteria

1. `kind create cluster --config examples/kind-config.yaml` exits 0 with 3 nodes Ready.
2. CNPG operator + cert-manager + Traefik installed; CRDs `clusters.postgresql.cnpg.io`, `certificates.cert-manager.io`, `ingressroutes.traefik.io` all `Established=True`.
3. `helm dependency update charts/openwhispr` resolves valkey 5.6.5 + minio 17.0.21 from Bitnami OCI registry without error.
4. `helm install openwhispr ./charts/openwhispr -n ow --create-namespace -f charts/openwhispr/examples/values-kind.yaml --wait --timeout 10m` exits 0.
5. `kubectl get pods -n ow` shows api, web, worker, postgres (CNPG), pooler, valkey, minio, litellm, otel-collector all Running 1/1 (or N/N for daemonset/cluster).
6. `helm test openwhispr -n ow --logs` GREEN; first-launch SLO probe reports `slo_first_launch_seconds < 300`.
7. `helm-unittest` total still passes (no regressions from inline fixes); new RED-assertions added for every bug fixed.
8. `09.1-FINDINGS.md` documents every bug surfaced + fix commit hash.

## Non-goals

- Production cloud cluster (EKS/GKE/AKS) — kind is the gate; cloud is operator-side.
- GPU workloads (Speaches) — out of scope for the chart kind path.
- Real LiteLLM with paid keys — mock image is sufficient to validate plumbing.
- helm-upgrade-matrix replay locally — already covered by CI workflow; Phase 09.1 scope says "Full + helm test", not "Full + upgrade-matrix".

## Acceptance gate

Phase 09.1 closes when (a) success criteria 1–8 all PASS on the maintainer's mac under kind 0.31, (b) every inline fix has its commit + RED→GREEN test pair, (c) 09.1-SUMMARY.md written with full findings list, (d) ROADMAP slot 18 flipped to [X].
