# Phase 02.18 — CONTEXT

## Goal

Close cascade tail Group F (2 verification-status tests). Real prod security defect surfaced: Better Auth's own rate-limiter doesn't honor Fastify `trustProxy` and instead requires explicit `advanced.ipAddress.ipAddressHeaders`. Currently all rate-limited routes (sign-in, sign-up, forgot-password) collapse onto an empty-string bucket in prod = anti-abuse limiter is effectively disabled. Fix the prod defect AND solve the test problem with per-fixture unique X-Forwarded-For.

## Locked Decisions (Recommended Option B from advisor)

### D-01 — apps/api/src/auth.ts: configure advanced.ipAddress.ipAddressHeaders

In Better Auth options:
```ts
advanced: {
  ...existing,
  ipAddress: {
    ipAddressHeaders: ["x-forwarded-for"],
  },
}
```

This makes Better Auth's `getRequestIp` use the X-Forwarded-For header set by Traefik. Traefik strips client-supplied X-Forwarded-For at the public edge by default (`forwardedHeaders.trustedIPs`), so this is NOT a header-spoofing risk.

### D-02 — packages/contract-tests/src/helpers/sign-in-fixture.ts: inject unique X-Forwarded-For per fixture

Add module-scope counter; each `signInFixture()` call increments and forwards `x-forwarded-for: 10.0.0.<counter>`. Each fixture lands in its own bucket; deliberate D-28 assertions (check-user 11th-call, verification-status 31st-poll) UNCHANGED — they hammer one IP intentionally.
