# Phase 02.19: Traefik forwardedHeaders.trustedIPs (RFC 1918) — Group F E2E closure

Configured `entryPoints.websecure.forwardedHeaders.trustedIPs` on Traefik's static config to trust X-Forwarded-For ONLY from the three RFC 1918 private CIDRs. Closes the cascade tail surfaced by Phase 02.18 D-DISC: the contract-test runner inside `openwhispr_internal` (Docker default bridge, allocates within 172.16.0.0/12 or 192.168.0.0/16 depending on the host's IPAM pool — empirically observed `192.168.208.0/20` on this host) can now have its per-fixture X-Forwarded-For preserved end-to-end so Better Auth's rate-limiter buckets per synthetic test IP instead of collapsing onto the runner's single socket IP.

**Production safety preserved (D-03):** trustedIPs is a strict RFC 1918 allowlist. External clients on real public IPs are NOT in any trusted range. Traefik continues to overwrite their XFF per default Traefik 3 behavior. The prod-side abuse vector closed by 02.18 D-04 is unchanged.

## Defect → fix narrative

### Cascade tail from 02.18

Phase 02.18 fixed the production-side defect — `apps/api/src/auth.ts` now sets `advanced.ipAddress.ipAddressHeaders=["x-forwarded-for"]` so Better Auth's built-in rate-limiter (sign-in/sign-up/forgot-password/polling carve-out) actually buckets by real client IP behind a reverse proxy. But the contract-test runner's per-fixture XFF was not surviving the Traefik hop (Traefik default-strips client XFF when `forwardedHeaders.trustedIPs` is unset). The 02.18 SUMMARY D-DISC architectural finding listed three options for a follow-on phase; this phase implements **option (a)** — the smallest blast radius and the only one that closes Group F end-to-end while remaining production-correct.

### Fix — `compose/traefik/traefik.yml`

Added a `forwardedHeaders.trustedIPs` block to the `websecure` (port 443) entrypoint:

```yaml
websecure:
  address: ":443"
  http:
    tls: {}
  forwardedHeaders:
    trustedIPs:
      - 10.0.0.0/8       # RFC 1918 Class A private
      - 172.16.0.0/12    # RFC 1918 Class B private (Docker default bridge pool)
      - 192.168.0.0/16   # RFC 1918 Class C private
  transport:
    respondingTimeouts:
      readTimeout: 3700s
      writeTimeout: 3700s
      idleTimeout: 180s
```

Verification chain: a request from `192.168.208.x` (the openwhispr_internal subnet on this host) → Traefik checks the immediate socket IP against `trustedIPs` → 192.168.208.x is in 192.168.0.0/16 → trust the inbound `X-Forwarded-For` → forward header to api → Fastify resolves `req.ip` from XFF → Better Auth's `getIp()` reads `["x-forwarded-for"]` → buckets per synthetic IP.

A request from a real internet IP (e.g., 203.0.113.42) → Traefik checks against `trustedIPs` → 203.0.113.42 is NOT in any private range → Traefik discards client XFF and rewrites to the immediate socket IP. Production abuse vector remains closed.

## Production-safety verification (D-03)

The chosen `trustedIPs` allowlist contains ONLY RFC 1918 private ranges:

| CIDR              | RFC 1918 class | Purpose                                                      |
| ----------------- | -------------- | ------------------------------------------------------------ |
| `10.0.0.0/8`      | Class A        | Wide private range; covers BullMQ/test fixture XFF (10.x.y.z) |
| `172.16.0.0/12`   | Class B        | **Docker default bridge IPAM pool** (172.17–172.31.x)        |
| `192.168.0.0/16`  | Class C        | **This host's openwhispr_internal subnet (192.168.208.0/20)** + small home networks |

Explicitly **NOT trusted** (asserted by `tests/integration/traefik-forwarded-headers.test.ts` "ONLY RFC 1918" guard test):

- `0.0.0.0/0` — would trust any source (catastrophic)
- `127.0.0.0/8` — loopback (no legitimate XFF source)
- `100.64.0.0/10` — CGNAT (carrier-grade NAT, not behind our edge)
- All public unicast space (the entire IPv4 space minus the above)

The TDD test enforces this with an iteration over each entry and `expect(allowedPrivateCIDRs.has(cidr)).toBe(true)` — adding a non-private CIDR to traefik.yml in the future will fail this test and block the commit (lefthook commit-msg hook + CI).

### Empirical subnet verification (D-04)

```bash
$ docker network inspect openwhispr_openwhispr_internal | grep -A2 Subnet
                    "Subnet": "192.168.208.0/20",
                    "Gateway": "192.168.208.1"
```

`192.168.208.0/20` ⊂ `192.168.0.0/16` ✅ — trust applies.

```bash
$ docker network create --driver bridge openwhispr_test_probe && docker network inspect openwhispr_test_probe | grep -A1 Subnet
                    "Subnet": "172.28.0.0/16",
                    "Gateway": "172.28.0.1"
```

`172.28.0.0/16` ⊂ `172.16.0.0/12` ✅ — covers the alternate Docker default-bridge IPAM pool that gets allocated when the 192.168.x ranges are exhausted on a heavily-used host.
