## Phase 32 — RLS fail-closed ✅ CLOSED

### Implementation pivot — important for Phase 33

The originally-proposed RLS body `current_setting('app.tenant_id', true) IS NOT NULL AND <> '' AND tenant_id = current_setting(...)::uuid` does **NOT work** in PostgreSQL — the planner does not guarantee left-to-right short-circuit on the AND chain, and the `::uuid` cast hits empty string before the guard rejects it, raising `invalid input syntax for type uuid: ""`.

**Working pattern:** `tenant_id = NULLIF(current_setting('app.tenant_id', true), '')::uuid`. NULLIF returns NULL for empty string; cast yields NULL; comparison evaluates to NULL → treated as FALSE for USING and WITH CHECK. Documented in `32-SUMMARY.md` D-1 + migration 0018 header. **Phase 33 MUST inherit this pattern** for any new tenant-scoped tables or RLS-policy edits.

### Semantics chosen

- **Variant (a) silent-deny-read + raise-write** (rejected variant (b) raise-everywhere via `missing_ok=false`).
- SELECT without `withTenant()` returns 0 rows.
- INSERT/UPDATE/DELETE without `withTenant()` raises PG `42501`.
- Variant (b) was rejected because it would surface dozens of pre-existing routes that legitimately read empty result sets; those route fixes belong to Phase 41.
