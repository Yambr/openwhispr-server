# Phase 01.2 — CONTEXT

## Goal

Make `docker compose --profile db-only up --wait` succeed end-to-end: postgres healthy, pgbouncer healthy, migrate exits 0 with `migrate: ok`. Unblocks Phase 01.1 Plan 05 stack-up smoke at the database layer.

## Background

After Phase 02.1 fixed `apps/api/Dockerfile` (api/migrate images now build clean), the next blocker in the chain became postgres init failing on first volume init with `00-roles.sh: line 29: POSTGRES_OWNER_PASSWORD: parameter not set`.

## Locked Decisions

### D-01 — NO workarounds (project enterprise rule)
Apply real architectural fixes, NOT env-only patches that hide structural defects. Reject any "just hardcode credentials in compose" or "set blank passwords for now" suggestions.

### D-02 — Three real defects identified, fix all three atomically
1. `docker-compose.yml` postgres `environment:` block does NOT pass `POSTGRES_OWNER_PASSWORD` and `POSTGRES_APP_PASSWORD` through to the container — Postgres entrypoint only auto-exposes `POSTGRES_USER/PASSWORD/DB` to init scripts; everything else must be declared explicitly.
2. `tools/bootstrap.sh` treats every key in `.env.example` as a random secret to generate, including composite values like `DATABASE_URL=postgres://user:${POSTGRES_APP_PASSWORD}@host/db`. As a result, `DATABASE_URL` and `DATABASE_URL_OWNER` end up as opaque base64 tokens, NOT real connection strings. drizzle migrate then fails with `getaddrinfo ENOTFOUND` because the parsed URL has no hostname.
3. `packages/data/tsup.config.ts` overrides the default `.cjs` extension to `.js`. When the api Dockerfile (Phase 02.1 rewrite) shares a single `/app` between api and migrate services, the api's `package.json type: module` makes Node treat any sibling `.js` file as ESM — including `migrate.js`, which is actually CJS, causing `ReferenceError: require is not defined in ES module scope`.

### D-03 — Single-fix-per-phase boundary
Fix exactly the postgres+migrate runtime boot. Do NOT fix tempo (`unknown backend`), mimir (cluster-seed timing), grafana (depends on tempo), otel-collector (depends on tempo) — those are Phase 6 (observability) defects, separate scope.

### D-04 — API `pg` external (DEFERRED to next phase)
Running `docker compose --profile default up` after the 01.2 fixes uncovered that the `noExternal: [/^@openwhispr\//]` from Phase 02.1 ALSO inlines transitive `pg` via drizzle, which breaks the native pg driver in ESM. The api container restart-loops with a require/pg error inside `dist/index.js`. This needs `external: ['pg', 'pg-native']` in api tsup config — a Phase 02.2 follow-up, NOT 01.2.

## Constraints

- No workarounds; real structural fixes only
- Bash 4+ remains a hard requirement for bootstrap.sh (existing constraint)
- bootstrap.sh remains idempotent: re-running on an already-correct .env produces the same file byte-for-byte
- Composite values (`postgres://...${VAR}...`) are intentionally NOT operator-overridable; they always reflect the current secret values to keep rotation safe
