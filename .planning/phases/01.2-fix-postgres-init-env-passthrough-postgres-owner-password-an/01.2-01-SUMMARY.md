# Plan 01.2-01 — SUMMARY

## Outcome

Phase 01.2 succeeded. `docker compose --profile db-only up -d --wait` now exits 0 with postgres healthy, pgbouncer healthy, and migrate exit 0 logging `migrate: ok`. Three distinct enterprise-grade fixes landed; no workarounds.

## What was built

### Fix 1 — `docker-compose.yml` postgres env passthrough

Added `POSTGRES_OWNER_PASSWORD` and `POSTGRES_APP_PASSWORD` to the postgres service `environment:` block. The Postgres official image's `docker-entrypoint.sh` only auto-exposes `POSTGRES_USER`, `POSTGRES_PASSWORD`, and `POSTGRES_DB` to scripts under `/docker-entrypoint-initdb.d/`; anything else must be declared explicitly even if `env_file:` would otherwise inject it.

### Fix 2 — `tools/bootstrap.sh` composite-value interpolation

Added a pre-Phase-2 path in bootstrap.sh: when `.env.example` contains a value like `postgres://user:${POSTGRES_APP_PASSWORD}@host/db` (any value matching the `${KEY}` pattern), bootstrap interpolates `${KEY}` references against the already-built `RESULT` map instead of generating a random opaque token. Iteration order over `KEYS[]` mirrors `.env.example` order, so referenced secrets are always present in `RESULT` by the time the composite key is processed.

Composite values are intentionally NOT operator-overridable — they always reflect the current secret values, otherwise password rotation silently breaks downstream services.

Two composite keys benefit today: `DATABASE_URL` and `DATABASE_URL_OWNER`. The mechanism is general; future composite vars will work without code changes.

### Fix 3 — `packages/data/tsup.config.ts` use default `.cjs` extension

Removed the `outExtension: () => ({ js: ".js" })` override. The data migrate bundle is now `migrate.cjs`, matching its actual format. This eliminates the ESM/CJS conflict caused by the api container's `package.json type: module` shipping at `/app/package.json` and being inherited by `/app/packages/data/dist/migrate.*` for Node's module-type detection.

Updated callers:
- `docker-compose.yml` migrate `command: ["node", "/app/packages/data/dist/migrate.cjs"]`
- `apps/api/Dockerfile` comments
- `packages/data/src/migrate.ts` comment

No production code other than the build artifact name was affected.
