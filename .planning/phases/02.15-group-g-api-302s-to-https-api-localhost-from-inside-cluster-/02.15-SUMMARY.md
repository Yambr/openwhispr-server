# Phase 02.15: traefik network aliases + runner CA trust — Summary

Closes Group G (intra-cluster ECONNREFUSED on api 302 to its publicly-configured callback URL) surfaced by Phase 02.14: the in-network contract-test runner reached the api directly at `api:3000`, but any redirect chain that followed the api's published `OPENWHISPR_API_URL=https://api.localhost` hit `127.0.0.1:443` inside the container (host loopback ≠ cluster loopback) and ECONNREFUSEd. The fix routes `api.localhost` (and `auth.localhost`) through Docker's embedded DNS to traefik's container IP via network aliases, and the runner trusts the bootstrap-generated cert via `NODE_EXTRA_CA_CERTS`. The full Traefik+TLS+cert-SAN path is now exercised end-to-end, symmetric with what an operator's host-side browser sees.

## Defect → fix narrative

**Symptom (Phase 02.14 Group G, 3 failing oauth-redirect tests):** `oauth-redirect.test.ts` (openwhispr / openwhispr-dev / openwhispr-staging schemes) advanced past the Group E DNS gate (`getaddrinfo ENOTFOUND fixture-idp` was gone — that fix landed in 02.14) but the api 302'd back to its public callback `https://api.localhost/...` and the runner's `followToFinal` ECONNREFUSEd on `127.0.0.1:443`. Inside a container, `api.localhost` resolves to loopback, and port 443 is unbound on the container's loopback (Traefik publishes 443 on the **host**, not the container).

**Root cause:** `api.localhost` was unroutable from inside `openwhispr_internal`. The api correctly emits its publicly-configured callback URL (operators want the canonical-public one in 302s so browser-side OAuth completes correctly), but no in-cluster mechanism resolved that hostname to the traefik container.

**Fix (Option B network-alias variant per CONTEXT D-01):** Add `aliases: [api.localhost, auth.localhost]` under traefik's network attachment on `openwhispr_internal`. Docker's embedded DNS now resolves both hostnames to traefik's container IP for every service on the network. Symmetric with prod DNS resolution (operators set `/etc/hosts` on the host; we set it via Docker DNS inside the network). Bootstrap-generated cert SAN already covers both hostnames.

The runner now drives traffic through the canonical-public URL: `BACKEND_URL=AUTH_URL=https://api.localhost`. CA trust is established via `NODE_EXTRA_CA_CERTS=/certs/local.crt` with the cert mounted read-only at `/certs/local.crt` from `compose/traefik/certs/local.crt` (D-02a chosen — no image rebuild on cert rotation; preferred over baked-in CA for dev cadence). `AUTH_TRUSTED_ORIGINS_EXTRA` is dropped from the runner (its Origin is now the public AUTH_URL which Better Auth already trusts via the existing `trustedOrigins` resolution); kept on the api service for the seed flow which still posts directly to `api:3000` with that Origin.

**Group H (NEW)** — `oauth-redirect` HTTP 500 on api callback completion (3 tests). Group G's transport defect is fully closed (the runner reaches the callback via full Traefik+TLS+cert-SAN). The 500 is server-side: the api callback path now executes but errors out, most likely because the genericOAuth callback handler can't complete the token-exchange / session-creation cycle against fixture-idp's minimal `/token` response (the fixture returns a token shape that may not satisfy Better Auth's strictest validation, or the api's redirect-state-cookie roundtrip is breaking under the alias path). Phase 02.16+ candidate: capture the api error log under `LOG_LEVEL=debug` during the failing callback and either fix the api handler, fix the fixture, or both. **NOT** a regression — this defect was hidden behind ECONNREFUSED in 02.14 and has now surfaced one layer deeper, which is the executor protocol working as intended.
