### Tool choice (resolves Claude's Discretion)
**Use `docker buildx imagetools inspect <image>`** in `verify-images.sh`, not `docker manifest inspect`.

| Property | `docker manifest inspect` | `docker buildx imagetools inspect` |
|----------|--------------------------|-----------------------------------|
| Stability | Experimental (historical: required `DOCKER_CLI_EXPERIMENTAL=enabled`) [CITED: docs.docker.com/reference/cli/docker/manifest/inspect/] | Stable, GA [CITED: docs.docker.com/reference/cli/docker/buildx/imagetools/inspect/] |
| OCI-native (handles OCI manifest format) | Partial | Yes |
| Daemon required | Yes | **No** (queries registry directly when image is published; does not need a running daemon for remote inspect) [CITED: docs.docker.com/reference/cli/docker/buildx/imagetools/inspect/] |
| Multi-arch awareness | Manual `--verbose` parsing | Native (`--format '{{json .Manifest}}'` exposes platform list) |
| Pre-installed on `ubuntu-24.04` GHA runner | Yes | Yes |
| Pre-installed on Docker Desktop macOS | Yes | Yes |

**Note on D-05 wording:** CONTEXT.md says "run `docker manifest inspect`" but the same paragraph explicitly grants Claude's Discretion to substitute `docker buildx imagetools inspect`. Use the latter; document the choice in the script's header comment so reviewers understand the deviation.

### Parsing strategy (no `yq` dep)
```bash
# Extract all `image:` values from docker-compose.yml, ignoring commented lines.
# Handles both `image: foo:bar` and `image: "foo:bar"` (rare).
grep -E '^[[:space:]]*image:[[:space:]]+' docker-compose.yml \
  | sed -E 's/^[[:space:]]*image:[[:space:]]+["'"'"']?([^"'"'"' ]+)["'"'"']?[[:space:]]*$/\1/' \
  | grep -v '^#'
```

This avoids the `yq` dependency. `yq` IS pre-installed on `ubuntu-24.04` runners as of 2024+ but is NOT on stock macOS — the project favors zero-dep portability (CLAUDE.md mandates "boring, well-staffed").

### Multi-arch verification
Project constraint: amd64+arm64 [CLAUDE.md project tech stack table]. The verifier SHOULD assert manifest list contains both platforms:

```bash
output=$(docker buildx imagetools inspect "$image" --format '{{json .Manifest}}' 2>&1) || {
  echo "MISSING $image"
  exit_code=$((exit_code + 1))
  continue
}
# Parse manifests[].platform.architecture from the JSON. If both linux/amd64 and
# linux/arm64 are NOT present, print "ARCH-INCOMPLETE $image (missing: arm64)".
# This is non-fatal in v1 (warning only) — D-05 says exit code = number of MISSING.
```

**Recommend:** make ARCH-INCOMPLETE a WARNING (stderr, not fatal) in v1. All 11 currently-pinned images are known multi-arch (per Phase 1 RESEARCH-INFRA.md and the project tech-stack table in CLAUDE.md). If ARCH-INCOMPLETE ever fires it surfaces a real regression but doesn't block PRs that were passing before.

### Daemon-required question (resolves research focus item 7)
`docker buildx imagetools inspect` against a registry-published image **does not require a running Docker daemon** for the registry round-trip; it uses `~/.docker/config.json` for auth and HTTP only [CITED: docs.docker.com/reference/cli/docker/buildx/imagetools/inspect/]. This means `make verify-images` works on a dev machine without Docker Desktop running, which is operator-friendly. However, **`docker buildx` itself requires Docker CLI to be installed**. For local dev without Docker installed at all, the script will fail with a clean error — document this in the script header.

### Anti-patterns to avoid
- **Don't `docker pull` per image.** That downloads layers — slow, network-heavy, fills runner disk. Inspect-only is the right verb.
- **Don't use `yq`** for parsing — adds a hidden macOS dep where `grep`+`sed` works.
- **Don't put the verifier inside `ci.yml`'s existing jobs** — it should be its own workflow with `paths:` filter so it doesn't fire on every PR.
- **Don't catch only `MISSING` and skip the future-date check.** The MinIO defect was a *valid Docker Hub URL* with no manifest published — `docker buildx imagetools inspect` does return non-zero for that, but we should also lint the date suffix shape: any `RELEASE.YYYY-MM-DD...` with `YYYY-MM-DD > today` should be flagged before even calling Docker. This is cheap (a few lines of bash + `date`) and catches the same defect class without a network round-trip. **Recommend adding a `FUTURE-DATED <image>` exit class alongside `MISSING`.**

## Don't Hand-Roll

| Problem | Don't Build | Use Instead | Why |
|---------|-------------|-------------|-----|
| Registry manifest parsing | Custom HTTP client against Docker Hub registry API v2 | `docker buildx imagetools inspect --format '{{json .Manifest}}'` | Auth flow, OCI vs Docker manifest schemas, rate limits, retries — all handled by the CLI |
| YAML parsing of `docker-compose.yml` | Full YAML parser in bash | `grep -E '^\s*image:' \| sed` | We only need one field; YAML's full grammar is overkill |

## Common Pitfalls

### Pitfall 1: GHA runner Docker Hub rate limit
**What goes wrong:** Anonymous Docker Hub pulls/inspects from GHA-hosted runners share an IP-bucket rate limit (100 inspects per 6h per source IP for anonymous users in 2026). 11 images × every PR could exhaust this.
**Why it happens:** Many repos on the same shared GHA runner pool hit the same bucket.
**How to avoid:** (a) Cache the verifier result keyed on the SHA of `docker-compose.yml` so unchanged compose files skip the network round-trip; or (b) authenticate to Docker Hub with `DOCKER_HUB_USER` / `DOCKER_HUB_TOKEN` org secret if available, raising the limit to 5000/day. **Recommend (a) for v1** — simpler, no secret required, and the `paths:` filter already limits how often the job runs.
**Warning signs:** `toomanyrequests` error from `docker buildx imagetools inspect`.

### Pitfall 2: macOS Bash 3.2 incompatibility
**What goes wrong:** Using `declare -A` (associative arrays) or `mapfile` makes the script fail on stock macOS (Bash 3.2).
**Why it happens:** macOS won't ship GPL-3 Bash; system Bash is stuck at 3.2.
**How to avoid:** Stick to POSIX-ish bash. Use indexed arrays only. Use `while read` loops, not `mapfile`. Mirror `tools/bootstrap.sh` style.
**Warning signs:** Local `make verify-images` errors with `declare: -A: invalid option` on a dev macOS box.

### Pitfall 3: Floating tags vs immutable tags
**What goes wrong:** `traefik:v3.6` floats — today it points to v3.6.16, tomorrow it could be v3.6.17. Verifier passes today, but a deploy six months later picks up a different image silently.
**Why it happens:** Phase 1 chose minor-floating pins for some services (`traefik:v3.6`, `valkey/valkey:8.1-alpine`, `axllent/mailpit:v1.29`) and patch-pinned for others. Inconsistent.
**How to avoid:** This phase is NOT the place to fix it (D-03: don't chase versions; D-04: stay within major intent). DOCUMENT in the audit summary commit body that 5 of 11 pins are floating, and flag a future-phase task to standardize. **Do not change pins in this phase except to fix defects.**
**Warning signs:** Discussion of "should we tighten X to a patch pin" creeping into PR review.

### Pitfall 4: `docker buildx` returns 0 for an image that exists but has no manifest list
**What goes wrong:** Some old single-arch images return manifest schema v2 (not a list). The verifier should treat that as OK (image exists) but ARCH-INCOMPLETE (warning).
**How to avoid:** Inspect the JSON output for `mediaType` — if it's `application/vnd.docker.distribution.manifest.v2+json` (single arch), no `Manifests` list will be present; warn but don't fail.

### Pitfall 5: `set -e` swallows the loop's exit-code accumulation
**What goes wrong:** `for img in $images; do docker ... || exit_code=$((...)); done` — under `set -e` the `||` keeps the inner non-zero from terminating the script, but the final `exit $exit_code` at script end works as intended. Verify with a test fixture having 2 missing images that exit code is `2`, not `1`.
**How to avoid:** Use `set -uo pipefail` (drop the `-e`) for explicit error handling, or carefully use `|| true` chains. Mirror `tools/bootstrap.sh`'s pattern.

## Code Examples

### `scripts/verify-images.sh` skeleton
```bash
#!/usr/bin/env bash
# verify-images.sh — Phase 01.1.
#
# For each `image:` line in $COMPOSE_FILE (default: docker-compose.yml),
# query the upstream registry via `docker buildx imagetools inspect`.
# Print one line per image: `OK <image>` to stdout, `MISSING <image>` or
# `FUTURE-DATED <image>` to stderr. Exit code = count of failed images.
#
# Why `docker buildx imagetools inspect` not `docker manifest inspect`:
#   - GA stable, not experimental
#   - Daemon-optional for registry-only inspect
#   - Native multi-arch / OCI manifest support
# CONTEXT.md D-05 grants Claude's Discretion to choose either; we choose buildx.

set -uo pipefail

COMPOSE_FILE="${COMPOSE_FILE:-docker-compose.yml}"
TODAY="$(date -u +%Y-%m-%d)"

if ! command -v docker >/dev/null 2>&1; then
  echo "verify-images: docker CLI not found in PATH" >&2
  exit 127
fi

if [[ ! -f "$COMPOSE_FILE" ]]; then
  echo "verify-images: $COMPOSE_FILE not found" >&2
  exit 2
fi

mapfile_images() {
  grep -E '^[[:space:]]*image:[[:space:]]+' "$COMPOSE_FILE" \
    | sed -E 's/^[[:space:]]*image:[[:space:]]+["'"'"']?([^"'"'"' ]+)["'"'"']?[[:space:]]*$/\1/' \
    | grep -v '^#'
}

fail_count=0
while IFS= read -r image; do
  [[ -z "$image" ]] && continue

  # Cheap local check: future-dated RELEASE.YYYY-MM-DD... tags.
  if [[ "$image" =~ RELEASE\.([0-9]{4}-[0-9]{2}-[0-9]{2}) ]]; then
    tag_date="${BASH_REMATCH[1]}"
    if [[ "$tag_date" > "$TODAY" ]]; then
      echo "FUTURE-DATED $image (tag date $tag_date > today $TODAY)" >&2
      fail_count=$((fail_count + 1))
      continue
    fi
  fi

  # Network check.
  if docker buildx imagetools inspect "$image" >/dev/null 2>&1; then
    echo "OK $image"
  else
    echo "MISSING $image" >&2
    fail_count=$((fail_count + 1))
  fi
done < <(mapfile_images)

exit "$fail_count"
```

### `tests/self-tests/verify-images.test.ts` skeleton (mirror refuse-default-secrets.test.ts)
```typescript
import { execFileSync } from "node:child_process";
import { mkdtempSync, rmSync, writeFileSync } from "node:fs";
import { tmpdir } from "node:os";
import { join } from "node:path";
import { describe, expect, it } from "vitest";

const SCRIPT = join(process.cwd(), "scripts", "verify-images.sh");

function runVerify(composePath: string) {
  try {
    const stdout = execFileSync("bash", [SCRIPT], {
      encoding: "utf8",
      env: { ...process.env, COMPOSE_FILE: composePath },
      stdio: ["ignore", "pipe", "pipe"],
    });
    return { code: 0, stdout, stderr: "" };
  } catch (err) {
    const e = err as { status: number | null; stdout?: Buffer | string; stderr?: Buffer | string };
    return {
      code: e.status ?? 1,
      stdout: e.stdout?.toString() ?? "",
      stderr: e.stderr?.toString() ?? "",
    };
  }
}

describe("verify-images self-test", () => {
  it("exits non-zero with offending image in stderr when image is missing", () => {
    const dir = mkdtempSync(join(tmpdir(), "verify-images-"));
    const compose = join(dir, "docker-compose.yml");
    writeFileSync(
      compose,
      "services:\n  bad:\n    image: nonexistent/image-xyz:does-not-exist\n  good:\n    image: hello-world:latest\n",
    );
    try {
      const r = runVerify(compose);
      expect(r.code).toBeGreaterThan(0);
      expect(r.stderr).toMatch(/nonexistent\/image-xyz:does-not-exist/);
      expect(r.stdout).toMatch(/OK hello-world:latest/);
    } finally {
      rmSync(dir, { recursive: true, force: true });
    }
  }, 30_000);

  it("exits non-zero on a future-dated RELEASE tag without network call", () => {
    const dir = mkdtempSync(join(tmpdir(), "verify-images-"));
    const compose = join(dir, "docker-compose.yml");
    writeFileSync(
      compose,
      "services:\n  minio:\n    image: minio/minio:RELEASE.2099-01-01T00-00-00Z\n",
    );
    try {
      const r = runVerify(compose);
      expect(r.code).toBeGreaterThan(0);
      expect(r.stderr).toMatch(/FUTURE-DATED/);
      expect(r.stderr).toMatch(/RELEASE\.2099-01-01T00-00-00Z/);
    } finally {
      rmSync(dir, { recursive: true, force: true });
    }
  }, 10_000);
});
```
