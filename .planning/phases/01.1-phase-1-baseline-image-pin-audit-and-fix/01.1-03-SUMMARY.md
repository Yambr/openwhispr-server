# Phase 01.1 Plan 03: verify-images CI Workflow + Branch-Protection Wiring Summary

Path-filtered, time-bounded, SHA-pinned GitHub Actions workflow that runs `bash scripts/verify-images.sh` on every PR touching `docker-compose.yml` (or the verifier itself or this workflow), wired as a required check via `scripts/branch-protection.json` so it becomes a hard merge gate.

## What Was Built

- **`.github/workflows/verify-images.yml`** — new workflow. Triggers on PRs and pushes to `main` only when one of `docker-compose.yml`, `scripts/verify-images.sh`, or `.github/workflows/verify-images.yml` changes. Single job `verify-images` on `ubuntu-24.04` with `timeout-minutes: 5`, hardened runner (audit egress), SHA-pinned `actions/checkout@v5`, runs `bash scripts/verify-images.sh`.
- **`scripts/branch-protection.json`** — appended `"verify-images"` to `required_status_checks.contexts` (was 14 entries, now 15). All other fields preserved.

## How It Satisfies SC-03

| Requirement Facet | Mechanism |
|-------------------|-----------|
| Recurrence guard against bad image pins (D-07) | Workflow file exists and runs the verifier on every compose-file change. |
| Required-check wiring | branch-protection.json now lists `verify-images`; the GitHub API consumer (`scripts/setup-branch-protection.sh`) will enforce it. |
| Self-validating link | Existing `tests/self-tests/branch-protection-contexts.test.ts` walks workflows for `jobs.<name>:` keys and asserts every required context maps to a real job — this stays green because the new job key matches the new context name byte-for-byte. |
| Supply-chain (T-01.1-03) | Third-party actions SHA-pinned with version-tag comments. |
| DoS bounds (T-01.1-02) | `paths:` trigger filter + `timeout-minutes: 5` + `permissions: contents: read`. |
