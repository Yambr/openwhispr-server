<decisions>
## Implementation Decisions

### Audit scope
- **D-01:** Full audit. For every `image:` line in `docker-compose.yml`, verify (1) the tag exists on its upstream registry and (2) any date-shaped portion of the tag is `<=` today (2026-05-09). Fix every defect found, not just MinIO. Same root-cause class (a planner/agent inventing future-dated pins) likely affected sibling pins.

### Replacement pin policy
- **D-02:** When a pin is bad, replace it with the **latest stable tag currently published** on the registry as of execution date. "Stable" means non-prerelease, non-`master`, non-`latest`, non-RC. For MinIO this is the most recent `RELEASE.YYYY-MM-DDTHH-MM-SSZ` tag. Keeps the baseline current and avoids pinning to a tag that is about to be EOL.
- **D-03:** Do NOT change a pin that already verifies clean, even if a newer tag exists. Audit fixes defects; it does not chase versions.
- **D-04:** Honor Phase 1 CONTEXT.md `<decisions>` D-02 intent (e.g., `valkey/valkey:8-...`, `traefik:v3.x`, `postgres:17-...`) — the chosen replacement must stay within the same major-version intent line. If the latest stable would cross the major intent (e.g., MinIO removes the date scheme, Postgres jumps to 18), STOP and surface to the user; do not silently bump.

### Recurrence guard
- **D-05:** Add `scripts/verify-images.sh` (Bash; portable across Linux + macOS + GHA Ubuntu runner). For each `image:` line in `docker-compose.yml` run `docker manifest inspect <image>` and exit non-zero if any inspect fails. Print one line per image: `OK <image>` or `MISSING <image>`. Exit code = number of missing images.
- **D-06:** Add `make verify-images` target that calls the script. Add a self-test under `tests/self-tests/` that asserts the script exits non-zero when fed a synthetic `docker-compose.yml` containing `nonexistent/image:does-not-exist`.
- **D-07:** Add a GitHub Actions job `verify-images` in `.github/workflows/` that runs on every PR touching `docker-compose.yml` (path filter). Required check via branch protection — same model as the existing `contract-test` job.

### Re-verification
- **D-08:** Both proofs are required:
  - **(a) Local stack smoke:** `docker compose --profile default up --wait` against the real upstream registry — every service must reach `healthy`. Tear down with `docker compose down -v` after.
  - **(b) Phase 2 contract-test re-run:** Re-execute `make contract-test` (the item recorded as blocked in `02-HUMAN-UAT.md`). On pass, update that UAT entry inline: `result: passed` + add a note linking to this phase's commit.
- **D-09:** Both proofs are part of this phase's success criteria, not deferred. Phase 01.1 is not done until both pass.

### Commit hygiene
- **D-10:** Pin fixes land as a single atomic commit (`fix(01.1): correct future-dated/missing image pins`) with the audit summary in the commit body listing every audited image and its before/after state. The verifier script + CI job land as separate commits per the project's TDD convention (RED test commit, then GREEN implementation).

### Claude's Discretion
- The exact set of `make` target wiring (e.g., reusing existing `Makefile` patterns) — Claude picks based on what's already in `Makefile`.
- Output format of `verify-images.sh` beyond the per-image OK/MISSING line + exit code (colorization, JSON mode for CI parsing, etc.) — Claude picks; nothing downstream depends on it.
- Whether to use `docker manifest inspect` or `docker buildx imagetools inspect` (latter handles OCI better) — Claude picks; both satisfy D-05.

</decisions>
