# Phase 02.16: mintBearer OIDC discovery — Summary

Closes Group H (3× `oauth-redirect` HTTP 500 surfaced when Phase 02.15 closed Group G transport). Diagnose-first revealed `mintBearer`'s fail-fast env validation throws `OIDC_TOKEN_URL is not configured` before any IdP call. Fix performs OIDC discovery (`${OIDC_ISSUER_URL}/.well-known/openid-configuration`) when explicit endpoint env overrides are unset, matching Better Auth genericOAuth's lazy-discovery contract and removing the multi-env-var setup burden from real-world operators.

## Defect → fix narrative

**Symptom (Phase 02.15 Group H, 3 failing oauth-redirect tests):** With Group G transport closed, the runner reaches `https://api.localhost/api/auth/desktop-callback/oidc?code=fixture&state=<uuid>` over the full Traefik+TLS path. The api returns 500 with the catch-all envelope `{"error":"Internal server error"}`. No request log emerged because Fastify is initialized with `logger: false` (`apps/api/src/index.ts:109`) and `setErrorHandler`'s `req.log.warn` silently no-ops.

**Diagnosis (Class b per CONTEXT D-02 — committed in `c299350`):** Captured the wire trace via in-network busybox-wget against `contract-test-runner` and introspected the running api container's env:

```
$ docker compose exec -T api env | grep ^OIDC_
OIDC_CLIENT_ID=conformance-test-client
OIDC_CLIENT_SECRET=conformance-test-secret-do-not-use-in-prod
OIDC_ISSUER_URL=http://fixture-idp:9000
```

`OIDC_TOKEN_URL` and `OIDC_USERINFO_URL` are not set. Code-path tracing confirmed:

1. `desktop-signin.ts` succeeds (it only requires ISSUER + CLIENT_ID + CLIENT_SECRET + AUTH_URL).
2. fixture-idp `/authorize` 302's straight back to the api callback URL with `code=fixture` and the echoed state.
3. `auth-callback.ts` CAS-consumes the `oauth_state` row successfully (verified by retrying the same state in a follow-up call which returns 400 "state already consumed" — proves CAS happened).
4. `auth-callback.ts:224` calls `await mintBearer({...})`.
5. `mint-bearer.ts:116` (pre-fix) calls `requireEnv("OIDC_TOKEN_URL")` → synchronously throws `mint bearer: OIDC_TOKEN_URL is not configured`.
6. The throw propagates up through the `await`, Fastify catches it, the centralized `setErrorHandler` falls through to the catch-all branch (no `instanceof` match), maps to `status=500, message="Internal server error"`, replies with the envelope.

The wire trace matches the code path 1:1.

**Fix shape rejected (Option 1 — `OIDC_TOKEN_URL` + `OIDC_USERINFO_URL` env vars in docker-compose):** Mechanically correct, architecturally wrong. It would mask an upstream `mintBearer` defect and force real-world operators to configure THREE env vars instead of ONE for what the OIDC spec considers a discoverable property. Rejected per CLAUDE.md no-workarounds rule.

**Fix shape chosen (Option 2 — OIDC discovery in mintBearer):** When `OIDC_TOKEN_URL` / `OIDC_USERINFO_URL` are unset, `mintBearer` fetches `${OIDC_ISSUER_URL}/.well-known/openid-configuration` once and derives `token_endpoint` + `userinfo_endpoint` from it. The doc is cached for process lifetime (OIDC issuers consider discovery stable per OIDC Discovery 1.0 §4). Explicit env overrides still win — kept for non-conforming IdPs without discovery docs, matching the existing `OIDC_AUTHORIZE_URL` override pattern in `desktop-signin.ts:147–148`.

This:
- Closes Group H against fixture-idp (which serves a fully-formed discovery doc — `tests/fixtures/idp/server.mjs:54–67`).
- Aligns `mintBearer` with Better Auth genericOAuth's lazy-discovery contract (already documented in `auth.ts:89–90`).
- Removes the multi-env-var setup burden from real-world operators.
- Preserves operator overrides for the rare non-conforming IdP.

## TDD evidence (apps/api/src/lib/mint-bearer-discovery.test.ts)

4 assertions, all using `vi.stubGlobal("fetch", ...)` against the `MintBearerArgs` contract:

1. **Test 1** — When `OIDC_TOKEN_URL` is unset, `mintBearer` fetches the discovery doc and POSTs to its `token_endpoint`.
2. **Test 2** — Same for `userinfo_endpoint`.
3. **Test 3** — When the explicit env overrides ARE set, no discovery fetch happens (operator-overrides bypass the roundtrip).
4. **Test 4** — Discovery doc non-2xx surfaces as `Error: mint bearer: discovery <status> (issuer=<issuer>)`; the IdP response body is NEVER included (T-02.7-07 — body may leak PII or attacker-controlled values).

**Pre-fix:** 3 RED, 1 PASS (Test 3 trivially passed because explicit env vars satisfy the old `requireEnv` path).
**Post-fix:** 4/4 GREEN.
**Reverse-patch evidence:** Restoring `requireEnv("OIDC_TOKEN_URL")` in `mint-bearer.ts:116` (or removing the `discoverOidc` helper) returns Tests 1, 2, 4 to RED with `mint bearer: OIDC_TOKEN_URL is not configured`.

Existing `mint-bearer.test.ts` (9 tests covering the explicit-endpoint path) **all still GREEN** — the new discovery branch is purely additive and only activates when the explicit env vars are unset.
