# Phase 02.16 — DIAGNOSIS

## Reproduction

Stack brought up via `make clean-stack` → `tools/bootstrap.sh` → `pnpm build` → `docker compose --profile default --profile contract-test up -d --wait` → seed (5/5 OK).

Manual chain (in-network, via `contract-test-runner` busybox-wget against canonical-public TLS path):

```
GET https://api.localhost/api/desktop-signin/oidc?callbackURL=openwhispr%3A%2F%2Fcallback&protocol=openwhispr
  → 302 Location: http://fixture-idp:9000/authorize?…&state=<uuid>&code_challenge=…
```

## Why this is `enterprise-grade-fix`-not-`workaround` shaped

Two surgical options exist; I picked the architecturally correct one.

### Option 1 — Add `OIDC_TOKEN_URL` + `OIDC_USERINFO_URL` env vars to docker-compose

**Mechanically correct, architecturally wrong.** mintBearer's contract is "give me an OIDC issuer URL, I do the rest" — that's the standard OIDC pattern (RFC 8414 / OIDC Discovery 1.0). Real-world operators should configure ONE env var (`OIDC_ISSUER_URL`) and have the server discover token/userinfo/jwks endpoints via `${ISSUER}/.well-known/openid-configuration`. Forcing operators to set THREE env vars instead of one is a regression vs the Better Auth genericOAuth contract (which uses lazy discovery — `auth.ts:89–90` already documents this).

The fixture-idp already serves a fully-formed discovery doc (`tests/fixtures/idp/server.mjs:54–67`). It's a CORRECTNESS bug in mintBearer that it doesn't use it.

### Option 2 — mintBearer derives endpoints from OIDC discovery, falls back to env overrides ✓

mintBearer should:
1. Read `OIDC_ISSUER_URL` (already required by readOidcEnv at signin-time, so by the time the callback fires we know it's set).
2. If `OIDC_TOKEN_URL` is unset, fetch `${ISSUER}/.well-known/openid-configuration` once and derive `token_endpoint` from it.
3. Same for `userinfo_endpoint`.
4. Cache the discovery doc in-memory (process-lifetime cache; refresh on miss only). OIDC issuers consider discovery stable; cache invalidation is a non-issue for our scale.
5. Keep the explicit `OIDC_TOKEN_URL` / `OIDC_USERINFO_URL` env overrides for the rare non-standard IdP (matches Plan 05's existing `OIDC_AUTHORIZE_URL` override pattern at `desktop-signin.ts:147–148`).

This:
- Closes Group H against fixture-idp (discovery doc present).
- Aligns mintBearer with Better Auth genericOAuth's lazy-discovery contract.
- Removes the multi-env-var setup burden from real-world operators.
- Preserves operator overrides for non-conforming IdPs.
- No Workaround. No Mock. No Suppress. Per CLAUDE.md.
