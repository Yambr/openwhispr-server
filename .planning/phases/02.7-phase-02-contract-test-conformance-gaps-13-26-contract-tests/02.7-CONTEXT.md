## Implementation Decisions

### D-01 — OAuth channel-scheme: complete the side-route (NOT Better Auth onSuccess hook)

Wire `mintBearer` adapter at the existing `apps/api/src/routes/auth-callback.ts` `desktop-callback/:provider` route. After IdP redirects with `code`, route:
1. CAS-consumes the `oauth_state` row (already implemented per Plan 05)
2. Exchanges `code` for IdP tokens via `better-fetch` to the IdP token endpoint (PKCE verifier from oauth_state)
3. Upserts user via Better Auth's internal helpers OR direct drizzle (preserve tenant binding)
4. Mints opaque bearer via `auth.api.*` so the Bearer plugin's `set-auth-token` rotation header still fires
5. Calls existing `buildProtocolRedirect(scheme, bearerToken)` → returns 302 `Location: <scheme>://?bearer_token=...`

**Why NOT Better Auth's `genericOAuth({onSuccess})`:** Empirical confirmation in `auth-callback.ts:1-9` against installed `better-auth@1.6.9` — `genericOAuth` exposes only `getUserInfo` and `mapProfileToUser`; no per-request `onSuccess` redirect-rewrite hook exists. `customTokenResponseFields` belongs to the unrelated `oauth-provider` plugin (us as IdP, not OAuth client). The "2026 idiomatic path" tech-stack note was a category error — retire that misconception.

**Why NOT a Fastify onSend post-handler hook:** Couples to Better Auth's stock callback URL shape across minor versions; produces header-grovel that fails the project's no-workarounds rule.

Channel-scheme allowlist enforcement (already shipped in Plan 05):
- Validated at sign-in entry (`desktop-signin.ts:107-119`) — rejects `javascript:` etc with 400 + canonical envelope
- Re-validated implicitly at callback because `scheme` is read from the server-side `oauth_state` row, never query param → no open-redirect vector
- `OPENWHISPR_PROTOCOL` env override (`scheme-allowlist.ts:74-77`) is the operator-override surface

### D-02 — Bearer-invalid envelope: hybrid (dual-auth-hook try/catch + setErrorHandler APIError recognizer)

The current 500 leak originates from `auth.api.getSession({headers})` THROWING on a malformed bearer (Better Auth's bearer plugin raises `APIError` for token shapes failing pre-validation) rather than returning `null`. The exception propagates past `dualAuthHook` straight into `setErrorHandler`'s default 500 branch.

Two-layer fix:

1. **`apps/api/src/middleware/dual-auth.ts`** — wrap `auth.api.getSession({headers})` in try/catch:
   - On thrown `APIError` with `status` in [400, 401, 403] → fall through to existing `throw new AuthError("unauthorized")` path (single emission point preserved)
   - On thrown error WITHOUT a `status` field OR with `status >= 500` → re-throw (infra errors stay 503/500, never silently 401'd)

2. **`apps/api/src/error-handler.ts`** — add Better Auth `APIError` recognizer branch BEFORE the default 500:
   - `import { APIError } from "better-auth/api"` (or equivalent path; verify in plan)
   - If `err instanceof APIError`: map status 401/403 → `AuthError` envelope; status 400 → `ValidationError` envelope; else default
   - Covers `/api/auth/*` plugin routes (sign-in, verify-email, sign-out) when their own validations throw — same envelope as dual-auth-hook

Existing `conventions.test.ts` parametric loop (per advisor 2 rationale) auto-enforces conformance going forward — adding new authenticated routes to `AUTH_REQUIRED` list mechanically picks up envelope coverage.

### D-03 — check-user: A+B layered (seed lifecycle fix + email lowercase normalization)

**Root cause is operational, not architectural** — the route + RLS + tenant binding are all correct. `packages/data/src/seed/conformance.ts` `signUp()` helper treats ANY 4xx (400/409/422) from `/api/auth/sign-up/email` as "already exists" and returns `{created: false}` silently. If the contract-test DB was reset without re-seeding, OR if signup is failing for an unrelated reason (rate limit, CSRF, email-verification policy), the row never lands and `check-user` correctly returns `{exists: false}`.

**Layer A — seed lifecycle fix:**
- Tighten `signUp()` to inspect response body and distinguish "already exists" (idempotent OK) from "validation/CSRF/server error" (loud fail)
- Gate the contract-test job on a seed-completion signal in compose (seed exit code already gates per Phase 02.3; verify behavior under failure)
- Add a one-shot preflight at the top of the suite: `SELECT count(*) FROM users WHERE email='fixture@conformance.test'` — fail fast with diagnostic message if 0

**Layer B — email lowercase normalization (defense-in-depth, citizen-grade hygiene):**
- New migration `0004_email_lowercase_normalize.sql` (atomic, separate file per the user's "clearer rollback story" preference): `CREATE UNIQUE INDEX users_email_lower_unique ON users (lower(email))` (replacing the existing case-sensitive unique index inside the same migration)
- Update the check-user route to query via `lower(email) = lower($1)` (or rely on the new functional index)
- Update Better Auth signup to lowercase email at write — Better Auth typically does this by default; verify and either rely on it or add an explicit hook
- Backfill existing rows: `UPDATE users SET email = lower(email)` (idempotent; wrapped in DO block guarding against case-collision dupes — fail loud if any)

Defer Options C (separate `openwhispr_owner` BYPASS RLS pool for public lookups) and D (per-request role-switch) to v2 multi-tenant — unjustified privilege expansion in v1 single-tenant.

### D-04 — signInFixture 404: collapse AUTH_URL default (Option C — collapse default but keep var as override)

**Root cause** (verified by advisor 4): `packages/contract-tests/src/env.ts` defaults `AUTH_URL=http://auth.localhost`, but Traefik's `dynamic.yml` has NO router for `auth.localhost` — only `api.localhost`, `grafana.localhost`, `minio-console.localhost`, `mailpit.localhost`, plus `*.example.test` split-host fixtures. Signup "works" because the seed container overrides `AUTH_URL=http://api:3000` (internal DNS, bypasses Traefik); host-side test runner hits the env-default and 404s at Traefik before Fastify sees it.

**Fix:** `packages/contract-tests/src/env.ts` — change `AUTH_URL` default from `http://auth.localhost` to mirror `BACKEND_URL` (which after D-05 becomes `https://api.localhost`). Keep `AUTH_URL` as a separate env override for cookie-domain conformance tests that legitimately need split-host topology via `*.example.test`.

No Traefik changes; no /etc/hosts changes; no cert SAN additions.

### D-05 — Makefile/cert: bake `https://` + NODE_EXTRA_CA_CERTS + add cert generation to bootstrap.sh

**Critical compound finding** (advisor 5): `compose/traefik/dynamic.yml:4` and `compose/traefik/certs/.gitkeep` BOTH document that `bootstrap.sh` writes `local.crt`/`local.key` — but inspection shows `bootstrap.sh` has ZERO cert-generation logic. Traefik is silently falling back to its built-in `TRAEFIK DEFAULT CERTIFICATE`, which is precisely why Phase 02.6 reached for `NODE_TLS_REJECT_UNAUTHORIZED=0` as a workaround.

Fixing this collapses two defects:

1. **`tools/bootstrap.sh`** — add openssl SAN-cert generation block:
   - SANs: `*.localhost`, `localhost`, `auth.example.test`, `api.example.test` (covers all Traefik vhosts including the split-host cookie test)
   - 10-year validity (`-days 3650`)
   - Output to `compose/traefik/certs/local.crt` + `local.key`
   - Idempotent: skip if files exist AND not expired
   - openssl-only path (NO mkcert dep — keeps bootstrap install-free per "boring" project rule)

2. **`Makefile`** line 80 — change to:
   ```make
   BACKEND_URL=https://api.localhost AUTH_URL=https://api.localhost \
     NODE_EXTRA_CA_CERTS=$(PWD)/compose/traefik/certs/local.crt \
     pnpm -F @openwhispr/contract-tests test
   ```
   (After D-04, AUTH_URL collapses to api.localhost.)

3. **`packages/contract-tests/src/env.ts`** — `probeBackend()` adds `redirect: 'error'` so an http→https redirect surfaces as a loud probe failure rather than the current silent `308 → not ok → skip-all-25` cascade.

4. **`Makefile` `contract-test-deployed` target** — add a refuse-on-NODE_TLS_REJECT_UNAUTHORIZED=0 guard at the top:
   ```make
   @test "$$NODE_TLS_REJECT_UNAUTHORIZED" != "0" || (echo "refusing to run with TLS verification disabled" && exit 1)
   ```
   Mechanical no-insecure-tls-in-prod-paths enforcement.

NO `NODE_TLS_REJECT_UNAUTHORIZED=0` anywhere in the codebase. End-to-end HTTPS-only honored.
