## Objective

Land Wave 1 infra for Phase 02.7: the openssl SAN cert generation that `compose/traefik/dynamic.yml` and `compose/traefik/certs/.gitkeep` document but `tools/bootstrap.sh` never implemented (root cause for the Phase 02.6 NODE_TLS_REJECT_UNAUTHORIZED=0 reach), plus the env.ts and Makefile touches that close D-04 (AUTH_URL 404) and the D-05 probe-loud-fail surface. ## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 3 - Blocking] Coverage measurement required exclude override**
- **Found during:** Task 2 verification (per-file coverage on env.ts)
- **Issue:** `pnpm vitest --coverage --coverage.include='packages/contract-tests/src/env.ts'` reported 0/0 because the root `vitest.config.ts` excludes `tests/**` (which is correct for tests as covered files) AND the include/exclude intersection produced an empty set when the test runner is in `tests/unit/`.
- **Fix:** Add `--coverage.exclude='[]'` to override the root exclusion list when measuring env.ts via the unit test. Documented in SUMMARY for downstream plans.
- **Files modified:** none (config flag only)
- **Commit:** N/A (process change)

**2. [Rule 3 - Blocking] Vite dynamic import limitation**
- **Found during:** Task 2 (writing module-isolation tests for `BACKEND_URL_EXPLICIT` branch coverage)
- **Issue:** Vite rejects template-literal dynamic imports with cache-bust query strings (`Unknown variable dynamic import`). Initial version used `?explicit=${Date.now()}` for re-import freshness.
- **Fix:** Switch to plain string dynamic imports (`await import("../../packages/contract-tests/src/env.ts")`). `vi.resetModules()` invalidates the import cache between tests, so re-import re-evaluates module-load-time constants under the mutated env.
- **Files modified:** tests/unit/probe-backend-redirect-error.test.ts
- **Commit:** `8f59b10`

**3. [Rule 1 - Bug] Plan acceptance grep is literal contradiction**
- **Found during:** Task 2 verification step (`! grep -q "NODE_TLS_REJECT_UNAUTHORIZED=0" Makefile tools/bootstrap.sh packages/contract-tests/src/env.ts`)
- **Issue:** The plan REQUIRES the refuse-on-=0 guard in `contract-test-deployed` (which by definition contains the literal `NODE_TLS_REJECT_UNAUTHORIZED=0` to refuse on it), AND it asserts the literal must be absent. Mutual contradiction.

No actual NODE_TLS bypass anywhere in the codebase.
