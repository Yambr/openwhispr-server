# Phase 02.7 Plan 03: D-02 Hybrid Bearer-Invalid Envelope Summary

**Hybrid two-layer fix for the bearer-invalid 500 leak: dual-auth hook try/catch swallows Better Auth APIError 4xx and re-throws 5xx, setErrorHandler APIError recognizer branch maps direct `/api/auth/*` plugin throws to canonical envelope without leaking err.message.**

## Accomplishments

- **A1 verification probe** (Task 1) confirmed Better Auth v1.6.9 APIError exposes `.status` as STRING-NAME ("UNAUTHORIZED") with `.statusCode` as the numeric (401). Helper handles BOTH defensively.
- **Layer 1 (dual-auth.ts)**: getSession is now wrapped in try/catch. 4xx APIError → null fall-through to existing `AuthError("unauthorized")` emission; 5xx APIError + non-APIError → re-throw with original cause preserved.
- **Layer 2 (error-handler.ts)**: new `instanceof APIError` recognizer branch maps 401/403 → "Session expired", 400 → "Invalid request", 5xx → "Internal server error", other-4xx → "Request failed". Never emits err.message.
- **Helper (api-error-status.ts)**: single `resolveApiErrorStatus(err)` source-of-truth for both layers; STATUS_MAP covers 12 standard HTTP statuses; unknown → 500 safe-default (mitigates T-02.7-11 status-name spoofing).
- **26 new tests** (6 dual-auth + 6 error-handler + 14 helper) all GREEN.
- **No regression** in 224 pre-existing apps/api tests (excluding the unrelated D-03A seed-signup file already in working tree from a different plan).

## Decisions Made

See key-decisions in frontmatter. Highlights:

- **Two-layer split is intentional, not redundancy.** Layer 1 handles dualAuthHook-protected routes (the 13/26 contract test surface for bearer-invalid). Layer 2 handles `/api/auth/*` plugin routes that opt out of dualAuthHook (`auth=false`) and throw APIError directly during sign-in/verify-email/sign-out. Without Layer 2, those routes would still 500 on plugin-side validation throws.
- **5xx re-throw preserves infra-error semantics.** The CONTEXT explicitly calls out "do NOT silently 401 a database outage". Test 4 in dual-auth-hook-bad-bearer.test.ts pins this as a regression guard.
- **Defensive A1 numeric branch** is dead code under v1.6.9 BUT future-proofs against Better Auth aligning `.status` with `.statusCode` in any future minor. Cost: ~3 lines + 2 tests; benefit: zero rework when the bump happens.
