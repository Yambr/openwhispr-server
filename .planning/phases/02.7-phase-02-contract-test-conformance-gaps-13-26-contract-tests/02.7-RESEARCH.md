**Critical correction to CONTEXT.md framing**: CONTEXT D-01 says "Only `mintBearer` adapter is missing." Inspection shows `apps/api/src/lib/mint-bearer.ts` already exists (Plan 08). The defect is that this stub delegates to `auth.handler('/api/auth/oauth2/callback/oidc?code=&state=')`, but Better Auth's `callbackOAuth` route reads PKCE state from its OWN `verification` table via `parseState(c)` — NOT from our `oauth_state` table. Since `desktop-signin.ts` writes to `oauth_state` (not Better Auth's `verification`), the callback always 400s with `state_not_found`. The real fix is to **rewrite mint-bearer.ts** to bypass Better Auth's callback entirely: token-exchange via direct fetch, then `internalAdapter.findUserByEmail` + `createOAuthUser` + `createSession`, returning the raw `session.token` as the bearer. The bearer plugin's `before` hook accepts unsigned 32-char tokens (verified in `bearer/index.mjs:32-37` — when `!token.includes(".")`, it self-signs via `serializeSignedCookie`).

**Primary recommendation:** Plan tree below — five waves runnable in two passes (Wave 1: D-04 + D-05 cert-gen; Wave 2: D-01 + D-02 + D-03 in parallel after D-05 lands).

### D-01 OAuth channel-scheme: real `mintBearer` adapter

**The defect (verified):** `apps/api/src/lib/mint-bearer.ts:54-96` invokes `auth.handler` against `/api/auth/oauth2/callback/${provider}`. Better Auth's `callbackOAuth` (`node_modules/better-auth/dist/api/routes/callback.mjs:58`) calls `parseState(c)` which reads from Better Auth's internal `verification` table. Our `desktop-signin.ts:128-139` writes to `oauth_state` (a different table). Therefore the existing stub ALWAYS fails with `state_not_found`.

**The fix path** (per CONTEXT D-01 step 2-4 + Specific-Ideas note):

```ts
//    - createUser(user):                Promise<User>  // lowercases email automatically (line 62)
//    - createAccount(account):          Promise<Account>
//    - linkAccount(account):            Promise<Account>                    // line 470
//    - createSession(userId, dontRememberMe?, override?, overrideAll?):     // line 141
//        Promise<Session>  // returns row with .token = generateId(32) raw 32-char string
```

#### Bearer plugin token format (verified: `dist/plugins/bearer/index.mjs:32-37`)

```js
// before hook accepts EITHER:
//   * Signed cookie value containing "." → uses as-is (HMAC-verified split on ".")
//   * Raw 32-char token without "." → self-signs via serializeSignedCookie:
if (!token.includes(".")) {
  if (options?.requireSignature) return;       // we do NOT set requireSignature
  signedToken = (await serializeSignedCookie("", token, c.context.secret)).replace("=", "");
}
```

→ **Returning `session.token` (raw 32-char) directly works.** The bearer plugin will self-sign on subsequent requests.

#### Bearer rotation semantics (`set-auth-token` header)

Verified `dist/plugins/bearer/index.mjs:60-77`: the `after` hook reads `Set-Cookie` from the response and writes the cookie's value as `set-auth-token`. This fires on ANY auth-mutating Better Auth route response. Our `/api/auth/desktop-callback/:provider` route returns a 302 redirect (NOT a Better Auth route), so `set-auth-token` is NOT emitted on the OAuth-completion response. **This is correct**: AUTH-02 contract is `Location: <scheme>://?bearer_token=<urlencoded>` — the desktop pulls the token from the URL. AUTH-03 (`set-auth-token` rotation) fires later on subsequent `/api/auth/*` calls when the session is extended/rotated.

`@better-fetch/fetch` is bundled inside `better-auth` (`node_modules/.pnpm/.../better-auth/...`). It is NOT a direct dep of `@openwhispr/api`. Two viable options:

**Recommended (plain fetch):**

```ts

//   → token_endpoint, userinfo_endpoint
// (operator can override via OIDC_TOKEN_URL / OIDC_USERINFO_URL env to skip discovery)

const tokenRes = await fetch(tokenEndpoint, {
  method: "POST",
  headers: { "content-type": "application/x-www-form-urlencoded" },
  body: new URLSearchParams({
    grant_type: "authorization_code",
    code: args.code,
    redirect_uri: `${process.env.AUTH_URL}/api/auth/desktop-callback/${args.provider}`,
    client_id: process.env.OIDC_CLIENT_ID!,
    client_secret: process.env.OIDC_CLIENT_SECRET!,
    code_verifier: args.codeVerifier,
  }),
});
if (!tokenRes.ok) throw new Error(`mint bearer: token exchange ${tokenRes.status}`);
const tokens = (await tokenRes.json()) as { access_token: string; id_token?: string };

// Fetch userinfo
const uiRes = await fetch(userinfoEndpoint, {
  headers: { authorization: `Bearer ${tokens.access_token}` },
});
const profile = (await uiRes.json()) as { sub: string; email: string; name?: string; picture?: string };

// Find or create the user under default tenant (tenant binding is automatic
// via ALTER ROLE … SET app.tenant_id from migration 0003 + column DEFAULT).
const ctx = await auth.$context;
const existing = await ctx.internalAdapter.findUserByEmail(profile.email.toLowerCase());
let userId: string;
if (existing) {
  userId = existing.user.id;
  // (Optional) Link account row if not present for this provider.
} else {
  const created = await ctx.internalAdapter.createOAuthUser(
    {
      email: profile.email.toLowerCase(),
      name: profile.name ?? profile.email,
      emailVerified: true,
      image: profile.picture ?? null,
    },
    {
      providerId: args.provider,
      accountId: profile.sub,
      accessToken: tokens.access_token,
      idToken: tokens.id_token ?? null,
      scope: "openid email profile",
    },
  );
  userId = created.user.id;
}

const session = await ctx.internalAdapter.createSession(userId, false);
return session.token; // raw 32-char string; bearer plugin self-signs on receive
```

Better Auth's adapter writes go through `openwhispr_app` (the connection role) → `tenant_id` column DEFAULT resolves to default tenant via `current_setting('app.tenant_id', true)::uuid`. **No `withTenant()` wrapper needed for the internal-adapter calls** — the GUC is already bound at the role level.

This treats ALL of {400, 409, 422} as "already exists." Better Auth signup conflicts return HTTP 422 with body `{message: "User with this email already exists", code: "USER_ALREADY_EXISTS"}`. Distinguish:

```ts
async function signUp(authUrl: string, user: FixtureUser): Promise<{ created: boolean }> {
  const baseUrl = authUrl.replace(/\/+$/, "");
  const url = `${baseUrl}/api/auth/sign-up/email`;
  const res = await fetch(url, { /* … existing … */ });
  if (res.ok) return { created: true };
  const text = await res.text();
  // Distinguish "already exists" from any other 4xx.
  // Better Auth's USER_ALREADY_EXISTS code is the canonical idempotent signal.
  let parsed: { code?: string; message?: string } = {};
  try { parsed = JSON.parse(text) as typeof parsed; } catch { /* non-JSON body */ }
  const isDuplicate =
    parsed.code === "USER_ALREADY_EXISTS" ||
    /already exists/i.test(parsed.message ?? "");
  if (isDuplicate) return { created: false };

  throw new Error(
    `seed: signUp(${user.email}) failed: HTTP ${res.status} body=${text.slice(0, 300)}`,
  );
}
```

**Migration SQL (exact statement order):**

```sql
-- packages/data/migrations/0004_email_lowercase_normalize.sql
-- Phase 02.7 / D-03 Layer B — case-insensitive email uniqueness.
-- Hand-authored (drizzle-kit cannot emit functional indexes for our schema DSL).
--
-- Migration ordering rationale (per CONTEXT D-03 Specific Ideas note):
--   1. Verify no case-collision dupes EXIST in current data — fail loud.
--      We refuse to auto-deduplicate; collision resolution is a human
--      decision (which row wins? which audit trail to keep?).
--   2. Backfill UPDATE — lowercase every email row (idempotent).
--   3. Drop the old case-sensitive composite index.
--   4. Create the new functional unique index on (tenant_id, lower(email)).
--
-- All four statements run in the same migration transaction; partial
-- application is impossible.

-- Step 1: dupe check.
DO $$
DECLARE
  collisions integer;
BEGIN
  SELECT count(*) INTO collisions FROM (
    SELECT tenant_id, lower(email) AS lemail, count(*) AS n
    FROM "users"
    GROUP BY tenant_id, lower(email)
    HAVING count(*) > 1
  ) t;
  IF collisions > 0 THEN
    RAISE EXCEPTION
      'migration 0004: found % case-collision email dupes in users table; refusing to auto-deduplicate. Resolve manually (DELETE the duplicate rows or merge audit trails) before re-running.', collisions;
  END IF;
END $$;
--> statement-breakpoint

-- Step 2: backfill — idempotent, only touches rows that need it.
UPDATE "users" SET "email" = lower("email") WHERE "email" <> lower("email");
--> statement-breakpoint

-- Step 3: drop the old case-sensitive composite unique.
DROP INDEX IF EXISTS "users_tenant_email_unique";
--> statement-breakpoint

-- Step 4: new functional unique on (tenant_id, lower(email)).
CREATE UNIQUE INDEX "users_tenant_email_lower_unique"
  ON "users" (tenant_id, lower(email));
```

#### Exact openssl SAN-cert generation block

Add to `tools/bootstrap.sh` BEFORE the final exit (after the `BACKUP_AGE_IDENTITY` block, after line 262). Use config-file approach for explicit SAN list:

```bash
# Phase 02.7 / D-05 — Traefik self-signed cert for *.localhost + *.example.test.
#
# compose/traefik/dynamic.yml expects /certs/local.crt + /certs/local.key.
# Without these files Traefik falls back to its built-in TRAEFIK DEFAULT
# CERTIFICATE, which (a) violates the dynamic.yml contract, and (b) made
# Phase 02.6 reach for NODE_TLS_REJECT_UNAUTHORIZED=0 — we close both
# defects here.
#
# Idempotent: regenerate only if cert is missing OR expires within 30 days.
# 10-year validity (-days 3650) for self-host dev convenience.
CERT_DIR="${REPO_ROOT}/compose/traefik/certs"
CERT_FILE="${CERT_DIR}/local.crt"
KEY_FILE="${CERT_DIR}/local.key"
mkdir -p "${CERT_DIR}"

needs_cert=1
if [[ -f "${CERT_FILE}" && -f "${KEY_FILE}" ]]; then
  if openssl x509 -checkend $((86400 * 30)) -noout -in "${CERT_FILE}" >/dev/null 2>&1; then
    needs_cert=0
  fi
fi

if (( needs_cert )); then
  # Build a temp openssl config so SANs are declared explicitly.
  # No mkcert dependency (per project boring rule + CONTEXT D-07).
  openssl_config="$(mktemp)"
  cat > "${openssl_config}" <<'OPENSSL_CONFIG'
[req]
distinguished_name = req_distinguished_name
x509_extensions = v3_req
prompt = no

[req_distinguished_name]
CN = openwhispr-local-dev

[v3_req]
basicConstraints = CA:FALSE
keyUsage = nonRepudiation, digitalSignature, keyEncipherment
extendedKeyUsage = serverAuth
subjectAltName = @alt_names

[alt_names]
DNS.1 = localhost
DNS.2 = *.localhost
DNS.3 = api.localhost
DNS.4 = auth.localhost
DNS.5 = grafana.localhost
DNS.6 = minio-console.localhost
DNS.7 = mailpit.localhost
DNS.8 = api.example.test
DNS.9 = auth.example.test
DNS.10 = *.example.test
IP.1 = 127.0.0.1
IP.2 = ::1
OPENSSL_CONFIG

  openssl req -x509 -nodes -days 3650 -newkey rsa:2048 \
    -keyout "${KEY_FILE}" -out "${CERT_FILE}" \
    -config "${openssl_config}" -extensions v3_req >/dev/null 2>&1

  rm -f "${openssl_config}"
  chmod 600 "${KEY_FILE}"
  chmod 644 "${CERT_FILE}"
  echo "bootstrap: generated ${CERT_FILE} (10-year validity, SANs cover *.localhost + *.example.test)"
else
  echo "bootstrap: ${CERT_FILE} valid for ≥30 days — skip regeneration"
fi
```

**Note**: `*.localhost` does NOT match `localhost` (RFC 6125 — wildcard does not match parent), so both are needed in SANs. Same for `*.example.test` vs `api.example.test` — explicit + wildcard covers all router targets in `dynamic.yml`.

**Idempotence check** uses `openssl x509 -checkend $((86400 * 30))` — exits 0 if cert is valid for at least 30 days (86400 sec/day × 30).
