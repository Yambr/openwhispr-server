## Decisions Made

1. **Plain `globalThis.fetch` (Node 24 native) instead of `@better-fetch/fetch`** — RESEARCH §D-01 Open Question 1 RESOLVED. Zero new deps; matches the pattern already in `packages/data/src/seed/conformance.ts`.
2. **Lowercase email at adapter chokepoint, not in callers** — Better Auth's `findUserByEmail` does lowercase internally (verified at internal-adapter.mjs:448) but `createOAuthUser` does NOT (line 39). One explicit `.toLowerCase()` in mint-bearer.ts keeps both paths case-consistent and survives any future Better Auth refactor.
3. **Return raw `session.token` (no signing) for use in the channel-scheme URL** — bearer plugin self-signs on receive when the token has no `.` (verified plugins/bearer/index.mjs:32-37 with `requireSignature` unset). AUTH-03 (`set-auth-token` rotation) is unaffected — it fires on subsequent `/api/auth/*` calls, not on this 302 redirect response.
4. **Error messages contain status code + provider name only — never the IdP response body** (T-02.7-07 mitigation). Verified by Test 7a, which asserts `mint(ARGS)` rejects with `/userinfo 401/` AND does NOT contain the IdP body string `PII-LEAK-IN-BODY`.
5. **Fail-fast env validation BEFORE any network call** (Test 8) — missing `OIDC_CLIENT_ID` throws `Error: mint bearer: OIDC_CLIENT_ID is not configured` immediately and `fetchSpy` is NOT invoked.
