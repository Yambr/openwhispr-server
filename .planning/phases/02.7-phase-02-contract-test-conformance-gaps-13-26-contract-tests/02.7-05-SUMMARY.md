# Phase 02.7 Plan 05: D-03 Layer B — email lowercase normalize migration 0004 + check-user lower() lookup Summary

Case-insensitive email uniqueness via new atomic migration `0004_email_lowercase_normalize.sql` (collision-precondition DO $$ → backfill UPDATE → DROP legacy index → CREATE functional unique on `(tenant_id, lower(email))`), plus check-user route `WHERE lower(email) = lower($1)` lookup that hits the new functional index — closes WIRE-01 contract failure when fixture emails enter the DB with mixed case.

## Tasks Executed

### Task 1: A3 verification probe — drizzle-orm 0.45 functional index DSL support

**Path chosen: functional DSL form.**

Inspected `node_modules/.pnpm/drizzle-orm@0.45.2_*/node_modules/drizzle-orm/pg-core/indexes.d.ts:IndexBuilderOn.on()` signature:

```ts
on(...columns: [Partial<ExtraConfigColumn> | SQL, ...Partial<ExtraConfigColumn | SQL>[]]): IndexBuilder;
```

`SQL` is accepted in EVERY position alongside `ExtraConfigColumn`. Therefore `uniqueIndex("users_tenant_email_lower_unique").on(t.tenantId, sql\`lower(${t.email})\`)` parses cleanly. No drift comment / fallback needed.

### Task 2: RED — failing testcontainers integration test

Created `tests/integration/email-lowercase-normalize.test.ts` with 4 describe groups (7 tests total):
- Test 1: happy-path backfill on mixed-case rows (no collisions) — 4 assertions
- Test 2: collision precondition — migration RAISES EXCEPTION — 1 assertion
- Test 3: post-0004 unique violation on case-collision INSERT — 1 assertion
- Test 4: cross-tenant uniqueness isolation preserved — 1 assertion

Each test boots a fresh `postgres:17-alpine` testcontainer, creates the openwhispr_owner + openwhispr_app roles, applies migrations via per-statement `--> statement-breakpoint` splitting through `pg.Client`.
