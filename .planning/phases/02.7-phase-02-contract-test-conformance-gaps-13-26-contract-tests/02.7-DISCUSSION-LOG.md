## Area 4: signInFixture HTTP 404 from /api/auth/sign-in/email

### Research findings (advisor 4)

| Option | Pros | Cons | Complexity | Recommendation |
|--------|------|------|------------|----------------|
| A. Collapse AUTH_URL → BACKEND_URL entirely | Matches docker-compose default | Loses split-host topology hint exercised by *.example.test fixtures | 1 file | If v1 ships single-origin |
| B. Add auth.localhost Traefik router | Preserves split-host mental model | Cert SAN, /etc/hosts, doesn't fix redundancy | 2 files | If split-host is stated v1 goal |
| **C. Hybrid: collapse default but keep AUTH_URL as override** | Default works out of box; override hook preserved | Slight inconsistency | 1 file | **Forward-compat without operational cost** |

### Root cause (from advisor)

`packages/contract-tests/src/env.ts` defaults `AUTH_URL=http://auth.localhost`, but Traefik has NO router for that vhost. Signup works because seed container overrides `AUTH_URL=http://api:3000` (internal DNS, bypasses Traefik); host-side test runner hits the env-default and 404s at Traefik before Fastify sees it. Better Auth's canonical route IS `/sign-in/email` — the path is correct, the host is wrong.

### User question

| Option | Description | Selected |

| Add auth.localhost Traefik router | Cert + hosts + dynamic.yml | |
| Both — collapse AND add router | Belt-and-suspenders | |

**User's choice:** Collapse default — locked in CONTEXT D-04

## Area 5: Makefile BACKEND_URL=http vs Traefik HTTPS-only

### Research findings (advisor 5)

| Option | Pros | Cons | Complexity | Recommendation |
|--------|------|------|------------|----------------|
| **A. Bake `https://` + NODE_EXTRA_CA_CERTS at committed self-signed cert** | Honors HTTPS-only; no NODE_TLS_REJECT_UNAUTHORIZED anywhere; reproducible across contributors+CI; matches dynamic.yml claim; openssl-only | Need to actually generate local.crt/local.key (bootstrap.sh promises this but doesn't deliver) | 4 files: Makefile + bootstrap.sh + cert + env.ts | **PRIMARY — fixes 2 defects in one** |
| B. mkcert + locally-trusted CA | Cleanest UX | Operator install burden; CI complexity; modifies system trust store | 5 files + new dep | Combine with A as fallback |
| C. NODE_TLS_REJECT_UNAUTHORIZED=0 in Makefile | Trivially fixes silent-skip | Burns HTTPS-only rule; precedent for "just disable TLS"; violates feedback_no_workarounds_enterprise.md | 1 file | **REJECT** |
| D. Plaintext HTTP port on api for tests only | No TLS in test path | Violates HTTPS-only hard rule; test surface diverges from prod (CSRF/HSTS/Secure cookies untested); kills conformance value | 2 files | **REJECT** |

### Critical finding (from advisor 5)

`compose/traefik/dynamic.yml:4` and `compose/traefik/certs/.gitkeep` BOTH document that `bootstrap.sh` writes `local.crt`/`local.key` — but inspection shows `bootstrap.sh` has ZERO cert-generation logic. Traefik is silently falling back to `TRAEFIK DEFAULT CERTIFICATE`, which is exactly why Phase 02.6 needed `NODE_TLS_REJECT_UNAUTHORIZED=0`. This is a hidden 6th defect.

**User's choice:** No question asked — Option A locked in CONTEXT D-05 (research-recommended; aligns with `feedback_no_workarounds_enterprise.md` and HTTPS-only constitutional rule; collapses 2 defects)
