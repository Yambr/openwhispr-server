### Task 1 — RED: failing test scaffold + route-shape fixtures

- **Files:** `tools/lint-prod-readiness.test.ts`, five route fixture files, two dead-export fixture files.
- **Action:**
  1. `route-no-schema.ts`: `app.route({ method: "POST", url: "/api/x", config: { rateLimit: { max: 60, timeWindow: "1 minute" } }, handler: async () => ({}) });` — should flag `LOCKER-04-NO-SCHEMA`.
  2. `route-no-ratelimit.ts`: `app.route({ method: "POST", url: "/api/x", schema: { body: someSchema }, handler: ... });` — should flag `LOCKER-04-NO-RATELIMIT`.
  3. `route-health-ok.ts`: `app.route({ method: "GET", url: "/api/health", config: { auth: false, rateLimit: false }, handler: ... });` — allowed; no findings.
  4. `route-good.ts`: schema + config.rateLimit; allowed.
  5. `route-get-shape.ts`: `app.get("/api/y", { config: { rateLimit: false } }, handler);` (the test-only shape per Q3) — options object is arg[1]; URL is arg[0]. Locker handles both. Without `/api/_test/` URL match, the `rateLimit: false` is flagged → expect `LOCKER-04-INVALID-RATELIMIT-FALSE`.
  6. `dead-export/exporter.ts`: `export function unusedHelper() {}` + `export function usedHelper() {}`.
  7. `dead-export/non-importer.ts`: `import { usedHelper } from "./exporter";` (only one of the two exports has an importer).
  8. Test asserts: exporter's `unusedHelper` flagged `LOCKER-04-DEAD-EXPORT`; `usedHelper` clean. `route-no-schema.ts` flagged; `route-no-ratelimit.ts` flagged; `route-health-ok.ts` clean; `route-good.ts` clean; `route-get-shape.ts` flagged invalid-ratelimit-false.

### Task 2 — GREEN: route-shape AST scan + `--warn-only` flag

- **Files:** `tools/lint-prod-readiness.ts`, `tools/lint-prod-readiness.allowlist.txt`, `package.json`.
- **Action:**
  1. `import ts from "typescript"` direct (mirrors `lint-tenant-context.ts:59`). Per-file `ts.createSourceFile`; no ts-morph Project.
  2. `findFastifyRouteCalls(src)` per the sketch in 31-RESEARCH §"Pattern 2 / Code Examples → LOCKER-04". Match callee names: `route|get|post|put|patch|delete` on PropertyAccessExpression whose object is `app|fastify` (per Assumption A4 — handle plugin-rebound `fastify.route` too).
  3. `auditFastifyRoute(call, src)`:
     - For `route` method: arg[0] is the options ObjectLiteralExpression.
     - For `get|post|put|patch|delete` method: if arg[1] is ObjectLiteralExpression, that's the options; else (arg[1] is a handler function) → emit `LOCKER-04-NO-CONFIG` because no options object means no schema/no rateLimit.
     - Extract `url` property: if `/api/health|/api/ready|/api/healthz|/api/_test/` substring match → `rateLimit: false` allowed.
     - Check `schema` property exists.
     - Check `config.rateLimit` exists (object literal OR `false` for health URLs only).
     - Emit findings with `line: src.getLineAndCharacterOfPosition(call.pos).line + 1`.
  4. `--warn-only` flag: when present, `main(argv)` still prints findings to stderr but returns 0 (exit-code passthrough).
  5. **DEFER dead-export detection to Task 3** to keep this commit's diff bounded (per 31-RESEARCH §"Open Question 3"). Task 2 lands route-shape audit ONLY; dead-export ships in Task 3.
  6. Auto-run guard: `if (import.meta.url === \`file://${process.argv[1]}\`)` with `/* c8 ignore next 3 */`.
  7. Pre-seed `tools/lint-prod-readiness.allowlist.txt` by running the locker once against current main; output the ~18 route findings, edit each line to append `  # issue-31-04-debt-LOCKER-04-route-bulkfix-31-08`.
  8. `package.json` scripts:

     - `"test:lint-prod-readiness": "vitest run tools/lint-prod-readiness.test.ts --coverage --coverage.include=tools/lint-prod-readiness.ts --coverage.exclude= --coverage.all=false --coverage.thresholds.lines=90 --coverage.thresholds.branches=90 --coverage.thresholds.functions=90 --coverage.thresholds.statements=90"`
