# Plan 08.4-01: k6 adapter constructor fix + smoke regression + Run 5

<objective>
Restore the `Authorization` Bearer header on the load-test client's `/v1/realtime` WS upgrade by passing `params` to the correct positional argument of the `k6/websockets` WebSocket constructor, add a constructor-signature regression test, extend the smoke gate to catch any future zero-msg regression in 30 seconds (vs. a 30-min plateau), and operator-run the Run 5 plateau to validate the 4-endpoint mock baseline.

Purpose: Phase 08.3 closed partial because `realtime_ws_roundtrip_ms` p95 = 0 despite a healthy upstream echo handler and a verified-correct `@fastify/http-proxy` v11 forwarding path. The Run 4 summary has zero `ws_msgs_sent` / `ws_msgs_received` lines — the unambiguous signature of "upgrade failed at auth, `open` never fired." Research file `08.4-RESEARCH.md` traced this to `tools/load-test/src/utils/http-client.ts:152` calling `new W(url, params)` with 2 args instead of the documented `new WebSocket(url, protocols, params)` 3-arg form, silently binding `params` to the `protocols` slot and dropping the headers field. Fix unblocks the complete 4-of-4 endpoint SLO baseline.

Output: Single 1-line constructor fix + ~30 LOC regression test + ~20 LOC smoke-gate assertion + ~15 LOC smoke-gate behaviour test + Run 5 plateau result appended to RUN-LOG.
</objective>
