## 8. Pitfalls (planner WHY: lines)

1. **`withReuse()` requires `TESTCONTAINERS_REUSE_ENABLE=true` env.** Set in `apps/api/vitest.setup.ts` BEFORE the first import that may trigger testcontainer init. Not in `package.json` scripts (other consumers may not want reuse).
2. **`withReuse()` collisions on identical config.** All 22 files use `postgres:17-alpine + openwhispr + postgres_super + super-pw` → identical reuse hash → single shared container. First file to call `CREATE ROLE` wins; subsequent files crash `role already exists`. **Mandatory: idempotent role-bootstrap helper.** Use `DO $$ BEGIN ... EXCEPTION WHEN duplicate_object THEN NULL; END $$;` (Postgres ≤17 — no `CREATE ROLE IF NOT EXISTS`).
3. **Schema-per-file (D-04) requires migration-per-file.** `drizzle migrate` reads `__drizzle_migrations` from a fixed schema (default `drizzle`); D-04 sets `migrationsSchema: "_meta"`. If 22 files share container, each calling `migrate()` against own `test_<file>` schema, you must either (a) `SET search_path` then migrate, or (b) migrate to `public` ONCE in a global setup and have each file's schema clone the structure. **Option (b) is simpler** but requires global setup edit. Plan accordingly.
4. **`singleThread: true` is a vitest project-level concern.** Per `test.poolMatchGlobs` in each `vitest.config.ts`, not pool. In Vitest 4+, the field is `poolMatchGlobs: [["**/*.integration.test.ts", "forks"]]` with `poolOptions.forks.singleFork: true` — verify Vitest version before authoring config.
5. **Audio fixture failure is path-depth, not missing file.** CONTEXT D-08 says "find real location"; real fix is **edit 4→5 in test**, NOT touching `tests/fixtures/audio/`.
6. **BYOK guard refactor cascades.** `entrypoint-db-shape.test.ts` imports `apps/api/src/index.ts` which calls `assertBYOKConfig()` at top-level. If test env lacks BYOK envs, current code `process.exit(1)`s the vitest worker. The 2 entrypoint-db-shape failures likely vanish with D-07 fix — verify after D-07 lands, possibly remove from B-fix scope.
7. **`process.exit` move to entrypoint is breaking for tests too.** After D-07, tests that import `index.ts` will see thrown `BYOKGuardError` instead of `process.exit`. Update test setup to set required BYOK envs OR mock `assertBYOKConfig`. Without this, GREEN turns to RED elsewhere.
8. **onSignal export is api-surface change.** Coverage report (D-20) will demand `onSignal` is hit — direct test invocation satisfies. But `process.once` registration itself is now untested (cannot easily test in-process). Coverage ignore-pragma may be needed on lines 147-148 — verify what `c8/v8` reports.
9. **RU translation correctness.** Proposed RU `"Управление профилем, активными сессиями и удалением аккаунта."` matches EN structure. Verify with native speaker if available; otherwise this passes the locale-COVERAGE test (which checks key presence, not content quality).
10. **Ryuk-disabled + GHA cleanup is required pairing.** With Ryuk OFF, testcontainers do NOT self-clean on parent crash. The `if: always()` post-step is **mandatory** — without it CI runners accumulate orphans across runs.
11. **`docker info` pre-flight may need `sudo` on bare ubuntu-24.04.** GHA hosted runners have `docker` group membership for `runner` user (verified by e2e-phase6-quick:486 working). No sudo needed.
12. **W-3 plan-size discipline.** D-06 cluster #2 = 18 files. Migrating all 18 in one commit risks > 7-commit plan budget. Consider sub-clusters: notes (5) + conversations (4) + folders (2) + transcriptions (2) + v1/keys (2) + tokens (1) — or treat as single mechanical edit (all identical pattern) commit-wise but expect plan-size to bulge.
13. **CONTEXT D-06 wrongly says cluster #2 includes "worker + data".** No `*.integration.test.ts` files exist under those packages. If glob `**/*.integration.test.ts` is applied to `apps/worker/vitest.config.ts` + `packages/data/vitest.config.ts`, it matches nothing today — harmless but documentation-misleading.
