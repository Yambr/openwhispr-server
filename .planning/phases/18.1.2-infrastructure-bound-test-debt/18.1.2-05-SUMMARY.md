## New shared helper

`apps/api/tests/support/shared-route-pool.ts` (~80 lines, tests-tree only — HARD RULE-safe):

- Lazily wraps `getSharedPostgres()` (Plan 02/03) + `bootstrapSharedRoles()` + `provisionPgPartman()` + Drizzle `migrate()` into a single idempotent boot.
- Returns an `openwhispr_owner`-scoped `Pool` ready for route-level integration tests.
- Module-scope memoised — second-and-onward callers within the same vitest worker get the cached `Pool`; Drizzle migrate no-ops via `_meta.__drizzle_migrations`.
- `MIGRATIONS_FOLDER` uses 4 `..` segments from `apps/api/tests/support` → repo root → `packages/data/migrations` (one shallower than `usage.integration.test.ts`'s 6 segments because `support/` is one level above `unit/routes/__tests__/`).
- Caller MUST NOT call `pool.end()` in `afterAll` — Pool ownership delegated to the module cache.

## Per-file migration recipe

Each of the 15 files received the same surgical edits:

1. Drop `bootMigratedPostgres` and `seedUser` from production-tree setup.ts imports (keep `buildTestApp`).
2. Add `getSharedRoutePool` import from `apps/api/tests/support/shared-route-pool.js`.
3. Replace `const booted = await bootMigratedPostgres(); pool = booted.pool; shutdown = booted.shutdown.bind(booted);` with `pool = await getSharedRoutePool();`.
4. Replace `seedUser` calls with inline ON CONFLICT `INSERT INTO users` returning the row id (production-tree `seedUser` lacks ON CONFLICT and would violate the `(tenant_id, lower(email))` unique index on reused containers).
5. Drop `let shutdown: () => Promise<void>;` declaration.
6. Drop `if (shutdown) await shutdown();` from `afterAll`; add explanatory comment about shared container ownership.

## Critical config change

`apps/api/vitest.config.ts` — added `fileParallelism: false` (mirrors `tests/e2e/vitest.config.ts`).

**Rationale:** Cluster #2 integration tests share a single Postgres testcontainer and therefore share the `conversations`, `notes`, `folders`, `messages`, `transcriptions`, and `api_keys` tables. Their `beforeEach` clauses run unscoped `DELETE FROM …` by design (Plan 03 Option A canon — shared `public` schema + per-file TRUNCATE). Parallel file execution races those DELETEs against sibling-file INSERTs and SELECTs.

**Pre-fix evidence:** Running the 4 conversations files in parallel showed `Tests 11 failed | 23 passed (34)` with mid-test 404s and unexpected row counts. With `fileParallelism: false`: `Tests 34 passed (34)` in 4.05 s.

This is a **Plan 03 implicit prerequisite** surfaced here — Plan 03's 2 files happened to coexist without obvious races because their schemas (`usage_ledger`) are user-scoped and their inserts/selects scope by `user_id`, masking the race window. Cluster #2's unscoped DELETEs made the race deterministic.

## Deviations

### 1. Cluster #2 count: PLAN said 18, actual 15 (contraction; D-46 spirit honoured)

`18.1.2-05-PLAN.md` initially scoped Cluster #2 at 18 files. CONTEXT was corrected to 16. The discovered ground-truth is **15 pg-container files** (one fewer than CONTEXT) because `apps/api/tests/unit/routes/tokens/__tests__/rate-limit-isolation.integration.test.ts` boots a Valkey container (`GenericContainer(VALKEY_IMAGE)`), not Postgres — see Deviation #4. ### 2. File paths: PLAN said flat, actual nested

`18.1.2-05-PLAN.md` referred to files as e.g. `conversations-crud.test.ts` (flat). Actual layout is `apps/api/tests/unit/routes/conversations/__tests__/crud.integration.test.ts` (nested by domain + `__tests__`). Commit subjects and SUMMARY use the actual paths verified by `find apps/api/tests/unit/routes -name "*.integration.test.ts"`.

### 3. Pattern wording: PLAN said "schema isolation", corrected to "Option A (shared public + TRUNCATE)" per Plan 03 canon

`18.1.2-05-PLAN.md` commit subjects used "schema isolation" which suggested per-file `CREATE SCHEMA test_*` (Option B in Plan 03's research). That contradicts the canonical pattern landed in Plan 03 SUMMARY's "W-2 Option A (CLAUDE.md hard rule compliance)" section, which uses a **shared `public` schema + per-file TRUNCATE + per-file unique user emails**. Commit subjects in this execution use the corrected wording.

### 4. Tokens test out of scope (Valkey, not Postgres)

`apps/api/tests/unit/routes/tokens/__tests__/rate-limit-isolation.integration.test.ts` was originally counted as Cluster #2 sub-cluster 2c but boots `GenericContainer(VALKEY_IMAGE)` for Redis-backed rate-limit testing. It does NOT use Postgres or `bootMigratedPostgres()`. Container reduction for Valkey-backed tests is a separate concern (Cluster #N — possibly Plan 06 or 07 scope). Documented as out-of-scope here; no edits.

### 5. `fileParallelism: false` config change — auto-fix Rule 3 (blocking)

Adding `fileParallelism: false` to `apps/api/vitest.config.ts` was not in the plan but was discovered to be a hard prerequisite — without it, the migrated tests showed `Tests 11 failed | 23 passed (34)` from the parallel-DELETE race. Rule 3 applied: this is a blocking issue for completing the migration. Pre-fix RED + post-fix GREEN evidence both committed in `18.1.2-05-01`'s commit message.
