# Phase 08.3: mock-litellm `/v1/realtime` echo

## Goal

`compose/mock-litellm` exposes a `WSS /v1/realtime` endpoint that accepts the k6 realtime-ws flow handshake and echoes back one message frame per request. After Run 4 mock plateau lands, the 4-endpoint p95 baseline (transcribe / reason / agent-stream / **realtime-ws**) is complete and Plan 08-08 can publish the full SLO table.

## Why this phase exists

Run 3 (commit `fa799fa`) produced a valid 30-min plateau with PASS on transcribe / reason / agent-stream exit gates. The only outstanding item: `realtime_ws_roundtrip_ms` p95 = 0 across 102,162 healthy WS handshakes. Root cause is **not** a flow or trend bug (08.1 commit `2e91227` fixed the addEventListener tag-mapping) — it's that `compose/mock-litellm/src/server.ts` has no `/v1/realtime` route, so the upstream peer never emits a message frame. The k6 flow's `message` listener never fires, so `roundtripMs.add(...)` is never called.

This is a small, scoped gap.

## Success Criteria

1. `compose/mock-litellm/src/realtime.ts` exports a Fastify plugin that registers `GET /v1/realtime` as a WebSocket upgrade endpoint. On client connect: accept the handshake (101 Switching Protocols), wait for the first inbound text frame, echo back exactly one text frame, then leave the socket open for the client to close (the k6 flow closes with code 1000 after receiving the frame).
2. The echo frame shape is a minimal OpenAI Realtime API event envelope: `{"type":"session.created","event_id":"<uuid>","session":{"id":"mock-<uuid>"}}` — enough for the k6 flow to record a roundtrip; full session.state machine NOT required.
3. Strict TDD: `compose/mock-litellm/src/realtime.test.ts` asserts handshake + echo behaviour via a programmatic WebSocket client BEFORE the handler is implemented. RED → GREEN.
4. The new route is registered in `compose/mock-litellm/src/server.ts` alongside existing transcribe/chat-completions routes; existing tests stay GREEN.
5. `make load-test PROFILE=mock` Run 4 produces a summary JSON where `realtime_ws_roundtrip_ms` p95 is non-zero AND falls within `[50, 1000]` ms (Plan 08-07.1 plausibility window).
6. Coverage on new mock-litellm code ≥ 90/90/90/90.
7. All hooks pass (lefthook biome + english + commitlint); lower-case commit subjects.

## Threat model

No new attack surface. mock-litellm is **only** wired into `docker-compose.yml` under the `load-test-mock` profile; it is never exposed in production deploys. The new WS route mirrors the security posture of the existing chat-completions / transcribe routes (no auth, no rate-limit — load-test profile assumption). No PII, no secrets.

## Deferred items

1. **Full OpenAI Realtime session state machine** (input_audio_buffer.append, response.create, response.audio.delta, etc.) — out of scope. Run 4 just needs measurable roundtrip; behavioural fidelity is for a future realistic-LLM integration phase.
2. **Bidirectional ping/pong heartbeat** — not needed for the 30-min plateau; the k6 flow closes after the first inbound frame.
