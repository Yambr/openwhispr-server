# Phase 33 / Plan 03 — Node-side backfill migrator

**Requirement closed (partial):** CRIT-FIX-02 — backfill of existing plaintext rows.

## Goal

Implement `packages/data/src/encryption/backfill.ts` + a `cli/backfill-encrypt-credentials.ts` standalone entry point. The backfill reads existing plaintext from the 8 credential columns, encrypts each row's value via envelope, writes the 6 bytea sidecars + fingerprint (where applicable), and leaves the plaintext column intact (33-05 drops it). Idempotent: a second invocation processes 0 rows.

## Depends on

- 33-01 (the 48 bytea sidecars + 2 fingerprint cols must exist on disk).
- 33-02 (lens not actually called here, but `validateMasterKek` + provider selection are reused via `boot.ts`).
- DISCIPLINE Rules 1, 2, 5 (real PG testcontainer, no mocks).

## Architectural choices

- **Owner pool (BYPASSRLS), not app pool.** Backfill is a cross-tenant operation; RLS fail-closed posture (Phase 32) would mask all rows since `app.tenant_id` is unset. Backfill uses the migrator/owner role connection that already powers `packages/data/src/migrate.ts`.
- **NOT auto-run by `migrate.ts`.** Per CONTEXT D-Migration-split + research §Q11: rolling back 0019 must remain a single-SQL-file operation. If backfill ran inline, the rollback path would need to also un-encrypt — operationally fragile. Operator runs `pnpm --filter @openwhispr/data backfill:encrypt-credentials` after 0019, before 33-05's 0020 lands.
- **Batched by row id `ORDER BY id LIMIT batchSize`** to cap memory; default 500 rows/batch. Each batch is one TX.
- **Idempotency predicate:** `WHERE <col> IS NOT NULL AND <col>_value_ciphertext IS NULL` — captures both fresh post-0019 rows and partially-completed prior runs (process crashed mid-batch).
- **Fingerprint computed in the same UPDATE.** For `sessions.token` and `sessions.previous_token`: `crypto.createHash('sha256').update(plaintext).digest()` → `token_fp` column. Single round-trip per row.

## Risks + mitigations (from research §15 pitfalls)

| Risk | Mitigation |
|---|---|
| Pitfall #7 (backfill encrypts a row mid-INSERT and races with concurrent app write) | Lens (33-02) writes ciphertext on every new INSERT post-33-04 deploy. Backfill predicate `value_ciphertext IS NULL` skips already-encrypted rows. Operator runbook (33-05 docs): deploy 33-04 (lens active) BEFORE running backfill — new rows are encrypted at write, backfill only mops up legacy plaintext. |
| Pitfall #8 (token_fp collision risk for SHA-256 at scale) | SHA-256 collision probability at 10^9 tokens ≈ 5×10^-29 — accept. UNIQUE INDEX on token_fp gives 23505 if collision somehow occurs; explicit operator escalation. |
| Pitfall #10 (backfill blocks DDL — long-running lock) | Batched UPDATEs (default 500 rows) keep each TX small; no DDL competes during backfill (0020 lands separately in 33-05). |
| RLS masks rows | Owner-pool BYPASSRLS — Phase 32 fail-closed posture irrelevant for migrator role. Test asserts this explicitly by seeding 3 tenants and verifying all 3 are processed. |
| CLAUDE.md Hard Rule 1 (no prod-code edits to make tests pass) | Backfill is NEW prod code; existing production code unchanged. |
