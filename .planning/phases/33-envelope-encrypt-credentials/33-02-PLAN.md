# Phase 33 / Plan 02 — Drizzle/Better-Auth lens + boot-time validator

**Requirement closed (partial):** CRIT-FIX-02 — lens + boot validator.

## Goal

Implement `packages/data/src/encryption/lens.ts` as a **Better Auth `Adapter`-wrapping** lens (research §Q6 architecture (c)) that transparently encrypts on write / decrypts on read for the 8 configured credential columns, plus `packages/data/src/encryption/boot.ts` exporting `validateMasterKek()` that loud-fails at startup with exit 78 (BSD EX_CONFIG) when the KEK config is missing or unsupported.

## Depends on

- 33-01 (migration 0019 — 48 bytea sidecars exist on disk, but lens itself is DB-shape-agnostic and unit-tested with mocked Adapter).
- Existing `packages/data/src/encryption/envelope.ts` (6-bytea `EncryptedRow` shape — unchanged).
- Existing `packages/data/src/encryption/key-provider.ts` `KeyProvider` interface.
- DISCIPLINE Rules 1, 2, 4 (mock-of-Adapter allowed: external interface boundary, NOT internal logic).

## Architectural choices (locked by research §Q6)

- **(c) adapter-wrapper** chosen over (a) Drizzle `customType` (1→1 — won't work for 6 sidecars) and (b) Drizzle middleware (no public API).
- Lens wraps Better Auth's `Adapter` interface from `better-auth/types`, intercepting `create / update / findOne / findMany / delete / count`. The wrapped adapter is fed back into `betterAuth({ database: ... })` (wiring lands in 33-04).
- `EncryptedColumnMap`: `{ [tableName]: { [columnName]: { sidecarPrefix: string; fingerprint?: FingerprintColumn } } }`. Caller declares the 8 columns explicitly (no schema introspection — keeps lens tree-shakable and unit-testable without a DB).
- `FingerprintColumn`: `{ column: 'token_fp'; algorithm: 'sha256' }`. When set, lens computes `crypto.createHash('sha256').update(plaintext).digest()` and writes it alongside the 6 sidecars; reads accept a `lookupBy: { [fpCol]: plaintextToHash }` clause and the lens rewrites to `WHERE fpCol = <hash>` before delegating to the wrapped adapter.

### Task 2 — GREEN: lens.ts implementation

**Files:** `packages/data/src/encryption/lens.ts` (NEW), `packages/data/src/encryption/index.ts` (barrel export)

**What passes:** Implements `wrapAdapter(adapter: Adapter, keyProvider: KeyProvider | KeyProvider[], columnMap: EncryptedColumnMap): Adapter`. Inside each intercepted method:
- **Write path (create/update):** for each column in `columnMap[model]`, if `data[col] !== undefined && data[col] !== null`: encrypt via `envelope.encryptValue(activeProvider, Buffer.from(data[col]))`, expand into 6 sidecar fields named `${col}_${sidecarKey}`, optionally compute SHA-256 fingerprint into `${col}_fp` (when `fingerprint` configured). Set `data[col] = null` (post-0020 schema drops the column entirely; 33-04 lens behavior is "write NULL to plaintext, full payload to sidecars"; 33-05 schema flip removes the plaintext col so this becomes a no-op).
- **Read path (findOne/findMany):** post-fetch, for each configured column: if all 6 sidecars present, call `envelope.decryptValue(activeProvider, {dek_wrapped, ..., value_ciphertext})` and bind result back to `row[col]`. Strip sidecar keys from returned row.
- **Provider chain:** `keyProvider` accepted as `KeyProvider | KeyProvider[]`. First provider is active (used for writes); array entries 1..N are decrypt-fallback. `decryptValue` tries each in order until one succeeds.
- **Fingerprint rewrite:** if `where` contains `{field: '<col>_fp_lookup', value: <plaintext>}`, replace with `{field:'<col>_fp', value: crypto.createHash('sha256').update(value).digest()}`.

All 6 RED groups now GREEN.

**Commit:** `feat(33-02): green — lens.ts wraps better-auth adapter with envelope encryption`

## Risks + mitigations (from research §15 pitfalls)

| Risk | Mitigation |
|---|---|
| Pitfall #2 (Better Auth `Adapter` interface is internal-shaped — types may shift) | Pin import from `better-auth/types` with exact version in `package.json`; lens unit tests mock the interface explicitly — type drift surfaces at compile time before integration. |
| Pitfall #4 (DEK leaks via thrown error stack) | `envelope.ts` already zeroizes DEK in `finally`; lens does NOT log row payloads on error — only column names + model. |
| Pitfall #6 (Adapter `findMany` returns iterable of partial rows) | Lens iterates returned rows and decrypts column-by-column; rows missing all 6 sidecars (legacy plaintext only) pass through unchanged — supports 33-03 backfill window. |
| Pitfall #9 (provider chain mis-fallback masks tamper) | `decryptValue` only catches `unwrapDek` errors during chain walk; `decipher.final()` GCM auth-tag mismatch on the value layer propagates as the canonical tamper signal (no provider can recover from value-layer tamper — the DEK already unwrapped). |
| Mock-of-Adapter DISCIPLINE Rule 4 concern | Adapter is Better Auth's external interface (process boundary). Rule 4 mocks-internal-logic violation does NOT apply. Integration tests in 33-04 use real Better Auth + real PG. |
