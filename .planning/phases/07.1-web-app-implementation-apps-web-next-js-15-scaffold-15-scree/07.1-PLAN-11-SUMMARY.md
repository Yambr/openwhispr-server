# Phase 07.1 Plan 11: U11/U12/U13 Conversations Slice Summary

## One-liner

U11 list + U12 messages thread (keyset paginated, 4 roles via i18n) + U13 search
(POST) — full state matrix + axe per UI-SPEC end-user.

## What shipped

**U11 — `/app/conversations`** (`apps/web/src/app/(auth)/app/conversations/page.tsx`)
- RSC prefetches `GET /api/conversations/list?limit=20`, forwards cookie header.
- `ConversationsListClient` renders a Table with columns: Created, Title, Updated
  + per-row Delete action.
- Delete → `AlertDialog` confirm → `DELETE /api/conversations/delete` body
  `{ id }` → invalidate `["conversations","list"]`.
- Load-more button visible when `items.length >= 20` (PAGE_LIMIT).
- 4 UI states: loading (Skeleton rows), empty (Card), success (Table), error (Alert).

**U12 — `/app/conversations/[id]`**
(`apps/web/src/app/(auth)/app/conversations/[id]/page.tsx`)
- RSC prefetches `GET /api/conversations/messages?conversation_id=<id>&limit=50`.
  Uses the GET branch of the dual-method endpoint (Plan 01 verified line 145).
- `ConversationDetailClient` renders messages chronologically ascending. Because
  the API returns DESC order (`buildKeysetOrderLimit`), the Client reverses the
  first page and prepends older pages already kept ascending.
- "Load earlier messages" button visible when first page is full
  (`firstPageMessages.length >= 50`); each click fetches one older keyset page
  via `before=<oldest_created_at>` and prepends it.
- `MessageBubble` renders four distinct role styles (user / assistant / system /
  tool) with the role label rendered via the i18n key
  `end-user.conv-detail.role.<role>.label` — never via the raw `role` string.
- Actions: Copy transcript (joins `### <label>\n<content>\n` and writes to
  clipboard, fires sonner toast), Export JSON (Blob with
  `application/json` mime), Delete conversation (`AlertDialog` →
  `DELETE /api/conversations/delete` → `router.push("/app/conversations")` +
  invalidate list cache).
- 4 UI states: loading (Skeleton bubbles), empty (Card "No messages"), success,
  error (Alert).

**U13 — `/app/conversations/search`**
(`apps/web/src/app/(auth)/app/conversations/search/page.tsx`)
- Client-only page. Reads `?q=<query>` via `useSearchParams()`.
- `useQuery` is `enabled` only when `q.trim().length > 0`.
- Posts to `/api/conversations/search` (verified POST per Plan 01) with body
  `{ query, limit: 20 }`.
- Result rows: title + updated_at + score badge (`Score 0.94` format, 2
  decimals). Each row links to `/app/conversations/<id>`.
- 4 UI states: loading (Skeleton rows), empty (Type-a-query Card OR
  No-conversations-match Card), success, error (Alert with Retry).
- Submit pushes `?q=<urlencoded>`; Clear pushes `?q=`.
