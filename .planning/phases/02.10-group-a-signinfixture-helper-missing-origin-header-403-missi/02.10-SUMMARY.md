# Phase 02.10 Summary — signInFixture Origin Header (Group A Closed)

## One-Liner

`packages/contract-tests/src/helpers/sign-in-fixture.ts` POSTed `/api/auth/sign-in/email` without forwarding an `Origin` header → Better Auth's CSRF gate returned `403 MISSING_OR_NULL_ORIGIN` → 4 contract tests RED. Fixed via the proven seed-time pattern (`origin: AUTH_URL`) mirrored verbatim from `packages/data/src/seed/conformance.ts:46-58` (Phase 02.3).

## Defect → Fix Narrative

**Defect.** `signInFixture` builds the sign-in POST with only `content-type: application/json` in headers. Node's `globalThis.fetch` (undici) does NOT auto-set an `Origin` header for server-to-server requests — Origin is a browser-emitted CORS header. Better Auth's CSRF middleware (configured in Phase 02.3 via `trustedOrigins: [AUTH_URL, OPENWHISPR_API_URL]` in `apps/api/src/auth.ts`) consequently rejected the request with `403 MISSING_OR_NULL_ORIGIN`, blocking 4 contract suite cases that depend on a valid session cookie.

**Fix.** Added `origin: AUTH_URL` to the headers literal at `sign-in-fixture.ts:34`. The constant is already imported from `../env.js`. The pattern matches the seed-time `signUp` helper in `packages/data/src/seed/conformance.ts:46-58` (Phase 02.3) — a proven, in-production solution since the Plan 02 docker-compose stack came up.

**Diff.**

```diff
   const res = await jf.fetch(`${AUTH_URL}/api/auth/sign-in/email`, {
     method: "POST",
-    headers: { "content-type": "application/json" },
+    headers: {
+      "content-type": "application/json",
+      // Phase 02.10 — Better Auth's CSRF gate rejects sign-in POSTs whose
+      // Origin header is absent or not in `trustedOrigins` with HTTP 403
+      // MISSING_OR_NULL_ORIGIN. Server-to-server fetch() doesn't auto-set
+      // Origin; we forward AUTH_URL so the request matches the
+      // `trustedOrigins: [AUTH_URL, OPENWHISPR_API_URL]` allowlist declared
+      // in apps/api/src/auth.ts. Mirrors the proven seed-time pattern in
+      // packages/data/src/seed/conformance.ts:46-58 (Phase 02.3).
+      origin: AUTH_URL,
+    },
     body: JSON.stringify({ email, password: FIXTURE_PASSWORD }),
   });
```

#### NEW Class — Cascade Tail #11 — Better Auth `session.token` Drizzle schema mismatch (4-5 cases)

**Discovered during Phase 02.10 E2E re-run.** Direct evidence in `docker compose logs api`:

```
[Better Auth]: INTERNAL_SERVER_ERROR
  [BetterAuthError: The field "token" does not exist in the schema for the model "session".
   Please update your schema.]

[Better Auth]: The field "token" does not exist in the "session" Drizzle schema.
  Please update your drizzle schema or re-generate using "npx auth@latest generate".
```

**Surfaced because Group A is now fixed** — requests reach the sign-in code path that touches the `session` table. Previously masked by the 403 CSRF gate.

Failing schema location: `packages/data/src/schema/sessions.ts` declares `tokenHash bytea("token_hash")` (custom Phase 2 token-rotation column for the opaque-bearer + 5-minute overlap window AUTH-04 design) but does NOT declare a plain `token` text column that Better Auth's session model requires by default.

Affected tests (currently 500 instead of expected status):
- `delete-account > cookie cascade` — sign-in 500
- `verification-status > verified email` — sign-in 500
- `conventions > GET verification-status 401 on Bearer invalid` — bearer-auth path 500
- `conventions > DELETE delete-account 401 on Bearer invalid` — bearer-auth path 500

This is **NOT Group B (OAuth 503), NOT Group C (rate-limit 429), NOT Group A (CSRF 403)**. It is a NEW cascade tail #11 in the Better-Auth-schema-vs-OpenWhispr-custom-rotation-design tension. Likely fix candidates:
- (a) Add a plain `token` text column to `session` and let Better Auth populate it (canonical session token), keeping `token_hash` as a redundant rotation field; OR
- (b) Pass an explicit `betterAuth({ session: { fields: { token: "token_hash" } } })` mapping in `apps/api/src/auth.ts` to alias the field; OR
- (c) Re-evaluate the Phase 2 AUTH-04 design — confirm whether `token_hash` should subsume `token` and update the Better Auth init accordingly.

**Per task spec ("If E2E surfaces NEW class (not B/C/A): STOP, surface as deviation"), I am surfacing this for Phase 02.11+ scoping rather than auto-fixing.** The architectural decision (a vs b vs c) needs explicit scoping against the AUTH-04 token-rotation contract — Rule 4 territory.
