<objective>
Implement the BYOK boot-time guard as a workspace package and wire the OTel
`=disabled` sentinel. This plan satisfies BYOK-02 and is the consumer of the
env contracts documented by plan 14-02 and the slim-core base from plan
14-01.

The guard lives at `packages/byok-guard/` (mirrors the `packages/email/`
analog that closed the noopSender audit) and is imported by BOTH `apps/api`
and `apps/worker` via the workspace specifier `@openwhispr/byok-guard`.
Cross-app relative imports (e.g. `../../api/src/lib/byok-guard.js`) are
forbidden — the repo's canonical pattern for code shared by 2+ apps is a
workspace package, not a relative import that would violate tsconfig
project-reference boundaries and the `packages/email` precedent.

TDD plan (type: tdd) per get-shit-done planner conventions — RED → GREEN →
REFACTOR cycles. The guard is pure I/O on `env` (a `NodeJS.ProcessEnv`-shaped
input) plus a Pino logger; both are process-boundary, so internal-logic
mocks are forbidden and not needed. The only test-side mock is a spy on
`process.exit` (Node primitive) and capture of pino-fatal output via a
`pino.destination()` write stream targeted at an in-memory buffer.

Output: BYOK-02 satisfied. The api refuses to boot when an overlay is OFF
and the corresponding BYOK env is unset. The fatal record matches the
`{event, code, overlay, missing, hint}` shape from CONTEXT.md decision 2.
</objective>

The matrix collapses to: "for each row, if `missing` envs are unset (and NODE_ENV gate satisfied for SMTP), emit fatal + exit 1."
