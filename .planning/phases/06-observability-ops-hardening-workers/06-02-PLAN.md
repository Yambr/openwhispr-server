    Create `compose/postgres/Dockerfile`:
    ```
    FROM postgres:17-alpine

    # pg_partman 5.2.4+ — required for Phase 6 audit_log monthly partitioning.
    # Alpine community has no apk for pg_partman; build from source.
    ARG PG_PARTMAN_VERSION=5.2.4
    RUN apk add --no-cache --virtual .build-deps \
            build-base clang15 llvm15 git \
        &amp;&amp; git clone --depth 1 --branch v${PG_PARTMAN_VERSION} https://github.com/pgpartman/pg_partman.git /tmp/pg_partman \
        &amp;&amp; cd /tmp/pg_partman \
        &amp;&amp; make NO_BGW=1 install \
        &amp;&amp; rm -rf /tmp/pg_partman \
        &amp;&amp; apk del .build-deps
    ```

    (`NO_BGW=1` skips the background-worker which we don't need — our partman-maintenance BullMQ job calls `partman.run_maintenance_proc()` instead, per D-A4.)

    Create `compose/postgres/init/01-pg-partman.sql`:
    ```
    CREATE SCHEMA IF NOT EXISTS partman;
    CREATE EXTENSION IF NOT EXISTS pg_partman SCHEMA partman;
    GRANT USAGE ON SCHEMA partman TO openwhispr_owner;
    ```

    Update `docker-compose.yml` postgres service: replace `image: postgres:17-alpine` with `build: ./compose/postgres` and mount the init script via `volumes: - ./compose/postgres/init:/docker-entrypoint-initdb.d/zz-phase6:ro` (zz- prefix runs AFTER existing Phase 1 role init scripts).

    If the source build fails or takes too long on Alpine, fallback per RESEARCH.md Risk-1: switch base to `bitnami/postgresql:17` which bundles pg_partman natively. Document the fallback choice in the SUMMARY.

    DO NOT remove the existing image pin discipline — pin pg_partman to v5.2.4 explicitly via ARG.
