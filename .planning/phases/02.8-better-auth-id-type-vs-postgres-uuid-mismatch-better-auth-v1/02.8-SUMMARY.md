# Phase 02.8 — Better Auth UUID Mode + Plugin Allowlist CI Guard

## One-liner

Closes the LAST cascade-tail defect (Better Auth v1.6.9 32-char base32 IDs vs Postgres `uuid` columns → 22P02 → 422 signup) with a 1-line first-class config (`advanced.database.generateId: "uuid"`) plus a fail-closed CI lint to prevent plugin-introduced regressions of the same class.

## Defect → Fix Narrative

**Symptom (Phase 02.7-06 contract-test E2E):** seed step `signUp(rotation-test@local)` returned HTTP 422 from `/api/auth/sign-up/email`. API logs showed Postgres error `22P02 invalid input syntax for type uuid` on the `users.id` insert.

**Root cause:** Better Auth v1.6.9's default `generateId` (in `@better-auth/core/utils/id`) emits 32-char base32 strings (e.g. `kx7z...`). Our `users.id`/`sessions.id`/`accounts.id`/`verifications.id` are Postgres `uuid` columns (`PRIMARY KEY DEFAULT gen_random_uuid()`). The mismatched string was passed through Drizzle, hit the pg driver as text, Postgres rejected it with `22P02`.

**Fix:** Add `database: { generateId: "uuid" }` inside the `advanced:` block in `apps/api/src/auth.ts`. Verified resolution chain:

1. `@better-auth/core/dist/db/adapter/get-id-field.mjs:12` reads `options.advanced?.database?.generateId === "uuid"` → sets `useUUIDs=true`.
2. `@better-auth/drizzle-adapter/dist/index.mjs:432` declares `supportsUUIDs: provider === "pg"` → we use `provider:"pg"` so `supportsUUIDs:true`.
3. Combined: `shouldGenerateId=false` → BA stops emitting any ID.
4. Postgres `uuid PRIMARY KEY DEFAULT gen_random_uuid()` then synthesises the UUID server-side.

This is BA's documented first-class path, NOT a workaround. No JS round-trip, no `crypto.randomUUID()`, native pg-side UUIDs.

## Plugin Allowlist CI Guard (D-02)

New file `tests/self-tests/better-auth-plugin-uuid-safety.test.ts`:

- **Allowlist** (UUID-safe): `bearer`, `genericOAuth`, `jwt`
- **Denylist** (verified to bypass `ctx.generateId` by importing directly from `@better-auth/core/utils/id`):
  - `organization` — see `node_modules/.../plugins/organization/schema.mjs:1,12,20,27,38`
  - `anonymous` — see `node_modules/.../plugins/anonymous/index.mjs:9,19`
- **Static-source scan** of `apps/**` and `packages/**` for raw `import { generateId } from "@better-auth/core/utils/id"` — fails closed if found.
- **Fail-closed discipline:** any plugin not on the allowlist fails the test, forcing explicit triage when adding new BA plugins (and forcing the Option B uuid → text schema migration discussion if a denylisted plugin is needed).
