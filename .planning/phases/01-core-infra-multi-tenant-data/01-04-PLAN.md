withTenant signature (D-18, RESEARCH-DB §"Pattern 2"):
  withTenant<T>(db: NodePgDatabase<schema>, tenantId: string, fn: (tx) => Promise<T>): Promise<T>

CRITICAL: use `set_config('app.tenant_id', ${tenantId}, true)` (LOCAL flag = true) — Postgres `SET LOCAL` does NOT accept parameter binding for the value, so set_config is the parameterized equivalent. drizzle's tx.execute(sql`...`) parameterizes correctly.

Tenant-id validation: regex /^[0-9a-f]{8}-[0-9a-f]{4}-[0-9a-f]{4}-[0-9a-f]{4}-[0-9a-f]{12}$/i applied BEFORE touching the wire — fail fast on garbage.

Fastify hook (D-19):
- onRequest hook reads `x-tenant-id` header
- typeof !== 'string' OR header missing -> req.tenantId = '00000000-0000-0000-0000-000000000000' (default tenant per D-17 seed)
- Phase 2 will replace header reading with bearer-token -> sessions.tenant_id lookup

KEK/DEK envelope (D-11, D-12):
- KEK: 32 bytes from MASTER_KEK env (base64url-decoded; bootstrap.sh produces this length)
- DEK: 32 bytes random per encryption
- AES-256-GCM, 12-byte IV (randomBytes per op — never reuse), 16-byte auth tag
- EncryptedRow shape: 6 byteas (dek_wrapped, dek_iv, dek_auth_tag, value_iv, value_auth_tag, value_ciphertext)
- Per-row DEK wrapped with KEK; rotating KEK only re-wraps DEKs (no payload re-encryption)

KeyProvider interface (D-12, PROVIDER-02):
- EnvKeyProvider — production-grade in v1 (only impl that works)
- VaultKeyProvider — stub: throws Error("VaultKeyProvider not implemented in v1; HashiCorp Vault adapter deferred")
- KmsKeyProvider — stub: throws Error("KmsKeyProvider not implemented in v1; AWS KMS adapter deferred")
- selectProvider() reads OPENWHISPR_KEY_PROVIDER env (default 'env')

PgBouncer-interleave test setup:
- Wave-1 testcontainers: postgres:17-alpine + edoburu/pgbouncer:1.23.1 sidecar on shared network
- App-pool: max:5 (forces physical-connection reuse across many requests)
- Generate ~100 alternating ops between tenant A / tenant B / probe-empty-context, assert: under tenant B never see tenant A rows; under unset context see 0 rows

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| HTTP request -> Fastify onRequest hook | Tenant identity flows in via header (Phase 1 fixture; Phase 2 replaces with bearer-token) |
| App code -> Postgres via PgBouncer transaction-mode | EVERY query MUST go through withTenant; bare db.execute outside withTenant returns 0 rows by RLS fail-closed |
| KEK/DEK boundary | KEK from env/Vault/KMS; DEK per-row; payload encrypted with DEK; auth tag verifies integrity |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-04-01 | Information Disclosure | SET (without LOCAL) leaks across pooled connections | mitigate | withTenant uses set_config(name, value, true); plain SET forbidden; Plan 05 lint can be extended in Phase 3+ to grep for it |
| T-01-04-02 | Tampering | Tenant ID injected via SQL string interpolation | mitigate | UUID regex validation BEFORE wire; drizzle sql template parameterizes the value bind |
| T-01-04-03 | Information Disclosure | Cross-tenant leak under PgBouncer transaction-mode | mitigate | pgbouncer-interleave.test.ts asserts under real PgBouncer with small pool forcing physical-connection reuse |
| T-01-04-04 | Information Disclosure | GCM IV reuse under same DEK | mitigate | randomBytes(12) per encryptValue call; test 2 (same plaintext -> different ciphertexts) catches reuse regression |
| T-01-04-05 | Tampering | Modified ciphertext accepted | mitigate | GCM auth tag verification; tests 3-5 cover three tamper points |
| T-01-04-06 | Information Disclosure | KEK exposed via env in process listing | accept | env vars not visible in argv; future structured-log scrubber Phase 6+ catches accidental log; documented |
| T-01-04-07 | Information Disclosure | DEK retained in memory | mitigate (best effort) | dek.fill(0) post-use; documented as best-effort given V8 GC (RESEARCH-DB A2) |
| T-01-04-08 | Spoofing | Phase 1 x-tenant-id header trusted | accept | Documented Phase-1-only; Phase 2 replaces with bearer-token resolution; tenant.test.ts asserts non-string headers fall back to default tenant (no array-injection bypass) |
| T-01-04-09 | Elevation of Privilege | Vault/KMS stub silently succeeds with garbage | mitigate | Stubs throw on every method, not just getKek; calling code sees synchronous failure |
</threat_model>
