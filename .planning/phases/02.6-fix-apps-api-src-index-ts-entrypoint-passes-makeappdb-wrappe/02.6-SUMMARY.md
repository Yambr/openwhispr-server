# Phase 02.6 Summary — entrypoint destructure + clean-stack helper (Phase 02.5-04 cascade closer)

**One-liner:** Destructured `makeAppDb()`'s `{db, pool}` wrapper at the apps/api production entrypoint so Better Auth's drizzle adapter receives the bare `NodePgDatabase` (with `.select`) instead of the wrapper — closing the LAST cascade defect from the Phase 02 multi-phase chain. Live `make contract-test` proves the fix: `seed` exits 0 (signup succeeds) and 11/26 contract tests pass; the remaining 13 failures are unrelated downstream defects (Phase 02.7 candidates).

## Source-of-record commit

`450ce23` — `fix(02.6): destructure makeAppDb wrapper in entrypoint + clean-stack helper`

## Defect → fix narrative

### Symptom (surfaced by Phase 02.5-04 contract-test against production image)

```
ERROR [Better Auth]: TypeError: db.select is not a function
    at Object.findOne (file:///app/node_modules/@better-auth/drizzle-adapter/dist/index.mjs:303:26)
    at Object.findUserByEmail (file:///app/node_modules/better-auth/dist/db/internal-adapter.mjs:445:60)
    at sign-up.mjs:164:18
```

`make contract-test` consistently failed at the `seed` step with HTTP 500 from `/api/auth/sign-up/email`. Phases 02.5-01..03 had fixed schema-key mapping and tenant defaults; the `findOne` call in the drizzle adapter dispatched **after** schema lookup, proving the schema map was correct. The new symptom was at the wire level: `db.select` was not a function on the object the adapter received.

### Root cause

`apps/api/src/index.ts:229-233` (pre-fix):

```ts
const { makeAppDb } = await import("@openwhispr/data/client");
const { buildAuth } = await import("./auth.js");
const db = makeAppDb();                                          // ← WRAPPER {db, pool}
const auth = buildAuth({ db: db as never }) as unknown as AuthLike;  // ← `as never` hides mismatch
const app = await buildApp({ db: db as never, auth });               // ← same lie
```

`makeAppDb()` (per `packages/data/src/client.ts:32-40`) returns `{ db: NodePgDatabase, pool: Pool }`. The bootstrap assigned the entire wrapper to `db` and passed it to `buildAuth({db})` and `buildApp({db})`. Both functions expect the bare `NodePgDatabase`. The two `as never` casts silenced tsc — the type mismatch only surfaced at runtime when Better Auth's drizzle adapter called `db.select(...)` on the wrapper (which has no `.select`, only `.db` and `.pool`).

### Fix (D-01)

```ts
const { db } = makeAppDb();        // destructure
const auth = buildAuth({ db }) as unknown as AuthLike;
const app = await buildApp({ db, auth });
```

Both `as never` casts removed. `AppDb = NodePgDatabase<typeof schema>` satisfies both `BuildAuthOptions.db: AppDb` and `BuildAppOptions.db?: TransactionalDb<ExecutableTx>` without coercion (the `as unknown as AuthLike` at the buildAuth call site is unrelated — it's the structural-type cast for Better Auth's own zod-generic-leak surface, documented in `apps/api/src/auth.ts:46-52`).

### Test-harness footnote (relevant to interpreting the FAIL count)

The `make contract-test` Makefile target sets `BACKEND_URL=http://api.localhost`. Traefik 308-redirects to HTTPS (per the project's hard rule: HTTPS-only on externally reachable ports). Node `fetch` follows redirects automatically, but the destination `https://api.localhost` uses a self-signed cert — without `NODE_TLS_REJECT_UNAUTHORIZED=0` the redirected fetch fails, `probeBackend()` returns false, and **all tests skip**. That's the silent-skip pattern the first contract-test invocation exhibited (1 passed, 25 skipped — only the harness-load test). The 13/11/2 split above came from re-running the suite directly with `NODE_TLS_REJECT_UNAUTHORIZED=0 BACKEND_URL=https://...` so the probe succeeds and the assertions actually execute. **This is a pre-existing test-harness shortcoming (not introduced by 02.6) and a Phase 02.7 candidate** — the Makefile should either (a) export `NODE_TLS_REJECT_UNAUTHORIZED=0` + use `https://api.localhost`, or (b) add the local mkcert root to Node's CA bundle, or (c) run the contract suite as a docker-compose service inside the network using `http://api:3000`.
