<objective>
Land the OAuth shim that completes the desktop sign-in lifecycle: scheme-validating `/api/desktop-signin/{provider}` route, post-callback redirect emitter that echoes the validated channel scheme, token rotation overlap machinery (custom `previous_token_hash` lookup since Better Auth 1.6.9 stock invalidates immediately), and cookie-domain wiring (eTLD+1 for split-host topology).

Purpose: Without this plan, OAuth never completes from the desktop's perspective — the channel scheme is the desktop's only return path. Token rotation overlap prevents the cascading-401 failure mode (PITFALLS #8). Cookie-domain enables split-host deploys (PITFALLS #5).

Output: 2 new routes + 2 libraries + auth.ts updates + 2 integration tests; AUTH-A1 and AUTH-A3 open questions resolved with empirical findings.
</objective>

OAuth shim flow:
1. Desktop opens browser → `${AUTH_URL}/api/desktop-signin/oidc?callbackURL=openwhispr-dev://callback&protocol=openwhispr-dev`
2. Server validates scheme, generates PKCE pair, persists oauth_state row, 302 to IdP authorize URL
3. IdP authenticates user, 302 back to `${AUTH_URL}/api/auth/callback/oidc?code=...&state=<oauth_state.id>`
4. Better Auth's genericOAuth handles the callback (token exchange, user lookup-or-create under default tenant), mints bearer + sets cookie
5. Our onSuccess hook (or a follow-up Fastify route) reads oauth_state by state.id, builds `<scheme>://?bearer_token=<token>`, 302's there

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
