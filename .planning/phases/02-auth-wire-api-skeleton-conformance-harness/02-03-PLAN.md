| Boundary | Description |
|----------|-------------|
| Untrusted client → API route | Untrusted JSON, query params, headers cross here; zod is the gatekeeper |
| API handler → DB query | Tenant scope enforced via withTenant + RLS; defense-in-depth |
| Error path → response body | Stack traces and internal state must NOT leak |

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-03-01 | Information Disclosure | Stack traces in error responses | mitigate | setErrorHandler emits only `{error:<msg>}` for known classes; default 500 → "Internal server error" generic message; full err logged via req.log.warn (server-side only) |
| T-02-03-02 | Elevation of Privilege | 200-with-error on auth failure (PITFALLS #1) | mitigate | dualAuthHook + requireCookieOnly throw AuthError; setErrorHandler maps to 401; conventions.test.ts (Plan 06) iterates every authenticated endpoint and asserts 401 (not 200) on bad creds |
| T-02-03-03 | Information Disclosure | Email enumeration via /api/check-user | accept | Rate limit 10/min/IP (Plan 04); response shape identical regardless of existence; v1 accepts the tradeoff for desktop UX (D-09) |
| T-02-03-04 | Tampering | Cross-tenant access via verification-status email param | mitigate | preHandler binds req.tenant from session; handler queries WHERE email AND tenant_id (RLS enforced via withTenant) |
| T-02-03-05 | Spoofing | Bearer token accepted on cookie-only endpoints | mitigate | requireCookieOnly explicitly strips Authorization header before getSession; test asserts bearer-only request → 401 |
| T-02-03-06 | Tampering | Account-deletion CSRF | accept | SameSite=Lax cookie (Better Auth default); Phase 6 adds CSRF token if browser admin UI exposes endpoint; v1 desktop is not browser |
| T-02-03-07 | Tampering | Extra fields in request bodies bypassing validation | mitigate | All request schemas use .strict(); response schemas .passthrough() for forward-compat |
