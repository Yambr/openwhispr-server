<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| OIDC claims -> User row | JIT assignment of tenant/role crosses from signed claims into a persisted multi-tenant row |
| hook -> audit_log (post-commit) | after-hooks run in a separate tx from the user create |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-69-07 | Elevation | role assignment via JIT | mitigate | role additionalField input:false; role set server-side only via resolver; exact-match mapping |
| T-69-08 | Elevation | cross-tenant via changed claim | mitigate | create.before/update.before enforce mode-6 forbidden_tenant_mismatch (user bound to one tenant) |
| T-69-09 | Information disclosure | sso.jit.* log + audit | mitigate | no-PII payloads (D-69-2); structured-log object carries only event/tenant_id/role/code |
| T-69-10 | Repudiation | un-audited provisioning | mitigate | create.after/update.after + rejection path each write an audit_log row (separate post-commit tx, documented deviation) |
</threat_model>
