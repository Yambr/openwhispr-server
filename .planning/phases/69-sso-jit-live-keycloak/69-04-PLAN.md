<objective>
Close the desktop bearer-mint seam (D-69-1 Option C, second call-site): the desktop path bypasses `genericOAuth` so `mapProfileToUser` never fires there. Add the narrow ADDITIVE edits — (1) request the group scope in `desktop-signin.ts` + the `account.scope` in `mint-bearer.ts`; (2) widen `OidcUserinfo` to carry `groups` + the tenant claim; (3) call the SAME `resolveJitDecision` and pass `tenantId`/`role` into `createOAuthUser` on the new-user branch AND run `resolveJitDecision(profile, jitConfig, {tenantId,role} of existing)` on the `if (existing)` returning-user branch to re-sync role / reject tenant-mismatch — so desktop SSO users JIT-provision AND re-sync identically to the web path. The shared databaseHooks (Plan 03) fire because `createOAuthUser` routes through `createWithHooks`; the returning-user update path persists + emits the audit directly (the reuse branch never calls createOAuthUser).

Purpose: Without this, Req-7's desktop login lands a default-tenant + null-role user on first login (69-RESEARCH Pitfall 2) AND — critically — the `if (existing)` reuse-userId branch at mint-bearer.ts:~330 silently SKIPS createOAuthUser for returning users, so update.before / role re-sync (failure-mode 5) / tenant-mismatch (failure-mode 6) NEVER fire on the desktop path. D-69-1's premise is FULL web/desktop parity, so the returning-desktop re-sync gap is in scope and MUST work — not deferred. Token exchange, discovery SSRF guards (`assertEndpointAffiliated`), `set-auth-token` rotation, and channel-scheme deep-link echo MUST stay byte-for-byte unchanged.
Output: edited mint-bearer.ts (both new-user and returning-user branches) + desktop-signin.ts + a unit test (boundary-mocked userinfo) + an integration test (real PG) asserting a first-time desktop profile lands the resolved tenant+role AND a returning desktop profile re-syncs role / rejects tenant-mismatch.
