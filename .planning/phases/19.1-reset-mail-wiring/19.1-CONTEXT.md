## Locked decisions

### D-01 — Hook lives under `emailAndPassword.sendResetPassword` (NOT top-level)

**Why:** Better Auth 1.6.9 source-of-truth at `node_modules/.pnpm/better-auth@1.6.9_*/node_modules/better-auth/dist/api/routes/password.mjs:42`:

```js
if (!ctx.context.options.emailAndPassword?.sendResetPassword) {
  ctx.context.logger.error("Reset password isn't enabled. …");
  throw APIError.from("BAD_REQUEST", { code: "RESET_PASSWORD_DISABLED" });
}
```

This is the canonical key — unlike `sendVerificationEmail`, which BA reads from `options.emailVerification.sendVerificationEmail` and bit Phase 13 by being placed under `emailAndPassword`. Reset is the inverse: reset BELONGS under `emailAndPassword`. Phase 13's lesson does NOT apply here; verified directly against vendored sources.

**Hook signature (BA 1.6.9, password.mjs:73):**
```ts
sendResetPassword: async (
  { user, url, token }: { user: { id, email, name?, locale?, tenantId? }, url: string, token: string },
  request?: Request
) => Promise<void>
```

### D-02 — Variables payload contract

**Existing template files in tree use these placeholders:**
- `{name}` — user-facing greeting
- `{reset_url}` — primary CTA URL
- `{expires_minutes}` — link expiry in minutes

**Hook→variables wiring (locked):**
```ts
variables: {
  name: user.name ?? user.email,
  reset_url: url,
  url,                       // defensive alias (D-03)
  expires_minutes: 60,       // matches BA default resetPasswordTokenExpiresIn = 3600s
}
```

**Why fixed 60-min expiry, not env-driven:** BA 1.6.9 password.mjs:64 reads `ctx.context.options.emailAndPassword.resetPasswordTokenExpiresIn || 3600`. We accept the BA default (1 hour) — operationally sensible; no operator currently asks for override. If future need arises, both the BA option AND `expires_minutes` template var ship in same atomic commit (D-04 carry).

### D-03 — Defensive variables aliasing (mirror Phase 13 pattern)

**Send both `reset_url` AND `url` keys** in `variables` payload. Mirrors `sendVerificationEmail` precedent (`verification_url` AND `url` at `apps/api/src/auth.ts:319` region).

**Why:** Cheap insurance against any template editor mistakenly using `{url}` instead of `{reset_url}`. Cost = one extra key in the JSON; benefit = zero-cost recovery if templates drift.
