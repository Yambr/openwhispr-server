## Deviations from Plan

**1. [Rule 1 — Bug] Removed `signal` forwarding at the agent-stream call site (live-probe finding).**

- **Found during:** Task 3 (live probe).
- **Issue:** The fix as planned still produced the `upstream_error` finish-chunk. Bug isolation matrix on the running stack:

  | bodyTimeout | signal | Result |
  |---|---|---|
  | default | none | GREEN |
  | 0 | none | GREEN |
  | default | `abort.signal` | **FAIL (upstream_error)** |
  | 0 | `abort.signal` | **FAIL (upstream_error)** |

  Conclusion: `undici.request` 7.25 + `signal: AbortSignal` + the process-wide SSRF-wrapped `Agent` (apps/api/src/lib/ssrf-dispatcher.ts) fails at the connect/dispatch boundary BEFORE the socket reaches mock-litellm. Generalises the failure class that 08.2-RESEARCH.md candidate causes #1 and #4 had attributed to undici.fetch.
- **Fix:** At the agent-stream call site, omit `signal: abort.signal` from the args passed to `chatCompletionsStream`. The client interface keeps `signal?: AbortSignal` so non-SSRF callers can still use it (Test D in litellm-client tests continues to pin the contract that the client forwards a signal when given one). Client-disconnect abort still works via two paths: (1) `req.raw.once("close", ...)` flips `abort.signal.aborted` so in-route consumers observe the abort and the drain loop checks `raw.writableEnded` on every iteration; (2) `Readable.toWeb(upstream.body)` cancel propagation destroys the source Readable when the consumer breaks, closing the undici socket from the body side.
- **Files modified:** `apps/api/src/routes/agent/stream.ts` (one arg removed, 28-line deviation comment block added).
- **Commit:** `ae0dcc3`.

**2. [Rule 1 — Bug] Dropped obsolete Test 15 (`masterKey ?? ""` branch).**

- The route no longer reads `masterKey` from `deps.litellm` — the shared client owns auth — so the fallback branch the test exercised no longer exists. Per execute-plan deviation rules this is a "behaviour that legitimately changed"; documented as deviation rather than silently mutated.
