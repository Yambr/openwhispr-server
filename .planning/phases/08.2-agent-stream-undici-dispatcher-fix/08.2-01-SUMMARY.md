# Phase 08.2 Plan 01: Add chatCompletionsStream to @openwhispr/litellm-client — Summary

## One-liner

Extended `@openwhispr/litellm-client` with a streaming chat-completions method that returns the raw `Dispatcher.ResponseData` (Node `Readable` body, NOT pre-consumed on 2xx) so callers can drive SSE → NDJSON pipelines without bypassing the centralized auth / spend-logs metadata surface.

## API Surface Added

```ts
export interface ChatCompletionsStreamRequest extends ChatCompletionRequest {
  signal?: AbortSignal;
  bodyTimeout?: number; // defaults to 0 (no body timeout — long-lived SSE)
}

interface LitellmClient {
  chatCompletionsStream(req: ChatCompletionsStreamRequest): Promise<Dispatcher.ResponseData>;
  // ... existing methods unchanged
}
```

Behaviour:

- Forces `stream: true` and merges `stream_options.include_usage: true` with caller-supplied `stream_options` (preserves caller extras).
- Inherits canonical `authHeaders()` and `{openwhispr_request_id}` spend-logs metadata (T-08.2-05 canonical shape — no `openwhispr_user_id` divergence).
- Forwards `signal` to `undici.request` when provided; `bodyTimeout` defaults to `0` (long-lived SSE).
- Non-2xx → `LitellmUpstreamError(statusCode, bodyText)` via inline check (does NOT call `ensureOk` because the 2xx path MUST NOT pre-consume the body).
- **T-08.2-01 mitigation: NO per-call dispatcher option exposed.** The method relies solely on the process-wide SSRF dispatcher.
