<threat_model>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| api ↔ litellm (in-network) | LITELLM_MASTER_KEY-authenticated; never exposed to desktop |
| litellm ↔ external providers (egress) | OpenRouter/OpenAI/pyannote API calls leave the network with provider keys |
| postgres co-tenant | LiteLLM owns `litellm` database; api owns `openwhispr` database; both via owner role |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-01-01 | Information Disclosure | LiteLLM container exposes /health/liveliness publicly | accept | Mounted only on internal network; Traefik does not route /health/liveliness. Verify in Plan 06 wsUpstream wiring. |
| T-03-01-02 | Tampering | initdb script runs as superuser, executes interpolated env | mitigate | Use `quote_ident` in SQL to prevent SQL injection; only `POSTGRES_OWNER_USER` is interpolated and is bootstrap-controlled. |
| T-03-01-03 | Spoofing | LITELLM_MASTER_KEY default value | mitigate | bootstrap.sh generates random secret; deny-list refuses `changeme`/empty (existing Phase 1 pattern). |
| T-03-01-04 | Denial of Service | LiteLLM container OOM with `--num_workers 2` and 1000 concurrent | accept | v1 sizing is operator concern; Phase 8 load test validates. |
| T-03-01-05 | Information Disclosure | Provider API keys in process env visible via `docker compose exec litellm env` | accept | Standard 12-factor pattern; production operators use Docker secrets / k8s secret manager (Phase 9). |

</threat_model>
