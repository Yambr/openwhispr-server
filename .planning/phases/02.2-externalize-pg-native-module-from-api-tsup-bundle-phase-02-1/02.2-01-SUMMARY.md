# Plan 02.2-01 — SUMMARY

## Outcome

Phase 02.2 succeeded. **api container boots healthy** under `docker compose --profile default up -d --wait`. Three real architectural fixes (no workarounds), atomic commit. Only remaining blockers for Phase 01.1 Plan 05 are observability (tempo/mimir) — Phase 6 scope.

## What was built

### Fix 1 — `apps/api/tsup.config.ts` external natives

Added `external: ["pg", "pg-native", "better-auth"]` to the api ESM entry. Combined with the existing `noExternal: [/^@openwhispr\//]`, the bundle keeps workspace packages inlined but lets Node load native + dual-format deps from `node_modules` at runtime.

Bundle size: 504KB → 330KB.

### Fix 2 — `tools/bootstrap.sh` three-way value semantics

Rewrote the per-key generation/preservation logic to honor three distinct `.env.example` value types:

| Pattern | Action |
|---------|--------|
| `KEY=PLACEHOLDER_BOOTSTRAP_WILL_REPLACE` | Always regenerate as random secret |
| `KEY=postgres://...${OTHER_KEY}...` | Always rebuild via interpolate (Phase 01.2) |
| Anything else (concrete default OR empty) | Use current if set, else preserve example value as-is |

Previously the third case got regenerated as random tokens, corrupting `OPENWHISPR_API_URL`, `AUTH_URL`, `OIDC_*`, `SMTP_*`, `POSTGRES_OWNER_USER`, `POSTGRES_DB`, `MINIO_ROOT_USER`, `OPENWHISPR_KEY_PROVIDER`. The api crashed on better-auth init with `Invalid URL` when `AUTH_URL` was a base64 token.

### Fix 3 — `packages/data/migrations/init/00-roles.sql.tpl` idempotent

With Fix 2 in place, `POSTGRES_OWNER_USER=openwhispr_owner` is now preserved correctly (not regenerated), so the postgres official image creates the bootstrap superuser with that name. The previous `CREATE ROLE openwhispr_owner` then failed with `role already exists`.

Rewrote as `DO $$ BEGIN IF NOT EXISTS ... CREATE ELSE ALTER` block per role. Canonical password + LOGIN/BYPASSRLS attributes are applied regardless of whether the role pre-exists from the postgres-image bootstrap.
