# Phase 02.2 — CONTEXT

## Goal

Make `api` container boot healthy under `docker compose --profile default up`. Unblocks Phase 01.1 Plan 05 stack-up at the application layer.

## Background

Phase 02.1 fixed the api Dockerfile build by inlining `@openwhispr/*` workspace packages into the bundle (`noExternal`). This worked for the workspace packages themselves, but tsup also followed `@openwhispr/data`'s transitive `pg` dependency (via `drizzle-orm/node-postgres`) and tried to bundle pg's CJS native-bindings into the ESM image. Result: api restart-loop with `require is not defined in ES module scope` once postgres became reachable (Phase 01.2).

## Locked Decisions

### D-01 — NO workarounds, fix the real architectural issue
Native modules with C addons (`pg`, `pg-native`) cannot be cleanly inlined into a single ESM bundle. They MUST stay external so Node loads them via `node_modules` at runtime. `better-auth` ships dual ESM/CJS subpath exports that tsup can't reliably inline either — also external.

### D-02 — `external: ["pg", "pg-native", "better-auth"]` in api tsup config
Combined with the existing `noExternal: [/^@openwhispr\//]`, the bundle keeps workspace packages inlined but lets the runtime supply native and dual-format deps. Bundle size drops from 504KB to 330KB.

### D-03 — Bootstrap.sh secret/default discrimination (in scope)
The api container surfaced a deeper bootstrap defect: `tools/bootstrap.sh` was treating any `.env.example` value as either a placeholder-to-regenerate OR an operator-set value. It missed the third case: real default config values (`https://api.localhost`, `openwhispr_owner`, `1025`, `no-reply@openwhispr.local`, the empty `SMTP_HOST=`). These were getting overwritten with random base64 tokens, breaking better-auth (`Invalid URL` on AUTH_URL) and any URL-shaped key.

Fix: only regenerate when `.env.example` value is the literal `PLACEHOLDER_BOOTSTRAP_WILL_REPLACE`. Anything else is a real default — preserved as-is on first bootstrap.

### D-04 — Idempotent role init in `00-roles.sql.tpl` (in scope)
With `POSTGRES_OWNER_USER=openwhispr_owner` now correctly preserved (not regenerated as a random token), the postgres official image creates the bootstrap superuser with that name, then `00-roles.sh` tried `CREATE ROLE openwhispr_owner` → `ERROR: role already exists`.

Fix: rewrite the role section as a `DO $$ BEGIN IF NOT EXISTS ... THEN CREATE ELSE ALTER` block. Idempotent against the bootstrap-superuser pre-creation; canonical password + LOGIN/BYPASSRLS attributes are applied regardless.

- `mimir` cluster-seed timing / health — Phase 6
